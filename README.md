# MC 技术执行工具包

把已有OpenMC计算接到一套可重复调用、可追踪结果的流程中：**输入检查 → 独立计算 → 状态查询 → 结果/图表/报告 → 产物管理**。既可直接运行，也可作为标准MCP服务交给平台或智能体。

本包提供调用与管理层；专业模型、核数据和参数选择仍由相应业务负责。已有OpenMC输入可以直接接入，不要求从我们的示例重新建模。源码版本0.6.0，适配OpenMC0.16.0；具体支持范围见[使用指南](docs/使用指南.md#支持哪些工作)。

## 我想用OpenMC工具

先解压并进入本包根目录。服务端使用Linux/WSL；首次需Python3.10+与venv、Bash、curl、tar/bzip2及包源网络；自动准备Office需apt-get/dpkg-deb。运行工具无需Node、Harness或大模型账号。

```bash
./quickstart.sh
mcp/.venv/bin/python examples/public_case_demo.py
```

第一条准备环境，第二条用随包公开C5G7数据真实计算，打印计算编号、统计提示、图和报告的**服务端绝对路径**。它是工程例题，不是指定业务验收。已有运行环境可复用，Office可跳过，见[初始化](docs/使用指南.md#初始化)。

改一个参数再试，每次生成独立输入和计算记录：

```bash
mcp/.venv/bin/python examples/public_case_demo.py --particles 400
```

接下来按一份[使用指南](docs/使用指南.md)操作：带自己的输入 → 发现/修改参数 → 运行和查询 → 取结果与产物 → 维护清理 → 需要时部署MCP。程序要完整结果时加`--json`；直接CLI与MCP始终返回结构化数据。

## 我有自己的函数或程序，想做成MCP工具

不需要安装OpenMC。任选一种可编辑模板：

```bash
./create-mcp.sh ./my-mcp
# TypeScript使用：
./create-mcp.sh ./my-ts-mcp --language typescript
```

创建过程离线，复用包内固定源码快照，已有目录不覆盖。新服务可脱离MC包独立运行；首次启动按所选语言安装依赖。默认一个服务有函数和独立程序两个工具，继续加工具只需扩展同一注册表。

按[已有程序接入](docs/已有程序接入.md)走完创建、替换业务、增加多个工具、启动、验证和交付。命令行软件若不是JSON输入输出，需一层参数/文件转换；已有标准MCP地址则直接接入客户端，无需重封装。

## 我想让平台或智能体使用

已有OpenMC环境时，在本包执行`./mcp/start.sh`。新建通用服务则在它自己的目录执行`./start.sh`。把**实际MCP URL、传输方式、鉴权配置**交给调用方，工具名和参数说明由标准`tools/list`发现。

先看[部署与交接](docs/使用指南.md#部署mcp与交给调用方)，具体Codex/DSH等配置放在[可选宿主示例](docs/MCP平台接入.md)。服务不绑定Harness；标准协议连通、自然语言调用和专业验收分别验证。

- [开发者入口](docs/README.md#开发和项目维护)：实现结构、验证与项目计划，普通使用无需先读。

```bash
./cleanup.sh   # 默认仅列出记录，不删除
./verify.sh    # 工程回归；完整仓库还验证可选Harness，需Node22/pnpm
./package.sh   # 生成源码部署包，不代替验证
```

产物根默认是本包`workspace/`；`.mc-jobs`、`.mc-scans`是其中隐藏目录。产物保存于服务端，当前没有远程下载接口。清理需按指南先预览，在维护窗口显式应用，原输入保留。

部署包在`dist/mc-tech-execution-0.6.0.tar.gz`，附清单和SHA256；包括源码、配置模板、文档、示例、测试及通用服务模板，不含个人密钥、本机配置、已安装环境、原始合同和运行数据。正式业务条件与未完功能见[开发计划](docs/验收导向开发计划.md)；本次易用性完善不增加合同验收承诺。

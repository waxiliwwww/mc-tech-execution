# 把已有程序变成可交付的MCP服务

这条路线适合“已有函数、命令行程序或HTTP接口，希望给多个平台调用”。不需要先配置OpenMC，也不需要Harness或模型账号。创建可独立运行的服务，默认一个服务里注册多个工具；只有依赖、权限或运维确需分开时再拆多个服务。

## 1. 创建一个可编辑服务

从MC工具包根目录运行，目标父目录须存在、目标本身须是新目录：

```bash
./create-mcp.sh ./my-mcp
# 如果业务使用TypeScript：
./create-mcp.sh ./my-ts-mcp --language typescript
```

创建只读取包内固定source快照并校验哈希，不联网、不安装依赖、不启动服务。Python/TS都取可编辑源码；不会把只有编译产物的部署包当源码。服务名/客户端别名按目录生成，配置可继续修改，TEMPLATE.json记录来源及必要调整。

新目录不依赖MC工具包的其他路径，可以单独复制给他人。创建只负责封装模板，不会推断任意GUI/CLI的业务语义，也不会自动获得OpenMC的计算/扫描/产物管理；通用服务提供协议、Schema校验、适配执行及调用日志。业务长作业和产物规则需要在其接口中明确。

## 2. 不改代码，先验证同一服务两个工具

服务端进入刚创建的目录：

```bash
cd my-mcp
./start.sh
```

Python需Python3.10+和venv/pip；首次在本服务.venv安装锁定依赖。TypeScript需Node22及Corepack/pnpm，首次装依赖，每次从src编译。创建离线不等于首次安装无需网络；Python可按生成的README准备wheelhouse。

默认Python地址为http://127.0.0.1:8766/mcp，TS为http://127.0.0.1:8765/mcp。实际以启动输出/配置为准；端口占用需换端口。服务成功启动才生成connection.json，它停服后仍在，不能作为在线证明。

另一个终端回到MC工具包根目录，只准备协议客户端，不安装OpenMC：

```bash
./mcp/setup.sh
mcp/.venv/bin/python examples/mcp_client.py --url http://127.0.0.1:8766/mcp
mcp/.venv/bin/python examples/mcp_client.py --url http://127.0.0.1:8766/mcp --tool add --arguments '{"a":20,"b":23}'
mcp/.venv/bin/python examples/mcp_client.py --url http://127.0.0.1:8766/mcp --tool add_program --arguments '{"a":20,"b":23}'
```

同一个地址能发现并调用两个工具：add调用语言函数，add_program执行真实独立程序。Python返回result=43；TS改为其端口，返回sum=43。检查structuredContent和isError，不只看服务探活。MC包中的协议客户端是可选测试调用方，不是新服务的运行依赖；正式使用可换任意支持相应MCP协议/鉴权的客户端。

## 3. 接自己的函数：主要修改三处

| 目的 | Python | TypeScript |
| --- | --- | --- |
| 业务实现 | business.py，或自行新增模块 | src/business.ts，或自行新增模块 |
| 工具定义与参数 | tools.py | src/tools.ts |
| 服务监听/对外地址 | service.config.json及环境 | service.config.json及环境 |

先用函数写清输入输出，再在注册表声明名称、用途、各参数/返回含义、校验范围与执行绑定。Python最小示例：

```python
from business import add

INPUT = {"type": "object", "properties": {
    "a": {"type": "number", "description": "第一个有限加数"},
    "b": {"type": "number", "description": "第二个有限加数"}},
    "required": ["a", "b"], "additionalProperties": False}
OUTPUT = {"type": "object", "properties": {
    "result": {"type": "number", "description": "两个加数的和"}},
    "required": ["result"], "additionalProperties": False}
TOOLS = [{"name": "add", "description": "计算两个有限加数之和，无文件或外部系统写入。",
          "inputSchema": INPUT, "outputSchema": OUTPUT,
          "annotations": {"readOnlyHint": True, "destructiveHint": False},
          "function": add}]
```

这是替换模板注册表的写法。function按关键字参数调用，如add(a=20,b=23)，须返回JSON对象，支持同步/async；输入与输出都按声明校验。普通同步函数在线程执行，不能强制终止，可能挂死的程序用子进程适配。

TS在src/tools.ts使用defineTool，参数用Zod定义并附.describe，例如：

```typescript
const inputSchema = {
  a: z.number().describe('第一个有限加数'),
  b: z.number().describe('第二个有限加数'),
};
const outputSchema = { sum: z.number().describe('两个加数的和') };
```

沿生成模板的execute绑定业务。只修改源码，不编辑lib/或打包后的server.mjs；启动/打包会编译。

## 4. 接命令行程序或HTTP接口

### 已支持JSON输入输出的程序

在同一Python工具定义中，用program替代function：

```python
import sys
from pathlib import Path
ROOT = Path(__file__).resolve().parent
# 该对象放入TOOLS；沿用上面的INPUT和OUTPUT
{
    "name": "add_program", "description": "用独立程序计算两个有限加数之和。",
    "inputSchema": INPUT, "outputSchema": OUTPUT,
    "annotations": {"readOnlyHint": True, "destructiveHint": False},
    "program": {"argv": [sys.executable, str(ROOT / "programs/add_json.py")],
                "cwd": str(ROOT), "timeoutSeconds": 5, "maxOutputBytes": 65536}
}
```

一个工具只选择function、program、http中的一种。程序stdin接收一个JSON对象，stdout只输出一个JSON对象，诊断写stderr；参数不是追加到任意shell命令。非零退出、超时、超大输出、坏JSON或不符合输出Schema都会报错；Linux进程组在取消/超时后清理。

原程序若只接受命令行选项/文件，写一个薄适配函数或脚本，把JSON参数转换成它的固定argv/输入文件，再把实际产物转换成返回对象。使用参数数组，不拼shell，不让模型决定任意命令。程序、解释器、库和业务数据均须在部署环境具备；复制源码不会自动安装所有第三方软件。

TS模板已用runJsonProgram封装programs/add.mjs，照src/tools.ts的第二个工具替换command/args和结果转换即可。

### 已有普通HTTP JSON接口

Python同样在注册表增加一个对象：

```python
{
    "name": "add_api", "description": "调用部署方指定的加法HTTP接口。",
    "inputSchema": INPUT, "outputSchema": OUTPUT,
    "annotations": {"readOnlyHint": True, "destructiveHint": False, "openWorldHint": True},
    "http": {"url": "https://your-api.example/calculate", "tokenEnv": "BUSINESS_API_TOKEN",
             "timeoutSeconds": 10, "maxOutputBytes": 65536}
}
```

URL须换成真实固定端点，接收POST JSON并返回匹配的JSON对象。凭据只从服务进程环境注入Bearer，不写进URL或模型参数；不跟随重定向。现有接口形状不一致时用函数做转换。TS对应postJson调用见生成模板src/tools.ts的注释与README。

若对方已经给出真正的MCP URL，就把地址和认证交给客户端直接连接，不再套一层HTTP适配。

### 多个工具与长计算

继续往同一TOOLS（TS为tools）数组加定义，名称须唯一。每个工具有独立输入/输出Schema和执行绑定，服务协议处理不用重写；改定义后重启自己的服务。不同服务共存时设置不同端口和客户端连接别名。

长计算不要占用默认30秒同步适配器无限等待。业务可返回持久计算编号，另提供查询/取消和产物位置接口；需要OpenMC现成这套管理时，使用本包已有OpenMC工具。通用模板不会自动创建.mc-jobs或替任意软件做专业校核。

## 5. 让调用方知道怎么填参数

工具级description说明“什么时候调用、做什么、有什么副作用”。参数级description说明“值是什么意思、从哪里取、单位与范围、缺省如何处理”；复杂对象的嵌套字段也要说明。合法例子是填写方式，不表示适用于所有模型。

动态编号/参数名应来自前一步工具结果，例如先发现可调整项，再传相同name；不能要求模型凭常识猜业务字段。必填缺失应提示补充；默认值须由实际程序实现，JSON Schema的default只作注解。可省略不等于接受显式null。

模型不一定读取Markdown手册，因此这些说明必须进入MCP实际tools/list；文档与发现信息一致。说明完整也不替代实际参数校验、用户确认和专业判断。annotations只是客户端提示，不能代替权限控制。

## 6. 交给平台与另一台服务器

先在服务端真实启动并调用，再读取connection.json或/info；给调用方的核心信息是：

- 实际MCP URL及Streamable HTTP传输；不能把0.0.0.0或异机localhost交出去。
- 是否需要Bearer，以及在客户端配置认证的方法；真实令牌另行提供。
- 客户端连接别名；工具名/参数由初始化后的tools/list发现，无需手抄全部函数定义。

远程监听配置host、port、path、publicUrl，并在环境设置MCP_AUTH_TOKEN；公网由部署方提供HTTPS入口，代理保留Host/Authorization。/health只探活，/info和MCP同样鉴权；标准客户端不依赖/info。connection.json里的环境占位符不是所有平台都能自动展开。完整交接解释见[使用指南](使用指南.md#部署mcp与交给调用方)，具体平台为[可选示例](MCP平台接入.md)。

在新服务目录执行./package.sh。Python包是源码，接收方重建.venv；新增业务模块须加入其package.sh显式清单，programs/中的程序会随包。TS生成可运行部署包；更新源码须重新编译打包，接收方需要相应Node运行环境。

分发前解压到新位置，重新启动并验证每个工具、坏参数、上游失败与产物位置，核对包内确有业务模块/程序，没有密钥、本机环境和日志。配置/依赖安装、协议调用、自然语言选择与真实业务验收分别留记录。

## 在本MC服务里扩展

若希望把工具放进现有OpenMC服务，按相同Schema格式在mcp/tools.py的TOOLS中追加，放在最终prepare_tools(TOOLS)之前。function/program/http均可；参数应填写description，参数/返回文档由mcp/.venv/bin/python scripts/generate_tool_reference.py同步。MC注册器会为函数取符合原Schema的默认注解，不会为程序自动实现默认或猜业务含义。

模块职责和OpenMC适配扩展见[架构说明](架构与扩展.md)。通用模板与MC项目使用版本快照复用，运行不会通过绝对路径跟随另一个源码仓库。

模型由你定义，调用与记录交给工具包

例题和 demo 是学习入口。实际使用时，你可以按 OpenMC 的建模方式准备自己的几何、材料、源和计分，再将导出的输入交给这里的校核、计算和结果管理。

三层参数自有输入修改范围源码职责扩展与验证

先分清：你要改哪一层？

层次例子去哪里改
演示脚本选项--particles 400只控制该 demo 已开放的选项，固定步骤见演示说明；不代表工具能力全集。
工具调用参数case_dir、threads、tally_id描述“对哪份输入做哪个动作”。先查工具参数，CLI 用 JSON，MCP 使用相同 Schema。
模型字段材料组成、几何区域、源分布、计分和运行设置在自己的 OpenMC Python 脚本/XML 中定义；本包对部分字段提供自动发现/副本修改/扫描，其余先在外部准备。

例如：--particles 400 被公开例题 demo 转为生成工具的 particles=400，最终写入 settings.xml。而修改现有算例时，使用 openmc_prepare_case 的 parameters={"settings.particles":400}。两个入口产生相同类型的模型设置，参数形式不同。

自己的模型怎样进来

已经会用 OpenMC：继续使用现有建模脚本，先导出完整 XML 和所需数据。不会建模：先完成计算教程，业务模型的选择仍需专业依据；工具包不会仅凭一句话自动补齐专业输入。

输入内容本包如何使用
geometry.xml / materials.xml / settings.xml描述几何、材料与运行/源设置；也接受综合入口 model.xml。
tallies.xml按你的模型定义要统计的量；未定义的计分不能凭空读出。源设置通常在 settings 中，不要求另造 source.xml。
核数据、外部源文件等运行服务器必须具备且可访问；复制输入后检查引用路径。相对引用应能从输入副本/计算快照中解析，外部绝对路径需在部署环境成立。

以下用默认 workspace/ 为例，替换实际输入路径；如果设置了 MC_WORKSPACE，请使用它的真实目录：

mkdir -p workspace/cases/my-case
cp -a /实际输入目录/. workspace/cases/my-case/
./mc.sh call openmc_validate_inputs '{"case_dir":"cases/my-case","api_check":true}'
./mc.sh call openmc_list_parameters '{"case_dir":"cases/my-case"}'

复制前确认目标是专用目录，避免混入旧模型。Python 建模脚本本身不是已导出的输入；工具不会执行调用方任意提供的脚本路径。工作区路径不接受绝对路径、上级越界或符号链接；有链接的业务数据需要按部署条件整理实际文件和引用。

之后沿教程使用 cases/my-case：校核 → 提交 → 按编号查状态 → 按真实 tally 读图和报告。提交会在 .mc-jobs/<job_id>/work 保存输入副本，后续编辑原目录不会修改这次快照。

想看原生 OpenMC 模型是怎么组织的？

随包的官方多群例题源码依次构造截面数据、材料、几何、Settings、Tallies 并导出 XML。可以在自己的目录复制研究，保持包内 vendor 原件不变。它原生设置为 1000 / 100 / 10；本包准备工具为了短练习，显式覆盖为 200 / 10 / 2，并记录来源。

完整 OpenMC 建模能力与本包适配能力要分别看待：原生脚本能表达的内容更多；是否能在当前部署运行，仍取决于已安装引擎、数据和依赖。本地适配使用 native 运行，不能据此视为 CAD/HPC 等功能已具备。

官方使用说明的固定原文在 knowledge/openmc-0.16.0；可以通过 search_knowledge 按中文导航找片段与出处，通过 read_knowledge 继续读取。RST 的跨文件引用未全部展开。

自动改参/扫描的支持范围

openmc_list_parameters 对当前模型给出可修改项；openmc_prepare_case 和扫描工具只接受其中的名称。未列出的字段可以在自己的 Python/XML 输入中准备，再提交计算；希望纳入统一自动改参时，才需要扩展适配器。

当前可发现的类别填写时要注意
运行统计设置particles、batches、inactive、generations_per_batch、seed。整数/范围按返回定义，组合还须满足 batches - inactive ≥ 2。
材料密度 / 温度按实际材料 ID；保留原密度单位，sum 密度不提供此修改入口。macro 为倍率；温度用 K，实际计算需适用核数据。
部分 CSG 表面系数只覆盖实现列出的平面、球、圆柱、圆锥等表面公开属性；尺寸/系数单位看返回，不等于任意 CAD 或任意几何编辑。
源强按当前源索引，正数，相对强度；不自动覆盖任意源分布字段。

例如添加一个新能量分组计分，需要先在自己的模型中定义；不能猜一个 parameters 键让工具自动生成。读结果时从实际 tallies 选择 score、nuclide 与 filters。绘图接口说明多维选择与截断提示。

一次调用在源码里怎样走完

CLI / MCP工具定义与校验业务 / OpenMC工作区记录和产物
你想改什么先看这些文件
工具名、参数、说明mcp/tools.py 注册操作；tool_metadata.py 补现有 OpenMC 语义。新增参数要有 description，嵌套字段也需解释来源和单位。
CLI 与 MCP 公共调用cli.py / server.py 共用 adapters.py 的校验与函数/程序/HTTP 执行。demo 仅调用它们。
输入解析、例题和参数修改openmc_tools.py、openmc_worker.py 调用官方 API；openmc_parameters.py 负责发现、检查与局部 XML 修改。
计算 / 扫描 / 数据位置openmc_jobs.py / openmc_scan.py；openmc_runtime.py 读取运行配置并检查工作区边界。
图、报告、文件清单openmc_plots.py / openmc_visuals.py、openmc_reports.py、openmc_artifacts.py。

求解器 API 动作在配置的 OpenMC Python 环境执行；调用层用自己的 mcp/.venv。长计算交给独立 worker，以编号和持久记录查询；MCP 停服不会代替作业取消。Harness 位于可选宿主层，工具包不依赖它。

修改时先守住一条完整用法

新增一个可自动修改的 OpenMC 字段

在 openmc_parameters.py 同时补齐发现描述、值与组合校核、官方属性赋值和对应 XML 局部写入；不要只在参数清单增加名字。用实际输入检查修改值生效、原输入未变、无关字段未丢失，再跑到真实计算和结果读取。

本实现采用局部 XML 写入，原因之一是全量 Model XML 往返在 OpenMC 0.16 下可能丢失宏观材料条目。扩展时保持单位和未修改内容，不能只看 Python 属性赋值成功。

新增工具、例题、资料或结果格式

已有函数/程序/API 的注册步骤见MCP 封装。例题目录在 config/cases.json，需写来源、依赖和准备状态；ready_to_prepare 不等于已计算。资料更新需保留版本、许可、出处及哈希。

结果扩展使用真实 StatePoint/Tally；保留标准差、非有限值、截断和来源标记。图从完整所选计分读取，不从截断预览作图。专业规则和修复范围需业务依据，不能仅靠模型猜测。

改完如何验证、打包、交付

先用 tests/ 中相关用例验证受影响行为。涉及求解器就启用真实运行时；涉及确认修复，保留拒绝和原失败。再从新的解压目录按文档走完整路径。

mcp/.venv/bin/python scripts/generate_tool_reference.py
./verify.sh
./package.sh

第一条从真实注册表生成 HTML 参数参考；verify.sh 检查工程行为并输出日志，不等于业务验收。设置 MC_TEST_OPENMC_CONFIG 可启用真实 OpenMC 用例；完整工程回归也测可选 Harness，需要 Node 22/pnpm。package.sh 生成 dist/ 下源码包、文件清单和 SHA256，不代替验证。

包不含环境、个人密钥、本机配置、原合同和运行数据；接收方需按初配准备依赖。部署前在新位置检查运行、产物和文件引用。项目人员另查测试与验收记录、开发计划；公开工程例题、协议连通和专业验收分开判断。

只要添加现有程序而不改 OpenMC：直接创建独立 MCP 服务。

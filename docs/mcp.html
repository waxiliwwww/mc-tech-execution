供下游调用

一个 MCP 服务，可以提供多个工具

MCP 是调用方发现和调用工具的标准协议。你需要准备可执行能力、参数说明与服务地址；平台连接后通过 tools/list 读取工具定义，再通过 tools/call 调用。

发布现有 OpenMC 工具封装自己的程序接函数 / 程序 / API交给调用方

已经用本包计算，想开放远程调用

先按计算教程确认环境与输入可运行，然后在工具包根目录启动：

./mcp/start.sh

默认地址为 http://127.0.0.1:8770/mcp，传输为 Streamable HTTP，提供本包注册的全部工具。它调用的实现、参数校验和工作区与 CLI 一致；服务不需要 Harness 或模型账号。

另开终端，在包根目录用标准 SDK 验证发现和一次调用：

mcp/.venv/bin/python examples/mcp_client.py --url http://127.0.0.1:8770/mcp
mcp/.venv/bin/python examples/mcp_client.py --url http://127.0.0.1:8770/mcp --tool openmc_environment

第一条应返回工具列表及参数 Schema；第二条的 structuredContent 应含实际环境探测结果，isError 不应为 true。探活、协议成功和实际计算是三件事；还可将公开例题 demo 加 --mcp-url，复用同一工作流验证远端计算。

已有函数或程序：先创建独立服务

这条路线无需安装 OpenMC。在包根目录创建一个新的 Python 服务：

./create-mcp.sh ./my-mcp

它从包内固定源码模板复制完整服务，创建时不联网、不安装、不启动；目录必须是新的。生成的 my-mcp/ 可以移到其它位置独立运行。TypeScript 业务可改用 ./create-mcp.sh ./my-ts-mcp --language typescript。

文件你需要处理什么
business.py / src/business.ts写或导入现有业务函数。
tools.py / src/tools.ts声明工具名、用途、输入输出和执行绑定；继续追加定义即可在同服务提供更多工具。
programs/存放随包分发的命令行程序或转换脚本。
service.config.json改服务名、监听端口和实际对外地址。
start.sh / package.sh启动服务、生成部署包；详细语言说明随新目录 README 一并复制。

不改模板，先进入它的目录启动：

cd my-mcp
./start.sh

Python 默认 http://127.0.0.1:8766/mcp，需要 Python 3.10+ 与 venv/pip；首次在自身目录安装锁定依赖。TypeScript 默认 8765，需要 Node 22、Corepack/pnpm，启动时编译。端口以实际配置为准。

另一个终端回到原 MC 包根目录，仅准备测试客户端，无需装 OpenMC：

./mcp/setup.sh
mcp/.venv/bin/python examples/mcp_client.py --url http://127.0.0.1:8766/mcp
mcp/.venv/bin/python examples/mcp_client.py --url http://127.0.0.1:8766/mcp --tool add --arguments '{"a":20,"b":23}'
mcp/.venv/bin/python examples/mcp_client.py --url http://127.0.0.1:8766/mcp --tool add_program --arguments '{"a":20,"b":23}'

预期同一地址发现两个工具：add 调函数、add_program 调真实程序。Python 结果为 result=43；TS 端口改为 8765，字段为 sum=43。这里的 MC 客户端只是测试方式，服务可配合其它标准客户端使用。

换成自己的能力，主要改实现和注册表

先从现有函数得到明确输入输出，再照模板更新注册表。以下示例使用生成的 Python 服务；TS 对应使用 src/tools.ts 的 Zod 定义和 .describe()。

例：把 add 换成自己的函数，并补齐参数含义

例如在 business.py 实现两数乘积，替换该服务的 tools.py 为下列定义。业务换成别的内容时，字段、范围和副作用也须随之修改。

# business.py
def multiply(a, b):
    return {"result": a * b}

# tools.py
from business import multiply

TOOLS = [{
    "name": "multiply",
    "description": "计算两个有限数的乘积，无文件或外部系统写入。",
    "inputSchema": {
        "type": "object",
        "properties": {
            "a": {"type": "number", "description": "第一个乘数。"},
            "b": {"type": "number", "description": "第二个乘数。"}
        },
        "required": ["a", "b"], "additionalProperties": False
    },
    "outputSchema": {
        "type": "object",
        "properties": {"result": {"type": "number", "description": "两数乘积。"}},
        "required": ["result"], "additionalProperties": False
    },
    "annotations": {"readOnlyHint": True, "destructiveHint": False},
    "function": multiply
}]

保存并重启这个服务，再调用 multiply，传 {"a":20,"b":23}，预期 result=460。继续往 TOOLS 数组追加不同名字的工具即可；不需要为每个函数部署一个端口。

已有命令行程序：用 JSON 薄适配连接

Python 注册表的执行绑定可换为 program。其协议为 stdin 接收一个 JSON 对象，stdout 返回符合输出 Schema 的 JSON 对象，运行提示写 stderr。模板的 programs/add_json.py 已示范。

# 一个工具定义中的执行绑定；配套 inputSchema/outputSchema 仍需填写。
"program": {
    "argv": [sys.executable, str(Path(__file__).parent / "programs/add_json.py")],
    "timeoutSeconds": 30,
    "maxOutputBytes": 65536
}

在 tools.py 中导入 sys、Path。普通 CLI 如果使用 argv/文件输入、纯文本输出，就写一个小脚本将 JSON 转成它所需输入，再把结果转成 JSON；不能直接把任意命令字符串交给智能体执行。命令、工作目录、解释器和所需库由部署者固定配置。

TS 的 runJsonProgram 示例位于 src/tools.ts。长计算应返回持久编号，另设查询/取消接口；通用模板不会自动获得 OpenMC 的计算、扫描和产物管理。

已有 HTTP API，或者已经是 MCP 地址

Python 的 http 适配器向固定 URL 发送 POST JSON，并校验返回对象；API 形状不同则用函数转换。TS 可用 postJson。

"http": {
    "url": "https://your-api.example/calculate",
    "tokenEnv": "BUSINESS_API_TOKEN",
    "timeoutSeconds": 10,
    "maxOutputBytes": 65536
}

URL 换为真实业务端点，令牌从环境注入，不放进模型参数。若对方给的已经是标准 MCP URL，客户端直接连接即可，无需再封一层 HTTP 适配。

让调用方知道怎么填参数

工具说明写“做什么、何时用、有何副作用”；每个参数写“含义、来源、单位、范围、省略行为”。动态编号和参数名应从前一步结果取得，不让智能体猜。复杂对象的子字段也需要描述。

这些说明要进入实际 tools/list，只写在网页里不够。本包已有 OpenMC 工具的参考页从同一 Schema 生成。Schema 的 default 只是注解，运行默认必须由业务实现；可省略不代表可填 null。annotations 是提示，不代替权限或人工确认。

部署后，交给调用方哪些东西？

必须交接怎么用
实际 MCP URL例如同机 http://127.0.0.1:8770/mcp；远端使用可达的真实地址。不要交 0.0.0.0 或另一台机器的 localhost。
传输与鉴权Streamable HTTP；如有 Bearer，告诉对方认证头配置方式，真实令牌另行提供。
服务别名与工具说明别名由客户端区分服务；连接后 tools/list 自动获取工具名和参数，不用手抄所有函数。
数据和产物约定OpenMC 的 case_dir 相对服务端工作区，文件保存在服务器；通用工具的文件输入输出需由其业务接口明确。

启动成功后生成的 connection.json 和受鉴权保护的 /info 是交接辅助。连接文件停服后仍存在；/health 只探活。它们不是所有平台统一的配置文件，按客户端要求填写 URL/认证头即可。Codex/DSH 等宿主示例是可选扩展。

远程监听、鉴权和打包

例如在计算服务器上设置以下环境；路径、域名和令牌须由部署者替换：

export MC_WORKSPACE=/srv/mc-data
export MCP_HOST=0.0.0.0
export MCP_PORT=8770
export MCP_PUBLIC_URL=https://mc.example.org/mcp
export MCP_AUTH_TOKEN='部署方生成的令牌'
./mcp/start.sh

通用服务在它自己的目录执行 ./start.sh，按自身配置选择端口。非回环监听须有实际 publicUrl 和 Bearer；公网 HTTPS、防火墙、DNS 和代理由部署环境落实，代理保留 Host/Authorization。客户端的环境占位符是否展开，由其自身支持决定。

在独立服务目录运行 ./package.sh；Python 接收方重建环境，新增业务模块还须加入其打包清单，programs/ 会随包。TS 生成编译后的部署包，源码变更后重新编译打包。分发前在新位置解压，检查每个工具、非法参数、上游失败和产物约定，排除密钥/日志。

独立服务不依赖创建它的 MC 目录。函数/程序所需的第三方环境和数据仍需部署；源码打包不等于所有依赖自动内置。协议调用成功、模型能否正确选择工具、业务结果是否合格，分别验证。

要放入本包现有服务？在 mcp/tools.py 的最终 prepare_tools(TOOLS) 前追加定义，参数写 description，再生成接口参考。源码职责见开发入口。

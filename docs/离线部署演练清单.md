# 离线 / 内网部署演练清单（H1 准备件）

> 状态：**未演练**。本机不允许网络命名空间隔离（`unshare -n` → `Operation not permitted`），
> 无法如实模拟"断网后实跑"，因此本文只提供可查项的自动检查、目标环境的逐条演练步骤与
> 记录表。不要把"可查项通过"当成"离线部署已验收"。

## 1. 自动可查项（本机就能查）

```bash
python3 scripts/offline_check.py   # 退出码 0=可查项全过，1=有完整性/依赖问题
```

检查内容：

- `vendor/openmc-examples/0.16.0` 与 `knowledge/openmc-0.16.0` 清单中每个文件存在且 sha256 一致；
- `mcp/requirements.txt` 存在、全部依赖钉版（`==`）；
- `mcp/`、`scripts/` 中网络调用点静态扫描（`requests`/`httpx`/`urllib.request`/`socket.`/URL 字面量）；
- 运行时版本登记（`config/openmc.local.json` 的解释器与 OpenMC 版本）。

静态扫描**不是**"运行期无网络依赖"的证明；证明只能由断网实跑给出（第 3 节）。

## 2. 演练前准备（在可联网的准备机上完成）

1. 打包目录（含 `vendor/`、`knowledge/`、`config/` 模板、`mcp/requirements.txt`、`tests/`）；
2. 下载依赖 wheel 包到 `wheels/`：
   `python3 -m pip download -d wheels -r mcp/requirements.txt`
3. 复制运行时解释器环境（`config/openmc.local.json` 指向的 Python + OpenMC）或确认目标机已装同版本；
4. 记录包清单：`sha256sum` 上述打包件与 wheel 目录，登记到第 4 节记录表。

## 3. 目标环境演练步骤（断网执行，逐条记录）

| # | 命令 | 通过判据 |
|---|---|---|
| 1 | `python3 scripts/offline_check.py` | 可查项全部通过 |
| 2 | `python3 -m pip install --no-index --find-links wheels -r mcp/requirements.txt` | 安装成功且无联网 |
| 3 | `mcp/start.sh` 后客户端 `list tools` | 返回全部工具，数目与 `python3 -m json.tool` 生成的注册表一致 |
| 4 | `openmc_environment` | `engine_read.ok=true`，版本登记正确 |

| 7 | `openmc_read_results` | 返回 keff，无 NaN |
| 8 | `openmc_export_report` | 报告文件生成，路径可访问 |
| 9 | `./verify.sh --tools-only` | 全量通过（若目标环境已贴运行时） |
| 10 | `./accuracy.sh --only synthetic-mgxs-infinite-medium` | 判定 PASS，退出码 0 |

## 5. 已知边界与回滚

- 知识库为精选正文（非完整离线网站），跨文件引用未展开——离线查询能覆盖已收录正文；
- 依赖安装依赖第 2 节的 wheel 目录，缺哪个包会明确报错，不支持回退到联网（目标环境无网）；
- 任何步骤失败：保留日志，回到准备机补包/补文件后按第 4 节重新登记；
- 演练全部通过后，才可在交付材料中写"离线部署已演练"，并附本文件记录表。

# 测试与验收说明

本说明对应接口工具包工程自测、真实OpenMC联调和正式验收准备，更新于2026-10-27。优先级及状态见[开发计划](验收导向开发计划.md)，调用方法见[工具使用说明](OpenMC工具使用说明.md)。本文件不是甲方已确认的正式测试计划，也不是通过报告。

## 1. 分清测试结论

| 测试 | 使用什么 | 能证明什么 |
| --- | --- | --- |
| 工程自动测试 | 临时文件、模拟可执行程序、实际MCP协议和受控模型 | 路径/输入检查、作业控制、错误回执、原修复及Harness机制 |
| 真实OpenMC工程联调 | OpenMC0.16.0、真实API和求解器、合成单群MGXS | 实际生成、解析、计算、绘图、StatePoint读取和报告链路 |
| 真实业务与专业验证 | 甲方指定模型/真实核数据/参考答案 | 业务处理与物理结果是否满足相应判据 |
| 正式验收 | 经甲方确认的计划及完整记录、见证和评审 | 全部原合同功能、指标和交付是否符合约定 |

模拟进程不产生物理结果。合成截面即使经真实求解器计算，也不代表真实材料、真实堆芯或物理准确率验收。所有来源应随作业、结果和报告保留。

## 2. 工程自测

项目根目录执行：

```bash
./verify.sh
```

脚本检查锁定依赖、运行Python业务/MCP测试和原Harness策略/终端回归，不调用外部模型，不默认运行真实OpenMC测试。成功输出“校验成功”，失败返回非0且不输出成功结论。日志在`artifacts/python-tests.log`、`artifacts/harness-tests.log`及依赖日志；固定文件会被覆盖，需要留版时先复制旧记录。

按改动局部运行：

```bash
./mcp/setup.sh
mcp/.venv/bin/python -m unittest discover -s tests -p test_openmc_tools.py -v
mcp/.venv/bin/python -m unittest discover -s tests -p test_mcp_integration.py -v
```

新用例覆盖：缺程序/版本异常、坏XML/根元素/基础参数、路径与符号链接、成功/非零退出/超时、取消子进程、立即取消、父先退而子持管道、进程身份变化、重启后CLI查询、旧高批次statepoint不混入新作业、CSV截断和来源提示。MCP测试通过实际HTTP服务验证调用和失败回执。

修改Harness源码后沿其手册先构建再测试；verify不自动重建bundle。测试数量随代码变化，以当次实际运行记录为准，不把2026-10-13的历史摘要当作新版本通过证据。

## 3. 启用真实OpenMC测试

先按README安装运行时并配置`config/openmc.local.json`。运行：

```bash
MC_TEST_OPENMC_CONFIG="$PWD/config/openmc.local.json" \
  mcp/.venv/bin/python -m unittest discover -s tests -p test_openmc_real.py -v
```

未设置该变量时真实套件明确skip，工程测试不能据此宣称实际计算通过。启用后用真实求解器和合成截面执行两条测试：

- 直接CLI完整示例、绘图产物、绘图不能取计算结果、产物事后改变拒绝读取。
- 标准MCP客户端完整示例：发现/调用→生成→检查→提交/查询→读取→两种报告。

测试不需要私有模型或真实核数据库。原始结果保存在`artifacts/runs/20261027-openmc-interfaces/`，临时工作区结束后清理；其中绝对临时路径是当次环境记录，文件本体要留存时须另行归档。

手动演示可运行：

```bash
mcp/.venv/bin/python examples/openmc_demo.py
# 服务端先执行 ./mcp/start.sh，然后客户端：
mcp/.venv/bin/python examples/openmc_demo.py --mcp-url http://127.0.0.1:8770/mcp
```

查看返回的服务端工作区路径，实际打开Markdown/CSV/图像，不只看“完成”字样。提交、执行完成、读取成功与专业结果准确分别判断。

## 4. 部署包检查

```bash
./package.sh
```

对包核对SHA256SUMS和MANIFEST.json，确认有mc.sh、mcp模块、配置模板、示例和文档；没有本机local配置、凭据、环境、原始合同或计算产物。在新目录解压，安装依赖，配置可用OpenMC，再运行CLI与MCP示例。

更换目录可复用同一计算运行时，证明源码路径独立；它不证明真实异机、不同系统、网络/证书、防火墙或私有业务环境已通过。实际异机部署另按目标环境执行并留记录。

## 5. 甲方条件到位后的验证

| 类别 | 操作与判定 | 必要条件 |
| --- | --- | --- |
| 全15项功能 | 按RF001—015逐项用直接调用与MCP调用对照；检查实际文件/图像/报告和失败行为 | 业务模板、CAD、HPC、微调模型、资料及指定算例；各项按实际条件落实 |
| 调用成功率≥95% | 固定测试集及调用总数，逐条记录成功/失败；重试单独记录，按确认口径回算 | 甲方确认样本、分母与异常分类 |
| 接口结果准确率≥95% | 对照同输入直接程序输出或审定答案，逐条判定符合性 | 同版本、同输入设置及对应参考结果 |
| 规定物理准确率≥90% | 按17×17=289场景测试集，以相同计算设置比较关键物理参数 | 核数据/模型、专业公式、容差和参考值；不能仅比较接口执行成功 |
| 至少两个MCP宿主 | 同套服务/工具分别在两个独立宿主执行相应用例，保留参数/产物对照 | 按计划确定宿主版本及访问条件；CLI与Harness不自动算两个宿主 |
| 原多模型/本地模型要求 | 至少两个国产API等原要求，同用例核对工具选择、参数及结果；本地模型另验 | 模型服务权限及测试环境；不以受控模型代替 |
| 主备及72小时 | 注入主模型不可用场景，记录实际切换与已有操作；固定负载持续完整72小时，采集请求、异常、资源与结果 | 甲方确认负载、故障和连续性判据；定时心跳不等于无故障 |

主备验证需保留首次失败、切换过程及终态；已有输出或已执行的写操作不能盲目重放。模拟模型证据与真实服务证据分开。原功能符合率100%、性能指标达标率100%、文档完整性100%按规格判定，不新增比例或改变原口径。

## 6. 记录与报告

每次保留源码提交及是否有未提交差异、运行环境/依赖、实际OpenMC和核数据版本、用例及输入哈希、命令/参数、首个输出与失败、修复后复验、真实产物和结论。固定日志之外按运行批次归档，后续重跑不覆盖首次失败。

首批记录位置为`artifacts/runs/20261027-openmc-interfaces/`；扫描/图表/报告迭代为`artifacts/runs/20261027-scan-report/`，不入Git和默认源码包。工程实测摘要可写入项目文档，但不能把局部通过提升为整个合同验收。正式报告按表5-1记录环境、用例、结果和分析；不符合项记录整改后复验，交付按原要求组织。

## 7. 扫描、图表与报告真实用例

Quick Start准备产品依赖；要核对报告文件内容还需测试专用依赖：

```bash
./quickstart.sh
mcp/.venv/bin/python -m pip install -r tests/requirements-real.txt
MC_TEST_OPENMC_CONFIG="$PWD/config/openmc.local.json" \
  mcp/.venv/bin/python -m unittest discover -s tests -p test_openmc_scan_real.py -v
```

新套件运行真实OpenMC，不需要私有核数据。覆盖：

| 使用场景 | 预期 |
| --- | --- |
| 密度倍率×seed笛卡尔扫描 | 每组合仅一个计算编号；输入独立、密度单位和宏观截面条目保留 |
| 新算例参数修改/未知参数/坏组合/重复值/超组合数 | 原输入不变；非法组合在任何计算提交前拒绝 |
| 取消长扫描 | 当前计算取消，后续组合not_run；不把请求当终态 |
| 几何失败、stop_on_error | 失败保留，首错后不继续提交 |
| 监控被终止、启动后记录窗口中断、轮询异常 | 仍可定位已启动计算并取消，不自动重提或继续下一组 |
| 完整计分/score与filter选择、多轴固定 | 与独立官方API读取一致，不用截断预览画图，不猜选择 |
| 超图点数、报告行数限制 | 图表明确拒绝或要求缩小选择；数表能继续导出并提示省略/缺图 |
| 五种报告 | Markdown/CSV内容可读；DOCX结构及文本，PDF文本/中文，DOC的WordDocument流真实有效 |
| 转换组件缺失 | 明确失败且不登记虚假PDF |
| MCP图像与重启查询 | 标准MCP会话接收实际PNG及结构化文件位置；重启不重复计算 |

故障注入只在测试进程于真实操作边界触发SIGKILL/轮询异常；计算调用和求解器仍然执行，不用模拟物理结果替代扫描。图表数据与报告真实打开/渲染另留证。验证新断言时故意把fission选择替成flux，应测试失败，恢复后通过，保留两次记录。

完整演示：`mcp/.venv/bin/python examples/scan_report_demo.py`；标准MCP用同一脚本加`--mcp-url`。产物在服务端，清单不代表下载。本轮按用户决定不测试/交付远程下载；正式异机部署与未启动宿主另行记录。

Codex自然语言测试与标准客户端测试分开：宿主必须有可用模型、账号及工具权限。账号/模型配置错误不能报工具成功，也不能用标准MCP示例冒充自然语言通过。平台接入说明见[MCP平台接入](MCP平台接入.md)。DSH配置以官方DeepSeek Harness为依据，未经实际启动不计兼容性验收。

所选结果报告的使用方法见[HTML手册的图与报告说明](compute.html#report-selection)。报告导出成功不等于内容选对，尤其不能用默认首个统计项目代替用户选定的结果。

```bash
MC_TEST_OPENMC_CONFIG="$PWD/config/openmc.local.json" \
  mcp/.venv/bin/python -m unittest discover -s tests -p test_selected_report_real.py -v
```

使用真实求解器创建多个统计项目，明确选择第二个项目及指定score/核素/能量区间；用独立官方API对照均值/标准差，并打开Markdown、CSV、DOCX、PDF及Word97格式检查。核对报告数表、实际嵌图和完整配套CSV/JSON来自同一选择；正文最多20点且以9位有效数字显示，不能据此声称正文包含全部原始精度。能量区间逆序/零下界、多过滤器索引、显式空选择和无选择旧摘要分别核对；坏score不得覆盖旧报告。图点数上限超出时明确拒绝，不能静默截断。

现场再用既有公开C5G7结果做500点完整对照，保留修复前报告及首错，另存修复后产物。该证据支持结果后处理一致性，不代表重新计算、甲方指定模型、Helix自然语言联调或专业准确率通过。

## 1. 分清测试结论

| 测试 | 使用什么 | 能证明什么 |
| --- | --- | --- |
| 工程自动测试 | 临时文件、模拟可执行程序、实际MCP协议和受控模型 | 路径/输入检查、作业控制、错误回执、原修复及Harness机制 |

## 9. 准确率比对 harness（表4-2，D6）

`./accuracy.sh`（内部 `scripts/accuracy_baseline.py`）读参考值清单
`tests/fixtures/accuracy/manifest.json`，对每个基准：生成/复用算例（经
`openmc_create_model`）→ 登记核数据版本（模板、引擎版本、截面文件 sha256、
运行设置）→ 比对前校验（结构+引擎解析，经 `openmc_validate_inputs`）→
相同设置提交运行（经 `openmc_submit_job`）→ 读取 keff（经 `openmc_read_results`）
→ 按清单容差判定 → 输出表格与 JSON 报告（`--report` 指定路径）。

参考值两类，清单里必须写明类型与来源：

- `analytic_infinite_medium`：从算例自身的 MGXS 文件派生解析值
  `k∞=ΣνΣf/ΣΣa`（齐次、反射边界、无泄漏的单材料系统）。不硬编码数字，
  算例数据变了参考值跟着变。这是**工程统计自检**（MC 统计与解析一致性），
  不代表反应堆精度。
- `constant`：公开基准或甲方基准值，必须填 `value` 与 `source`；**缺值判
  INCONCLUSIVE 并给出原因，不冒充通过**。C5G7 多群 pin-cell 条目当前即为此
  状态（官方例题不带参考值，待公开文献/甲方值复核后填入）。

判定语义：PASS（全部已定义判据满足）/ FAIL（有判据不满足）/ INCONCLUSIVE
（缺参考值、缺 keff、非有限值、校验未过、作业未完成、容差未定义）。退出码
0=全 PASS，1=有 FAIL，2=有 INCONCLUSIVE，便于接 CI。

真实门控测试：`MC_TEST_OPENMC_CONFIG=<配置> mcp/.venv/bin/python -m unittest
discover -s tests -p 'test_accuracy_baseline.py'`；离线部分只测判定数学与清单
校验，不依赖引擎。

| 正例：自定义格架 | 修改矩形组件格架排布、密度和 seed，再构建并 `openmc_preview_input` | 保存后的 spec 保留调用方布局；预览 manifest 完整，列出 XML 与校验包 |

| 反例：悬空面/零粒子数 | 把 region 的面编号改成 99；另提交 `particles=0` | 语义校验拒绝面引用，输入 schema 拒绝 `spec.settings.particles`；均不创建目标目录；随后合法构建仍成功 |
| 边界：外边界 transmission | 先无覆盖提交，再加 `outer_boundary_transmission` 覆盖提交 | 无覆盖被拒绝并给出 transmission 原因；有覆盖构建成功，结果和 `mc-case.json` 都带覆盖 tag |

# 公开资料、例题与确认修复

工具包提供三条可独立使用的能力：离线查官方原文、按注册例题准备输入并计算、基于真实失败生成差异并在确认后重新验证。CLI和MCP使用同一实现，不需要Harness源码或模型密钥。先按根README运行Quick Start；首次下载依赖，此后这些例题与资料可以离线使用。

演示默认输出简明摘要与服务端位置；程序获取完整对象时加--json。标准协议与下游完整流程见[MCP接口](MCP服务与接口.md)和[使用指南](使用指南.md)。

## 1. 查资料

```bash
./mc.sh call list_knowledge_sources
./mc.sh call search_knowledge '{"query":"运行模式"}'
```

搜索会返回source、start_line/end_line、原文、version、source_url/citation_url和sha256。把实际source和行号用于read_knowledge，例如：

```bash
./mc.sh call read_knowledge '{"source":"openmc-0.16.0/io_formats/settings.rst","start_line":730,"limit":12}'
```

这里是随包OpenMC0.16.0原始RST的行号。原文与manifest逐次核对SHA；变化后拒绝作为已核对官方原文引用。中文参数导航帮助找英文原文，不生成专业答案。可查粒子数、批次、非活跃批次、运行模式、材料密度、核素、源项、计分、通量、几何、截面与故障。未命中不编造，用上下文与原出处继续核对。

资料源自openmc-dev/openmc固定提交617d35a5063c57796b43428bc401e627d2011046（v0.16.0），许可和来源见knowledge/openmc-0.16.0。只包含精选正文，RST的跨文件引用/include/autodoc没有展开，不是完整离线文档网站或官方中文译文。维护人员可运行scripts/update_openmc_sources.py重新取得同一固定版本；该脚本需要联网，日常工具不调用它。

## 2. 公开例题库

```bash
./mc.sh call list_cases
./mc.sh call get_case '{"case_id":"openmc-pincell-mg"}'
./mc.sh call openmc_prepare_example '{"case_id":"openmc-pincell-mg","case_dir":"demo/public-mg"}'
./mc.sh call openmc_submit_job '{"case_dir":"demo/public-mg"}'
```

拿到实际job_id后查询终态，再调用openmc_read_results、openmc_plot_results和openmc_export_report。也可一条命令演练：

```bash
mcp/.venv/bin/python examples/public_case_demo.py
# 服务先启动 ./mcp/start.sh，再运行：
mcp/.venv/bin/python examples/public_case_demo.py --mcp-url http://127.0.0.1:8770/mcp
```

| case_id | 数据与状态 |
| --- | --- |
| synthetic-mgxs | 自制合成单群工程示例，Quick Start环境即可计算，非真实材料/专业基准 |
| openmc-pincell-mg | OpenMC官方多群燃料棒，官方源码自带C5G7多群数据，无需外部核数据库；固定源码SHA校验后执行 |
| run-mode-typo | 故意含eigenvale拼写错误的合成练习，首次预期failed，供确认修复流程测试 |
| openmc-pwr-pin-cell | 官方连续能模型，可以生成；计算还需要匹配的真实核数据库，未提供时不宣称可运行 |
| CLEAR-S、17x17 | 甲方指定基准仍待输入/环境/参考判据，不能运行或替代验收 |

ready_to_prepare表示环境条件满足后有明确生成入口，execution_status=not_run表示这次查询/生成尚未执行计算。真正完成以提交后的job状态和产物为准。prepare_example可指定particles/batches/inactive，默认200/10/2用于工程演示，不冒充官方推荐收敛设置；记录保留实际覆盖值和来源。官方例题原文与MIT许可在vendor/openmc-examples/0.16.0。

能谱图当前横轴是OpenMC能量过滤箱顺序，未换算为单位能量/单位对数能量归一化；对应JSON/CSV和原StatePoint保留。公开数据计算成功不表示甲方物理准确率已达标。

## 3. 诊断、确认与重验

完整演练：`mcp/.venv/bin/python examples/repair_demo.py`，MCP模式加--mcp-url。程序先故意提交错误输入，正常情况下首次应failed。操作次序是：

1. openmc_diagnose_job读取真实日志尾部和原输入快照，给出证据行、规则/官方出处及有限建议。实际入口优先model.xml，不分析未使用的遗留settings.xml。
2. openmc_prepare_repair核对原输入哈希，把输入复制到新的普通算例目录，生成plan_id及diff。原输入/失败作业不动，也不应用修改。
3. 读read_repair_plan，展示差异并取得真实用户确认，再调用apply_repair。用户拒绝则不改、不重算。直接CLI强制TTY确认；MCP由可信宿主负责同样的确认过程，模型confirmed=true不构成确认，也不在schema中。
4. openmc_recheck_repair仅接受已应用的关联计划，核对全部输入未再次变化，做XML/API校核，只有通过才提交新计算。返回origin_job_id及新job_id，重复调用查询同一重算，不隐式再提交。
5. 按新job_id查终态，成功后读取/导出结果；失败继续保留新旧记录，不能把“修改完成/校核通过”写成“计算成功”。

当前自动闭环只支持普通run计算，自动准备的差异仅限官方run_mode枚举中唯一近似拼写，例如eigenvale→eigenvalue。几何重叠、丢粒子、缺材料/核素、截面问题提供排查方向，不猜物理参数、删除核素或生成不存在的数据。绘图/几何调试必须按原模式另行显式验证，不能被自动转为普通计算。

只修一处拼写也可能留下另一处错误：例如核数据路径仍缺失，校核可通过而重算仍失败。工具保留此状态，并要求继续核对，不自动猜下一处修改。

## 4. 确认和文件边界

所有.mc-*目录是内部证据/控制记录，通用修复工具禁止写入。修复用新副本；预览后文件或计划变化会拒绝，跨进程修改同一目标有文件锁。重验绑定计划及输入集合/哈希，并在实际计算快照创建后再核对，避免校核与提交之间输入变化。

本工具服务不包含通用人类身份认证。MCP的tools/call本身不能证明用户同意；可信宿主必须展示预览、让用户批准当前apply_repair，并防止模型自己批准。可选Harness与本演示终端客户端有这种策略；其他宿主需配置/验证，不能仅凭destructiveHint认为确认已执行。不要给apply_repair配置永久自动批准。

示例/源码的编写与测试授权不代表正式业务输入修改的逐次确认。TTY测试自动驱动n/y证明交互分支行为，仍不冒充真人见证或专业验收。其他普通提交/绘图/导出仍由宿主按实际部署策略处理。

## 5. 记录在哪里

原输入和首次失败日志在workspace/.mc-jobs/<origin_job_id>/；修改后的新算例在指定target_dir；计划、差异、备份和重验关联在内部.mc-plans/.mc-backups；新计算、结果与报告在新的.mc-jobs/<job_id>/。read_repair_plan可查当前状态与关联，openmc_list_artifacts可列计算产物。文件都在服务器，远程下载仍未加入本轮。

本轮测试包括资料哈希/出处、未知查询、真实官方例题、真实首次失败、CLI/MCP终端拒绝与接受、过期/并发/重复请求、实际入口选择、快照保护和修复后仍失败。方法和证据见测试与验收说明。甲方业务模型/专业规则、CLEAR-S及原合同完整指标仍按后续计划落实。

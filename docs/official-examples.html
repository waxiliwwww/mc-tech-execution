官方例题工作流

选例题，提供输入，逐步完成计算

先看简表：openmc_list_official_examples可传group="api"、limit=10、summary=true，按next_offset翻页；详情用openmc_get_official_example。省略新选项保留原全量输出，count仍是筛选总数。状态描述的是清单适配，不是某个实例已执行。

同一套例题工作流可以直接在终端操作，也可以通过标准MCP交给智能体。每次创建新实例，保留输入、各步骤日志和真实结果；下载原文、适配器存在与实际计算通过分别记录。

先区分：收录、历史验证、本次执行

看到的字段或记录应怎样理解
scope=included纳入本包的官方例题范围并提供对应入口，不表示在甲方服务器上已经运行通过。
implementation_status / execution_status=not_run目录工具返回静态适配说明和占位状态，不查询工作区或历史运行；某例题跑过后，目录也可能仍返回not_run。不能由此统计“未运行多少条”。
历史实跑快照开发环境的记录，附当时实例编号；不随源码包迁移运行数据，不作为新部署已通过的证明。
当前实例的状态记录本次instance_id，调用openmc_example_status；按next_step逐步执行。只有state=completed、next_step=null且全部声明步骤完成，才记录本实例流程完成，再读取结果及产物。

部署到甲方自己的服务器后，使用该服务器新建的实例、版本、日志和结果填写试用记录；没有本地记录就写“本部署未验证”，不要复制历史编号充当本机完成记录。

第一次操作

初次运行 ./quickstart.sh 准备OpenMC、Notebook与报告依赖及固定官方原文。服务端支持Linux/WSL；自定义源例题还需初配C++编译器。核数据按实例所选公开库准备并缓存，首次联网可能较慢；已有管理员数据可在配置中指定 cross_sections。例题默认使用OpenMC官方多温度ENDF/B-VII.1库，首次下载约1.7GB、展开约6.3GB；不混用不同评估库。

./mc.sh examples list
./mc.sh examples show source-pincell-multigroup
./mc.sh examples run source-pincell-multigroup --dir cases/my-first-official

这个例题来自OpenMC主仓库：先生成多群模型与截面，检查数据，再真正启动OpenMC。省略设置覆盖时保留官方原值：每代1000粒子、100批、10个非活跃批。不是此前演示脚本的200/10/2小规模练习。--dir 相对于工作区，目录必须不存在；再次练习换一个新目录。

结果在哪里，下一步做什么

命令结束打印实例编号、状态、原始结果绝对路径和各阶段产物位置。将返回的实例编号放入下列命令；不要照抄别人的编号。results 会列出真实可用的计分ID、名称、score和维度。

./mc.sh examples results 实例编号
# 本例的计分2是通量能谱，score为flux
./mc.sh examples plot 实例编号 --tally-id 2 --score flux
./mc.sh examples report 实例编号 --tally-id 2 --score flux --format markdown

图与报告采用相同计分选择，均返回服务端绝对路径，并保留完整CSV/JSON。能谱横轴说明能量单位与分箱坐标；保留OpenMC原始计分归一化。导出PDF/DOC需初配Office。Notebook已有原生图文报告；燃耗、脉冲等多阶段例题另按阶段保存曲线/数值，不强行解释成一个最终keff。

默认工作区是本包的 workspace/；也可用 MC_WORKSPACE=/绝对目录 指定。输入在所选的cases目录，实例在 .mc-examples/实例编号/，步骤作业在 .mc-jobs/作业编号/。这些目录位于服务端，远端客户端不会自动下载。

Notebook里有多次计算时

Notebook原文按顺序执行，报告保存实际代码、图、表与错误。每次求解保留自己的XML与原始结果，不让后一次同名StatePoint覆盖前一次依据。results 列出求解阶段；例如 ./mc.sh examples results 实例编号 --calculation 0002 只读取所选阶段。报告中的“本单元实际读取”按文件哈希关联结果。

初始化、逐批计算与完整求解分开标记；C API前后材料/温度另存properties；燃耗晚写的结果按真实文件名关联。XML与结果快照并非完整独立重跑包：网格/截面等资源保留身份，仍使用该作业文件与初配数据库。Notebook图文用其原生报告；通用 examples plot/report 仅适用于独立compute步骤，拒绝暗中把Notebook最后一份结果当作所选阶段。

兼容适配在报告和阶段记录披露。例如CAD仅调整源采样接受率的中止守卫，记录修改前后XML及语义比较；不修改粒子数、物理源分布或模型约束。运行成功不等于专业计算结论已确认。

拆成步骤运行，适合检查或智能体调用

./mc.sh examples prepare source-pincell-multigroup --dir cases/step-by-step
./mc.sh examples status 实例编号
./mc.sh examples step 实例编号 prepare --wait
./mc.sh examples step 实例编号 data --wait
./mc.sh examples step 实例编号 compute --wait
./mc.sh examples results 实例编号

以 status 返回的 next_step 为准，其他例题可能有编译、重启或后处理步骤，不能跳过。重复提交同一步返回已有作业，不偷偷重跑；失败后使用新实例保留原失败。等待超时不等于作业失败，先查询（智能体可用 wait_seconds:30 做有上限等待；终端为 examples status 实例编号 --wait-seconds 30）；需要停止则用 examples cancel 实例编号。详细JSON在命令末尾加 --json。

哪些参数可以改

对普通模型，可显式传 --particles、--batches、--inactive、--seed，原值和修改值一并保留；减配结果不能当原设置复现。Notebook内部可能包含多次不同计算，目前不接受通用覆盖，以免静默忽略参数。完整自有模型仍走原生Python/XML接入。

工厂特有输入在 examples show 中列明，例如随机射线pin-cell的 --factory-parameters '{"second_temp":true}'。一维多群工厂slab_mg必须用 --mgxs-file inputs/my-library.h5 提供真实多群库，其中包含 mat_1…mat_N 组；多分区用 --factory-parameters '{"num_regions":2}'。不替用户猜截面数据，也不自动将真实数据换成合成数据。

MCP怎样接入

按标准服务部署说明启动MCP，将服务输出的连接地址、传输方式和鉴权信息交给宿主。平台接入方法是扩展说明，工具包不依赖某一个平台。智能体先查询例题说明，再逐步调用这些工具：

中文操作／代码名输入 → 输出
列出官方例题 openmc_list_official_examples可选来源组 → 固定例题清单，未执行不显示为已通过
读取例题说明 openmc_get_official_exampleexample_id → 输入条件、公开参数、来源、步骤
准备实例 openmc_prepare_official_exampleexample_id、新case_dir、可选parameters → instance_id、下一步
执行步骤 openmc_run_example_stepinstance_id、next_step.id、线程数 → job_id；不代表计算已完成
查实例 openmc_example_statusinstance_id → 实际状态、日志尾、下一步
读取结果 openmc_read_example_resultsinstance_id、可选calculation_id → 真实计算量、Notebook报告／所选阶段结果、产物绝对路径
取消实例 openmc_cancel_exampleinstance_id → 取消请求，继续查询终态

openmc_read_example_results返回数值预览：max_values默认1000、可设1..10000，对每个tally分别限制。shape/total_values是完整维度/值数，returned_values和values_truncated说明实际返回范围；不能把完整shape当作已返回数组长度。大结果可先传max_values:20，完整数据在statepoint_server_path，通过管理员/SCP交付。绘图及显式选择的报告读取原始数据，不用截断预览代替全量；Notebook选择calculation_id时同样遵循此上限。

绘图／报告继续调用 openmc_plot_results 与 openmc_export_report，使用实例compute步骤返回的job_id与所选计分。MCP参数说明与CLI一致，见完整接口参考。标准MCP协议调用已经演练；Helix两条代表流程仍待完成。

清理练习产物

停止服务和其他写操作、确认实例已结束后，先预览再显式执行。实例清理连同所属步骤作业一起处理；被例题引用的单个作业不能孤立删除。原cases输入、运行环境、核数据缓存保留。

./cleanup.sh --example-id 实例编号
./cleanup.sh --example-id 实例编号 --apply

固定官方范围与当前实跑记录

主仓库与内置工厂固定OpenMC0.16.0；Notebook固定官方仓库版本。13个主仓工作流（含变体与重启）、9个公开工厂、28份Notebook，共50个入口。其中两份使用已移除共振重构的核数据Notebook按用户决定暂缓，本轮完成其余48项；第三方例题不纳入。清单完整不表示全部已通过，后续补齐未通过项。原始Notebook缓存输出会先清除，再保存本次实际执行输出；错误和未执行单元不伪装成功。来源版本、文件哈希及明确的0.16兼容适配保留在实例和报告中。

以下为开发中实测快照，历史成功不代替最终组合回归、独立新机安装或专业验收。目前已完成并读回 48 个本轮入口（范围48项，另外2项暂缓），其他按实际状态列出。本版提供上述例题工作流；Helix两条完整自然语言任务按用户决定留待验证。合同CAD/HPC/微调生成、指定基准与专业指标另按原计划推进，公开例题不替代它们。

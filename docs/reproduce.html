1．先准备服务，再让DSH连接

角色：管理员操作Linux服务器；试用者操作Windows DSH。输入与产物都在服务器，Windows路径不能直接作为case_dir。公开模型和数据由环境准备提供，不需要甲方私有模型。

管理员：一次性准备和启动（Linux服务器）

准备完整源码包到$HOME/mc-tech-execution，以下命令均在该目录执行。已有安装沿用其目录，不再次覆盖配置。首次准备需要软件源网络、C++编译器、make及足够空间；官方核数据约6GB展开，运行时和后续作业另占空间，先核对目标磁盘。

cd "$HOME/mc-tech-execution"
git rev-parse HEAD
df -h .
# 已安装并核对过环境可跳过；本流程不使用CAD和Office转换：
./quickstart.sh --skip-cad --skip-office
./mc.sh call openmc_environment '{}'
./mc.sh call openmc_storage_report '{}'
export MC_WORKSPACE="$PWD/workspace"
export MCP_HOST=127.0.0.1
export MCP_PORT=8770
./mcp/start.sh

环境返回api_available、executable_available、version_matches须为true；核数据由quickstart准备并配置official-endfb-vii.1。服务保持运行，首次试用按单任务、1线程安排。已有其他服务占用8770时先查清归属，不关闭未知进程。示例为交互前台启动，长期服务托管另按部署环境落实。

Windows DSH：选同机或远程连接

WSL同机：直接用http://127.0.0.1:8770/mcp。自有Linux服务器：本页采用SSH隧道，不把无认证回环服务暴露到公网。在PowerShell单独开窗口，替换登录用户和服务器地址，使用现有获授权的SSH身份：

ssh -N -L 8770:127.0.0.1:8770 linux-user@server-address
# 保持该窗口开启；若本机8770已被占用，停止本步骤并请管理员协调端口。
# 另开PowerShell：
Invoke-RestMethod http://127.0.0.1:8770/health

隧道的登录认证由SSH负责；DSH仍连接本机8770。若使用已有HTTPS/Bearer网关，按远程部署说明和所用DSH版本的认证配置接入，本页不猜测插件的令牌字段。

确认DSH当前profile后，备份%USERPROFILE%\.dsh\profiles\desktop\cordis.patch.yml，将以下patch追加一次，保留原模型配置：

- insert:
    - id: mcp-mc-tools
      name: '@deepseek-ai/dsh-mcp-client'
      config:
        serverName: mc
        transport: streamable-http
        url: http://127.0.0.1:8770/mcp
        failOnStartupError: true

如已存在同一插件，仅核对地址，不重复插入。保存后按DSH连接说明确认加载；在工具列表查找mcp__mc__openmc_environment，只调用它检查环境。找不到工具先解决连接，不能让模型自行安装包、猜工具名或用Shell替代本次MCP流程。服务健康、工具发现、实际调用分别记录。

后续表中代码名不含宿主前缀；DSH调用时通常为mcp__mc__加原名。参数就是表内JSON，工具定义由DSH通过tools/list获取。

2．例一：官方17×17组件 → 通量分布 → 报告

研究对象：OpenMC内置openmc.examples.pwr_assembly()，使用官方组件几何与材料。我们适配生成输入，新增规则网格flux计分并覆盖采样设置。它不是甲方指定组件，也不是未修改的官方完整统计计算。

先理解四个输入：case_dir是服务器工作区内的新模型目录；particles=1000是每代粒子数；batches=12是总批数；inactive=2是前两批不计入活跃统计。本次仅有10个活跃批，便于学习接口，专家计算需自行确定采样与收敛条件。

2.1 新建输入，追加明确要计算的量

创建模型 openmc_create_model

{
  "case_dir": "reproduction/assembly-001",
  "template": "assembly-17x17",
  "particles": 1000,
  "batches": 12,
  "inactive": 2
}

目录已存在就停下，保留旧输入，改用新的后缀。成功后记录返回的case_dir。模型内容来自包内官方工厂适配，不是DSH现场编写物理算法。

定义计分 openmc_define_tally

{
  "case_dir": "reproduction/assembly-001",
  "name": "assembly central slice flux",
  "scores": [
    "flux"
  ],
  "filters": [
    {
      "type": "mesh",
      "dimension": [
        17,
        17,
        1
      ],
      "lower_left": [
        -10.71,
        -10.71,
        -1
      ],
      "upper_right": [
        10.71,
        10.71,
        1
      ]
    }
  ]
}

tally是希望OpenMC统计的量，本例统计中间2cm厚区域内的flux；x/y覆盖21.42cm组件宽度，分为17×17格。每格是空间统计箱，不承诺等于一个独立燃料棒或组件功率。记录本次返回的tally_id为T，下文T必须替换成实际整数，不能猜1或17。未定义计分就不会自动出现相应结果。

2.2 看输入，分别核对各层校验

预览输入 openmc_preview_input

{
  "case_dir": "reproduction/assembly-001"
}

查看返回的files中settings.xml采样设置、材料/几何摘要和tallies.xml计分；预览内容可能截断，以文件SHA256记录本次确认的输入。保留本次返回值供提交快照比较。

校核输入 openmc_validate_inputs

{
  "case_dir": "reproduction/assembly-001",
  "api_check": true,
  "semantic_check": true
}

继续条件同时满足：structure_valid=true、openmc_api.api_parsed=true、semantic.checked/ok/complete均为true。complete=false不算已全部校验，通过skipped_reason查未执行的原因；报错则停止，不跳过错误提交。此处API读回/静态校验不做真实几何抽样，也不替代专业判断。

2.3 命名提交，按返回编号查到终态

提交计算 openmc_submit_job

{
  "case_dir": "reproduction/assembly-001",
  "name": "组件公开模型试用-001",
  "threads": 1
}

将返回的job_id记录为J，通常是32位字符串。下面JSON中的"J"只表示这次真实编号，执行前替换；T也是实际整数。不要复制示例占位符直接执行。

查询状态 openmc_job_status

{
  "job_id": "J"
}

queued/running时隔几秒再查原编号；completed后才能读结果。failed/cancelled/interrupted进入失败处理，不假装完成。将终态input_hashes与预览files的SHA256逐项比较；不一致时停止把结果归属于先前确认输入。

2.4 读取真实结果，再按实际tally生成产物

读取结果 openmc_read_results

{
  "job_id": "J",
  "max_values": 10000
}

在tallies数组找id=T且score含flux的计分，确认nuclides为total、values_truncated=false、mean和std_dev各289个数。查看keff及其std_dev；有null或warnings要保留并说明。不能为得到图而静默选择另一个tally。

空间热图 openmc_plot_mesh

{
  "job_id": "J",
  "tally_id": "T（替换为整数）",
  "score": "flux",
  "format": "png"
}

返回PNG路径及values_json/values_csv。横轴x/cm、纵轴y/cm，颜色是该网格的原始flux计分；本例只有一层，不需要level。不是实际功率，也没有追加体积或外部源强归一化。

完整所选曲线 openmc_plot_results

{
  "job_id": "J",
  "tally_id": "T（替换为整数）",
  "score": "flux",
  "nuclide": "total",
  "filter_selection": [],
  "format": "png"
}

此曲线横轴是明确标注的展平网格分箱索引，用于逐点核对，不是能量轴或空间长度。空间关系看前一张热图。

所选结果报告 openmc_export_report

{
  "job_id": "J",
  "tally_id": "T（替换为整数）",
  "score": "flux",
  "nuclide": "total",
  "filter_selection": [],
  "format": "markdown"
}

保留selection_mode、selection、points、chart、series_json和series_csv；应为selected、同一T/flux/total/空筛选、289点。报告引用的是完整所选曲线，不会自动嵌入前一张网格热图；热图作为独立产物一起交付。Markdown无需Office；PDF等需另配转换环境。

列产物 openmc_list_artifacts

{
  "kind": "job",
  "identifier": "J"
}

记录directory和每个artifact.server_path，下一节按这些真实文件核对。不要用DSH当前目录猜测.mc-jobs的位置。

4．怎样核对结果，不只看“文件生成了”

  1. 归属：记录J/T、输入SHA256、版本、采样与种子；所有结果必须来自同一J。read_results的keff与statepoint一致，缺不确定度不能补0。
  2. 图与数：热图配套JSON的dimension应为[17,17,1]或[8,8,1]，values/errors分别为17×17或8×8；CSV中(i,j)对应JSON的values[j][i]与errors[j][i]。x/y中心由边界等距计算：组件首格中心(-10.08,-10.08)cm、全堆(-175,-175)cm。
  3. 原生计分：本例单一mesh、flux、total，原生展平索引为i+nx*j；将StatePoint该tally均值/标准差与热图每格核对。完整曲线JSON的mean/std_dev应按该顺序一致；CSV以9位有效数字显示，比较时允许显示舍入，不引入物理准确率容差。
  4. 报告：打开report.md，检查版本、采样、选择说明与正文引用的plot-*.png/json/csv；报告预览最多20点，完整CSV仍289/64行。对照第1、最后1个点及任一中间点，核对均值和标准差，不能拿另一个tally替代。报告附带的曲线与此前显式生成的曲线文件名可能不同，数据选择和值应一致。
  5. 科学结论：这轮只说明公开模型经过工具处理得到相互一致的计分和产物。图的空间差异是样例原始计分分布，不足以断言工程功率、收敛或专业精度。需更高统计、参考值、归一化和专家判据后才能作进一步结论。

推荐先打开网格PNG理解空间分布，再打开report.md看计算信息和所选曲线，最后用配套CSV/JSON核数。图表文件名是随机唯一名，以工具返回为准。

管理员：从服务器直接核对原生StatePoint与派生JSON

在包根目录，用产物清单directory的实际绝对目录替换第一行，用本次真实T替换第二行。使用配置中实际OpenMC环境的Python；下列为quickstart默认安装路径。此检查只读取文件，不重新求解；任何assert失败都应保留并定位，不删除文件重来。

JOB_DIR='/实际返回的directory绝对路径'
TALLY_ID='实际返回的整数tally_id'
.runtime/openmc/bin/python - "$JOB_DIR" "$TALLY_ID" <<'CHECK'
from pathlib import Path
import json, sys
import numpy as np
import openmc
p=Path(sys.argv[1]); t=int(sys.argv[2])
r=json.loads((p/'job.json').read_text())
assert r['state']=='completed'
points=[p/'work'/name for name in r['output_files'] if name.startswith('statepoint.') and name.endswith('.h5')]
assert len(points)==1, '本流程应只有最终StatePoint；多个文件须先明确实际结果来源'
with openmc.StatePoint(points[0], autolink=False) as sp:
    tally=sp.get_tally(id=t)
    assert list(tally.scores)==['flux'] and list(tally.nuclides)==['total']
    mean=tally.mean.reshape(-1); std=tally.std_dev.reshape(-1)
    print('原生keff：',sp.keff,'；计分点数：',len(mean))
curves=[]
for f in p.glob('plot-*.json'):
    d=json.loads(f.read_text())
    if d.get('tally_id')!=t or d.get('score')!='flux': continue
    assert d['nuclide']=='total' and d['filter_selection']==[]
    np.testing.assert_allclose(np.asarray(d['mean'],dtype=float),mean,equal_nan=True)
    np.testing.assert_allclose(np.asarray(d['std_dev'],dtype=float),std,equal_nan=True)
    curves.append(f.name)
meshes=[]
for f in p.glob('mesh-*.json'):
    d=json.loads(f.read_text()); nx,ny,nz=d['dimension']
    assert nz==1 and nx*ny==len(mean)
    np.testing.assert_allclose(np.asarray(d['values'],dtype=float).reshape(-1),mean,equal_nan=True)
    np.testing.assert_allclose(np.asarray(d['errors'],dtype=float).reshape(-1),std,equal_nan=True)
    meshes.append(f.name)
assert curves and meshes, '缺少曲线或热图完整JSON'
report=(p/'report.md').read_text()
assert any(name in report for name in curves), '报告未引用本次所选曲线元数据'
print('原生计分、曲线/热图JSON及报告引用一致；仍需目视图、CSV与报告正文。')
CHECK

该读取片段针对本页单次新目录、单tally流程；不作为任意作业的通用物理验收程序。它不检查所有CSV显示舍入，也不识别图像像素，应结合上面的人工核对。

文件怎么拿到Windows

同机WSL用\\wsl.localhost\Ubuntu加服务端Linux绝对路径浏览；例如directory为/home/user/mc-tech-execution/workspace/.mc-jobs/J，资源管理器打开\\wsl.localhost\Ubuntu\home\user\mc-tech-execution\workspace\.mc-jobs\J，替换真实目录与J。

远程服务器由管理员交付产物；如获准SSH文件访问，在Windows PowerShell执行下式，将返回directory的真实绝对路径整体替换后下载到新目录：

scp -r linux-user@server-address:/真实绝对目录/.mc-jobs/真实J .\mc-result-真实J

保留图、CSV、JSON和report.md的同目录关系再打开报告。工具目前不提供远程下载接口；下载是人工交接步骤，MCP返回路径不等于浏览器可点击的下载URL。

5．不经过模型的标准MCP脚本复现

reproduce_public_models.py执行与上述相同的工具调用，便于比较“工具本身是否可用”和“DSH是否正确组织调用”。它不调用LLM，但会提交真实计算；用户统一实测时再执行：

# 在源码包根目录执行；MCP服务需已启动。
mcp/.venv/bin/python examples/reproduce_public_models.py \
  --mcp-url http://127.0.0.1:8770/mcp --model assembly
# 组件成功并核对后，再执行全堆：
mcp/.venv/bin/python examples/reproduce_public_models.py \
  --mcp-url http://127.0.0.1:8770/mcp --model core

脚本默认新建唯一目录，使用1000粒子/12批/2非活跃批、1线程、600秒求解等待；--help列出可调选项和含义。可明确改变采样，不能据此改掉专业输入。

默认客户端记录保存到脚本所打印的artifacts/reproduction/<model>-<nonce>.json绝对路径；服务端产物另打印directory。每次调用前后增量保存工具名、参数、返回值和J/T。遇未知响应不自动重试，超时只请求取消并保留J；仍须查原编号确认终态。

脚本检查完整校核、输入指纹、计分点数与报告选择；文件内容交叉核对标记为待按第4节执行，不能把脚本退出0当作全部检查通过，更不能替代DSH自然语言验证。

6．失败、恢复与清理

情况怎样处理怎样继续
连接/发现失败核对health、隧道、profile和插件事件，不重复提交。先使环境工具只读调用成功，再进入建模。
目录重复/输入不完整保留旧目录；核对校验problems和skipped_reason。缺核数据请管理员处理。修正明确原因后重新校核；新一轮用新目录。不得让模型猜材料、跳过不完整检查。
提交响应未知记录原case_dir、任务名及工具调用记录，用openmc_list_jobs按精确name查询，核对case_dir和时间。找到作业后继续原job_id；多个匹配由用户确认。未确认无作业前不重投。
超时/取消/失败用原J查询openmc_job_status，看error、日志和终态。需要取消时调用openmc_cancel_job，再查询到终态。保留首次记录。先处理原因，资源变更经用户确定；重算用明确关联的新作业。
图或报告失败先查原J是否completed；原生结果保留，不为重出报告重做求解。修复依赖/选择后仅重调相应产物工具；同格式报告会覆盖，留旧版先归档。

每轮填写：提交SHA、环境/核数据、J/T、采样、选择、是否截断/警告、产物目录、数据核对、DSH自动完成或人工补操作、首次失败和复测。分别记工程通过、未覆盖、发现问题、待专业判定，不预填结果。

结束后先用openmc_storage_report查看占用，按清理说明预览本次J的删除计划。只在维护窗口、资料归档后执行；原输入、核数据库、运行时和必要证据保留，不用一键全删腾空间。

当前实现说明；运行、模型联调与专业验收分别记录。合同进展另见执行对照。

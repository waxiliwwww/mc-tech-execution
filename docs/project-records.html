04 / 踩过的坑
四个会浪费半天以上的问题

症状原因处理
CMake 找不到 HDF5只找 PATH 上的 h5cc / h5pcc设 HDF5_ROOT 指向安装根目录
编译通过，运行时段错误或符号缺失HDF5 与 OpenMC 不是同一编译器工具链全流程固定一个工具链
import openmc 正常，import openmc.lib 失败共享库必须在 openmc/lib/ 包目录内，源码用 importlib.resources 定位，不搜 LD_LIBRARY_PATH由包管理器放置，不手工搬运 .so
开 MPI 后并行 I/O 失败用了串行 HDF5链接并行 HDF5，并设 HDF5_PREFER_PARALLEL=on

另有一条：使用 openmc.lib（燃耗、CMFD）时，h5py / mpi4py 建议与 OpenMC 用同一编译器与 HDF5 版本重装，否则问题只在燃耗阶段暴露。

Windows 不在官方支持范围。 OpenMC 安装文档中“在 Windows 上编译”一节只有一句：使用 WSL，再按 Linux 流程编译。甲方若提供 Windows 桌面机，只能在 WSL 或容器中运行，前置条件需写入部署说明。

06 / 可复现
两件改变结果、但与统计无关的事

  • 线程数。OMP_NUM_THREADS 不同，随机数分配路径不同，同一 seed 也会得到不同结果。任何“同输入同结果”的承诺都要连同线程数一起写。
  • 编译选项。RelWithDebInfo（-O2）与 Release（-O3）之间、以及是否开启 OPENMC_ENABLE_STRICT_FP，会产生比特级差异。跨环境比对要么统一编译选项，要么明确按统计判据比较，不比比特。

当前 runtime.json 已记录配置快照；建议补充线程数与 OpenMC commit hash，使复查不必推断。

07 / 选择
安装路径怎么定

路径结论说明
conda / micromamba采用唯一环境来源，由 config/openmc-linux-64.lock 锁定
源码编译不采用除非需要自定义开关组合，维护成本高
Spack仅 HPC 备用默认 MPI off、OpenMP on、RelWithDebInfo，与本地组合不同，混用会产生结果差异
Docker可选交付包装镜像应由同一 lock 文件构建，保证与本地环境一致

离线部署需准备本地 channel 或等价离线包，避免目标机无外网导致安装中断。切换 MPI 版本会连带更换 HDF5 与 h5py 的构建，不要为了 HPC 随手改锁文件。

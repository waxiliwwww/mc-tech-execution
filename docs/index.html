它在现有计算中负责什么

你的模型输入校核与输入快照OpenMC 求解结果、图表、报告

OpenMC 是蒙特卡罗粒子输运计算软件，模型描述几何、材料、源和要统计的量。本包复用它的计算能力，增加一套统一的调用与文件管理方式。熟悉 OpenMC 的用户可以沿用自己的建模流程；不熟悉业务的用户先用公开例题理解工具操作。

你要做的事本包当前能提供
带入输入接收已导出的 OpenMC XML 与所需数据，检查 XML 和基础设置，可选官方 API 解析。
重复计算、比较设置保留原输入创建参数副本；提交、查询、取消；按发现的参数做串行批量扫描。
整理结果读取 StatePoint 结果文件、选择计分生成图及对应 JSON/CSV，导出多种格式报告。
管理文件独立计算编号、输入快照、日志、产物位置与哈希清单；提供预览和显式清理入口。
交给下游调用终端 CLI 与标准 MCP 调用同一组工具；MCP 参数带类型、含义和来源说明。
参数有三个层次。演示脚本只开放少量命令行选项；工具接口用 JSON 描述一次操作；完整模型由 OpenMC 的 Python/XML 表达。三者如何衔接、哪些字段能自动修改，见自有模型与源码。

专业模型、核数据库、结果判断由业务方准备和确认。当前已有工具不能替代完整合同交付；CAD复杂件、HPC、微调生成和指定专业基准等状态，仍见近期开发计划。

只想先试运行：先知道它会做什么

完成环境准备后，可用下面的脚本快速检查链路。它会新建一个公开多群燃料棒算例，实际运行 OpenMC，画通量能谱图并导出 Markdown 报告。它固定了模型和流程；你不需要从这个脚本继承自己的业务。

mcp/.venv/bin/python examples/public_case_demo.py

本包例题默认每代 200 个粒子、总批次 10、非活跃批次 2，用于短流程练习。正常结束会打印计算编号，以及输入、记录目录、图和报告的服务端绝对路径。统计提示保留，不以这组小规模设置证明收敛或专业准确性。

这个脚本到底有哪些参数？
选项含义 / 省略后的行为
--particles每代模拟粒子数，正整数；工具默认 200。改变统计采样量，不能保证某次结果更准确。
--batches总批次数；工具默认 10。
--inactive非活跃批次数，不计入活跃批次统计；工具默认 2。非负，且 batches − inactive 至少为 2。
--case-dir服务端工作区内的新输入目录；默认 demos/public-mg-随机后缀。已存在会报错，不覆盖。
--report-formatmarkdown（默认）、csv、docx、pdf、doc；后两者需 Office 转换组件。
--timeout脚本等待计算终态的秒数，默认 120；超时会请求取消，后续按编号查询。不是服务端作业时限。
--mcp-url实际服务地址；省略时直接 CLI 调用，无需启动 MCP 服务。
--json将默认人读摘要换成完整 JSON；进度仍写到 stderr。
-h / --help查看脚本选项，不执行计算。

这些选项只有运行设置与演示控制，不包含任意几何或材料字段。要改变模型，走参数发现与输入副本，或准备自己的输入。

其它 demo 用来验证什么？它们能调哪些参数？

四个脚本都支持 --mcp-url、--case-dir、--timeout、--json 和 --help。目录默认各自随机生成；普通/修复例题等待默认 120 秒，扫描默认 180 秒。

脚本固定流程与可额外调整项
public_case_demo.py公开 C5G7 例题 → 计算 → 通量图 → 报告；上表列出全部选项。
openmc_demo.py合成单群模型 → 计算 → Markdown/CSV；无额外模型参数选项。
scan_report_demo.py合成模型的第一项密度参数按 0.8 / 1.0 / 1.2 扫描，画图并导出报告；额外 --formats 可选多个格式，默认五种全导出。没有扫描轴命令行选项，改扫描任务应调用扫描工具。
repair_demo.py故意的运行模式拼写错误 → 失败日志 → 副本差异 → 人工确认 → 重算；没有额外参数，需交互终端。

扫描例的 macro 是宏观截面倍率，不能当真实质量密度；keff 可能几乎不变，统计量也可能不可用。这些演示用于看懂工程行为。

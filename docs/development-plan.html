本机或甲方服务器怎样复现

在已配置真实运行时的包根目录执行。路径替换为本机实际配置，证据目录每次换新；不修改模型配置或启动已有服务。脚本只调已有真实测试，自动创建隔离服务/工作区并在结束后清理临时资源。

MC_TEST_OPENMC_CONFIG="$PWD/config/openmc.local.json" \
  mcp/.venv/bin/python scripts/verify-pilot-workflows.py \
  --workflow all --evidence-dir artifacts/pilot-my-run

也可将all换成official/build/import/scan/repair逐条执行。每条result.json须为PASS，skipped为空，required evidence与辅助记录不缺失；失败先保留当前目录，修复后换新尝试目录。证据复制失败时原临时目录保留并在temporary-directories.json中标明，不能自动删除现场。

如何执行与收口

  1. 每条先复用对应真实测试和原示例；没有设置真实运行时就停止，不用skip记通过。留存首次失败、实际输入、job/实例编号、所选数据及日志；模拟与合成数据单独标识。
  2. 失败先分清产品、测试、环境；只修本轮P0/P1或基础使用阻断，跑失败点和受影响测试。新能力、权限、恢复或验收取舍先确认，不能靠降低断言或缩小合法输入凑绿。
  3. 冻结源码后运行既有verify.sh --release；五条固定流程和既有发布关键项均不得缺失或skip。期间不改代码。
  4. 从最终源码打包，核对归档自洽和包内文件与定稿源码逐项一致；新目录解压后验证文档与代表流程，再按已确认的仓库交付方式推送。

每条流程保存unittest.log、result.json和受限证据副本；记录运行版本、依赖/核数据条件、测试范围、失败处置和未覆盖项。资源释放只清可再生成临时内容，原业务记录与必要证据保留。

最终状态和当前证据集中在项目进展；原两周安排及领域/HPC配合项仍保留在历史实施明细，不是本轮新增承诺。

Windows DSH接入

DSH负责理解任务和选择操作；WSL中的工具包负责建模、计算和保存结果。连接后，DSH自动获取工具及参数说明，不需要逐个录入函数。模型配置和密钥仍由DSH管理。

本机状态：DSH Desktop 2.0.17的desktop profile已加入MC插件，真实DSH进程连接后请求了55个工具定义。原有profile内容保留，模型设置未改。按用户决定，本轮模型请求为0、计算提交为0；自然语言完整任务尚未验证，不能计为宿主验收完成。

1．启动服务，连接DSH

在WSL工具包根目录按环境说明完成准备，然后运行：

./mcp/start.sh

默认同机地址为 http://127.0.0.1:8770/mcp。在Windows PowerShell检查：

Invoke-RestMethod http://127.0.0.1:8770/health
# 在工具包目录运行；只做MCP握手和发现，不调用模型：
.\scripts\check-mcp.ps1

健康检查和上述脚本证明网络、服务和标准协议；真实DSH仍需加载插件。桌面版常用profile位于 %USERPROFILE%\.dsh\profiles\desktop，先确认正在使用的profile，再备份其中的 cordis.patch.yml。

将DSH补丁示例的 - insert: 条目追加到现有 cordis.patch.yml；保留原内容，不把它当完整配置覆盖。serverName: mc须与其他服务不同。若编辑的是完整插件列表而非patch文件，使用普通插件条目，两种格式不要混用。

保存后由DSH的profile监听热加载；如果从WSL修改Windows文件未生效，在Windows编辑器保存该文件并复查连接。本机曾需要Windows原生保存才能触发监听，未因此更改模型或重启整个DSH。工具在DSH中注册为 mcp__mc__openmc_…；历史无前缀工具如 search_knowledge 则为 mcp__mc__search_knowledge。

服务启动输出会显示事件日志路径。真实宿主发现工具时会增加 tools.listed，包含工具名、数量及传输连接来源；结合实际宿主进程连接核对，不能把另一个检查客户端的记录当DSH记录。启动成功、工具发现、实际调用是三个检查层次。

远程部署改用实际服务器URL和已有HTTPS入口，按远程监听与鉴权设置Bearer。本机回环地址不需要令牌；不要把WSL文件路径当MCP地址，也不要为连通性检查放开所有网络。本机连接不代表异机部署已验证。

2．先理解一个任务：读全堆结果，生成图和报告

输入从哪里来：随包的 core-lattice 适配OpenMC官方 pwr_core()，生成公开简化全堆输入；额外明确加入8×8×1网格flux计分。此前通过标准MCP完成了真实计算，并核对原生StatePoint、图和报告。本机记录名为“DSH预备全堆用例”；这是已完成作业，不是这次DSH新算出的结果。换一个安装目录应先按操作指南准备自己的作业。

步骤与工具输入的来源做了什么，怎样看结果
找计算
openmc_list_jobs		任务名、completed状态；重名时由用户选择。从服务端持久记录取得job_id；后续始终使用同一ID。
看输入
openmc_job_status
openmc_preview_input		job_id对应的case_dir；提交快照和指纹在作业记录内。了解材料、几何、统计设置和计分。当前输入与提交快照要区分，不能只看文件名推断来源。
读数据
openmc_read_results		同一job_id下真实StatePoint文件。获取keff及tally类型、ID、均值和标准差；按实际返回选择flux计分，不猜ID。
画热图
openmc_plot_mesh		job_id、实际tally_id和score=flux；本例为二维单层。生成空间分布PNG及完整坐标/数值CSV、JSON。其他三维结果须选层，能量分箱须选箱。
出报告
openmc_export_report		同一job_id、tally_id、score及需要的筛选；选择markdown或已配置格式。正文、配套图与完整数据使用同一选择；默认摘要与显式选择报告不同。生成同格式会覆盖，留版本先归档。
找文件
openmc_list_artifacts		kind=job，identifier为同一job_id。返回服务端位置、文件清单、大小和哈希，便于查看及交接。

怎么看结论：热图表达各空间格子的原始flux计分分布，CSV/JSON用于核对全部格子及不确定度。它没有追加体积、源强或功率归一化，不能直接称实际功率或工况通量。此前1000粒子、12批、2非活跃批的运行是工程调试，小统计结果不证明收敛或专业精度。

工具的价值：模型仍能临时写脚本处理文件，但工具包预先固定了StatePoint读取、选择和坐标规则，将输入快照、作业ID、原始值、不确定度与产物关联起来；不同宿主可重复调用。模型负责选择与解释，工具不代替专业判据。

后续获准模型预算后，可在DSH发起：“查找已完成的‘DSH预备全堆用例’，先说明输入来源和运行设置，再读取其空间flux结果，沿用同一结果选择生成热图与Markdown报告，列出文件绝对位置。不要重新计算，不把结果解释成实际功率；缺参数先询问。”本轮未执行这段自然语言任务。

3．在哪里打开产物，怎样维护

所有产物保存在服务端工作区，不是DSH当前目录。默认布局为 workspace/.mc-jobs/<job_id>/；优先使用返回的 server_path。Windows同机可在资源管理器打开 \\wsl.localhost\Ubuntu\home\zhangbolun\projects\mc-tech-execution\workspace，再进入对应作业目录；发行版和安装位置不同请替换。异机按部署约定交接，当前不自动上传输入或下载产物。

./mc.sh call openmc_storage_report '{}'
./cleanup.sh --older-than-days 7
# 核对预览；在服务和CLI停止写入的维护窗口执行：
./cleanup.sh --older-than-days 7 --apply

7天只是命令示例，不是保留承诺；命中修复关联时会拒绝清理，不绕过保护。核数据库、运行时和必要证据保留。提交前磁盘门禁不代替运行期容量监测；WSL虚拟空间也不等于Windows宿主盘空间，可通过 disk_space_check_paths 检查实际宿主卷。

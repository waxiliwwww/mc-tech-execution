Windows上的DSH，连接WSL里的计算服务

OpenMC和MCP服务运行在WSL/Linux，Windows DSH通过HTTP发现并调用工具。DSH自己的模型配置保留，模型密钥不交给工具服务。

1．在WSL启动MCP服务

先按环境说明完成准备。在工具包根目录运行：

./mcp/start.sh

默认同机地址为 http://127.0.0.1:8770/mcp。远程部署使用实际服务器地址和部署方已有HTTPS入口，服务端按远程监听与鉴权配置；不要把WSL的文件路径当作MCP地址。

2．在Windows检查连通，再配置DSH

在PowerShell运行（替换实际端口/地址）：

Invoke-RestMethod http://127.0.0.1:8770/health

同机Windows到WSL的localhost转发是否可用，应在这台机器实测。健康检查只证明网络与进程可达；随后还需MCP发现。可以在Windows PowerShell运行随包的 scripts/check-mcp.ps1，它只完成协议握手和工具发现，不调用模型或提交计算。未通时检查WSL网络、监听、端口和防火墙，不先放开所有网络访问。

把 dsh-mcp.example.yml 中的插件条目加入DSH现有profile的插件列表。它不是完整DSH配置，不要覆盖现有模型和账号设置。本机已定位DSH Desktop 2.0.17，桌面profile位于 %USERPROFILE%\.dsh\profiles\desktop；随包已有MCP客户端插件。此处仅核对版本与入口，未修改用户配置。

默认同机URL可直接使用；其他地址在启动DSH的PowerShell中设置：

$env:MC_MCP_URL = "https://实际服务地址/mcp"
# 远程服务需要Bearer时设置，并取消示例中的headers注释：
$env:MCP_AUTH_TOKEN = "由部署管理员提供的令牌"

启动或重载DSH后，检查 mc 服务的连接状态与工具发现。工具将以 mcp__mc__openmc_… 等名称出现，不需要逐个抄写函数。本机未发现 dsh 命令，使用现有桌面入口即可。

3．用一个代表任务检查是否好用

建议使用已做过真实计算和数据核对的简化全堆空间通量：生成公开全堆输入 → 定义8×8×1通量计分 → 预览校核 → 命名提交 → 查看keff与64格分布 → 图和报告。小统计设置只用于调试，不代表专业精度。

“使用mc工具准备公开的简化全堆模型，定义空间通量统计。先给我看输入和运行设置，确认后提交名为‘全堆调试’的计算；结束后给出keff、通量分布图、报告和服务端文件位置。”

宿主应从实际模型发现参数、计分与ID，提交后继续查同一job_id；图表按实际计分处理，不能凭空转换成功率分布。初次也可先读取一份已完成任务的结果，验证发现与结果呈现，再安排重新计算。

4．产物在哪，怎样清理

输入和结果都在服务端工作区。同机Windows可用资源管理器进入 \\wsl.localhost\Ubuntu\home\zhangbolun\projects\mc-tech-execution\workspace（发行版/安装位置不同请替换），或使用工具返回的实际路径。异机按现场约定交接；当前不自动远程下载。

./mc.sh call openmc_storage_report '{}'
./cleanup.sh --older-than-days 7
# 核对预览，并在服务和CLI停止写入的维护窗口执行：
./cleanup.sh --older-than-days 7 --apply

7天是示例选择，不是自动保留策略。若年龄选择命中修复关联，清理会拒绝；先查存储报告，再按明确的非关联编号清理，不用允许断链开关绕过保护。清理脚本保护原算例及关联记录；核数据库、运行时和必要证据不列入日常删除。磁盘门禁只降低新任务继续占用的风险，不能代替运行中容量监测。WSL虚拟可用空间不等于Windows宿主盘剩余；本机Ubuntu在C盘，部署配置可用 disk_space_check_paths 加入 /mnt/c 同时检查，不把这个本机路径写进通用部署包。

验证边界：本机Windows已对隔离临时端口完成HTTP/MCP握手并发现工具，测试服务随后停止。标准MCP与真实OpenMC流程已有工程验证；DSH插件实际激活、自然语言完整任务尚未验证。按当前决定本轮不调用模型，不能据配置文件宣称DSH自然语言已通过，也不计为第二宿主验收。

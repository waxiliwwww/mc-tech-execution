MC工具包使用说明

本包帮助使用者把OpenMC模型接入、参数研究、计算执行和结果整理连成可复查的流程。你提供物理模型和判断依据，OpenMC求解；工具包保存每次提交的输入与设置，管理长计算，并把同一结果选择整理成数据、图和报告。可直接用CLI，也可通过标准MCP交给平台调用。

准备模型→预览与校核→命名提交、查询终态→选择结果、取用产物

本页帮助选择操作路线和理解结果；模块机制、执行后端和扩展位置见架构设计。

1．能帮助完成哪些工作

你的工作工具包提供的操作你仍需明确的内容
沿用已有模型导入原生XML及依赖，预览、校核并保存副本；已有建模程序可继续用。程序先导出OpenMC输入；核数据、外部文件和模型适用性要具备。
比较多组参数发现可调整项，创建参数副本并回显差异；命名提交、串行扫描、按作业比较输入与结果。研究参数的物理意义、允许范围，以及是否还要联动修改其他条件。
使用CAD几何检查STEP实体、换算长度并转换H5M；补齐材料、源与边界后交给OpenMC。CAD只提供几何；实体材料映射、源、计分与几何质量须有依据。
分析和交接结果选择计分、核素与过滤箱，保留均值和标准差；输出图、完整所选数据和同源报告。计分是否合适、统计是否充分，以及如何换算为目标工况或作专业比较。

这些操作把常用的文件组织和交接规则固定下来：修改有副本，计算有编号，失败有记录，图和报告能追到原始统计。原生XML、HDF5及CSV仍可用OpenMC或自己的程序继续处理。建模可表达范围、自动改参范围和结果接口范围分别明确，不把接口封装等同于OpenMC全部API。

2．怎样开始，以及怎样带入自己的模型

先按部署说明准备Linux/WSL环境。在完整源码包根目录运行 ./quickstart.sh；已有基础环境只补CAD可用 --cad-only。按自己的任务选入口：已有模型按下方步骤导入；初次体验OpenMC按公开例题的完整计算步骤操作；需要CAD再运行 mcp/.venv/bin/python examples/cad_case_demo.py，核对STEP到数据、图与报告的交接。CAD示例的固定输入、物理设置和选项含义见示例说明，不把示例条件套到自己的工程几何。

已有模型时，把自己程序导出的XML及本地依赖放入 workspace/incoming/model/，再按下面的目录创建独立工作副本：

./mc.sh call openmc_import_model '{"source_dir":"incoming/model","target_dir":"cases/model"}'
./mc.sh call openmc_preview_input '{"case_dir":"cases/model"}'
./mc.sh call openmc_validate_inputs '{"case_dir":"cases/model","api_check":true}'
./mc.sh call openmc_submit_job '{"case_dir":"cases/model","name":"模型研究","threads":1}'

公开官方例题也可作为学习和运行检查的起点，目录与分步骤操作见官方例题说明；专业基准对比仍需适用模型、参考结果和比较判据。接下来的状态查询和结果读取使用返回的真实 job_id。若要改参，先发现参数并创建新副本；若要空间/能量分布，提交前先定义对应tally。完整参数示例、失败时怎样继续及实际命令见模型操作指南与一次完整计算。

通过MCP使用时启动 ./mcp/start.sh，把服务地址和需要的鉴权交给宿主；宿主通过工具发现取得同一套参数说明，无须逐个配置函数。CLI与MCP共享业务实现。宿主的自然语言理解、工具选择和图像展示能力需要单独验证，配置连接不等于已完成任意自然语言任务。连接方式见标准MCP说明和Windows DSH接入。

日常先用存储报告查看占用，清理只在预览后执行并保留需要复查的记录。输入快照能固定模型文件，跨环境复现仍要一起记录引擎、核数据、随机种子、运行设置和线程条件；不承诺仅靠同一文件名就得到相同数值。

3．选择哪一份结果，图中的数怎样解释

OpenMC产生数值，工具提取和组织数值。先读结果清单，再明确 tally_id（哪项统计）、score（通量/反应率等量）、nuclide（总量或核素）和 filter_selection（哪些分箱）。多个候选时应显式选择，避免默认首项与你的问题不同。固定源计算通常没有keff，不能把空值当故障或零。

结果层次拿来做什么完整性与限制
接口预览快速看keff、计分、形状及部分均值/标准差。受max_values等限制，返回截断标记；默认作业汇总CSV也可能来自预览，不能一概当全量。
完整所选数据明确选择后得到配套CSV/JSON，继续用Python、表格或专业程序分析。通用所选曲线、数据和所选报告同源；正文最多预览20点，所选数据文件保留全部所选点。绘图点数超限须缩小选择，不静默截断。
原始StatePoint保留更深入分析所需的求解输出，用官方API重新读取。不等同于轻量预览或一张图；大计分仍需评估读取内存。

横轴决定图能说明什么。单能量过滤图用eV区间的算术中点，保留上下界；计分仍是bin积分量，没有自动除以能宽。多过滤器通用图使用展平分箱序号，不是空间距离。空间关系应看规则网格热图；多层三维网格选层、带能量过滤选箱，不能不说明条件就投影。

统计误差和归一化须一起看。std_dev是OpenMC对均值统计不确定度的估计（标准误），不是空间各格分布的离散程度，也不自动等于95%置信区间；非有限值保留为空并提示，不补零。图表没有自动追加功率、实际源强或体积归一化。k逐批图可辅助观察统计过程，不能单凭曲线平缓宣布收敛。

例如公开全堆模型加8×8×1网格flux计分，得到64格均值与误差：热图回答“所选计分在空间上怎样分布”，完整数据用于复核与后续归一化，报告说明输入与选择。它不能在没有功率和归一化条件时直接称为实际功率分布。CAD示例也遵循同一结果处理链，详见16格示例结果说明。

4．文件分别做什么，本包处理到哪一步

准备计算时的输入

文件科学用途本包的处理
model.xml；或geometry/materials/settings/tallies.xml几何、材料、运行设置与计分定义。导入、预览、受支持改参及分层校核；生成模型经官方Python API导出。
model-spec.json / build_model.py结构化建模依据及独立重建。组合建模时保留；不表示全部OpenMC属性都能由spec表达。
.step / .stp → dagmc.h5mCAD实体及其DAGMC网格几何。检查实体、按明确缩放/标签转换并读回；H5M是MOAB/HDF5几何输入。
cross_sections.xml + 核数据.h5核素、温度等相互作用数据索引与实际数据。初始化或指定库，检查相应索引并注入运行；复制索引不等于数据库已搬移。
燃耗链XML + 燃耗配置衰变/反应链、功率与时间步。供受支持燃耗作业使用；材料体积和实际链文件仍需准备。

OpenMC原始输出

文件用来查看什么直接分析、保留还是外部处理
statepoint.N.h5keff、tally均值/标准差、维度与过滤条件。通用结果读取的主要依据，使用官方StatePoint API；入口是本包成功作业，不是任意HDF5文件。
summary.h5 / source.h5等几何材料辅助快照、源分布；源库也可能是模型输入。若产生则可保留/列清单；可核对声明依赖，但没有独立通用Summary/源库分析工具。
tallies.out人可读的计分文本。若产生则保留供查看；通用结果提取选用StatePoint，不以ASCII文本解析为主。
solver.log / worker.log运行过程、进度与错误。用于状态和有限诊断；日志尾部不是最终统计结果，截断会标注。
几何PNG / PPM等检查输入模型外形或切片。绘图作业与切片入口；不是通量分布，也不证明无重叠或物理正确。切片与自动边界推断有适用范围。
depletion_results.h5时间序列的燃耗计算结果。读取时间、keff及U235/U238/Pu239/Pu241等当前支持项；不是通用解析全部HDF5结构。

用于分析和交接的整理产物

格式适合什么用途打开或继续使用时注意
PNG / SVG看结果曲线、误差或空间热图；SVG便于矢量排版。留意坐标、计分选择和归一化说明。几何图与计算结果图要区分。
CSV / JSON二次数值分析与自动处理。显式选择后的完整数据包含所选值、误差与坐标/来源；默认汇总可能截断。
Markdown / DOCX / PDF / DOC阅读、编辑、交流报告。所选报告沿用通用曲线的同一数据，网格热图是独立产物；MD图片用同目录相对链接，DOCX嵌图，PDF/DOC需Office转换。正文预览不替代完整数据。
job.json / runtime.json / mc-case.json回查名称、状态、输入、配置和来源。这是工具包管理记录，不能当物理结果；同一job_id把它们与求解文件关联。

文件存于服务端，默认记录目录为 workspace/.mc-jobs/<job_id>/，其中 work/保存提交副本和原始输出。以工具返回的 server_path为准；MCP返回数据或路径不等于已下载到客户端。部分PNG可随调用预览，网格热图主要返回文件位置，能否内联显示还取决于宿主。异机文件取回目前需另行安排；同机Windows可经WSL共享路径打开，见产物与清理。

5．运行范围与依赖

接口由MCP服务与CLI共用注册表和Schema校验；OpenMC 0.16.0的Python API用于建模、解析和读原始结果，可执行程序用于求解。CAD分支额外使用CadQuery、cad_to_dagmc和网格组件；Matplotlib绘图，DOCX生成与Office转换负责报告输出。核数据独立于软件安装。这些组件在初始化时准备，不要求科研用户把它们都装到同一个Python环境。

当前执行器面向本地Linux/WSL进程，尚无Slurm/HPC适配；组合建模和自动改参只覆盖已公布范围，CAD复杂件与统计/物理适用性仍需实际模型验证。官方原文检索不是完整专业知识库，宿主编排也不等同于微调模型生成。使用这些范围判断适合接入的任务，具体条件见对应操作页。

详细命令与参数见计算步骤、自有模型、标准MCP；模块实现见架构设计。

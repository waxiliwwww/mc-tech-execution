这个工具包做什么

把输入参数转成 OpenMC 输入，提交计算，取回结果。材料、几何、源和计分由使用者提供；工具不推断富集度、材料成分或堆芯设计。

下文用四个术语：case_dir 是模型目录，job_id 是一次计算，tally 是计分，instance 是官方例题实例。

已有 OpenMC 经验，可以直接用下面的命令；字段和限制见第4节。

命令链（展开） 
# 导入已有 XML
./mc.sh call openmc_import_model '{"source_dir":"inbox/my-model","target_dir":"cases/my-model"}'

# 用 model-spec 建好并跑完
mcp/.venv/bin/python examples/model_workflow.py --spec my-spec.json --case-dir cases/my-model

# 分步执行
./mc.sh call openmc_preview_input '{"case_dir":"cases/my-model"}'
./mc.sh call openmc_validate_inputs '{"case_dir":"cases/my-model","api_check":true,"semantic_check":true}'
./mc.sh call openmc_submit_job '{"case_dir":"cases/my-model","name":"trial","threads":1}'
./mc.sh call openmc_job_status '{"job_id":"JOB_ID"}'
./mc.sh call openmc_read_results '{"job_id":"JOB_ID"}'
./mc.sh call openmc_export_report '{"job_id":"JOB_ID"}'

长度用 cm，能量用 eV，温度用 K。ID 由调用方指定，引用必须存在。面支持 x/y/z 平面、x/y/z 圆柱和球；格架只支持二维矩形。六角栅格、CAD 和任意 Python 不能写进 model-spec。计分不定义就没有结果。

1．使用前准备

计算运行在Linux服务器或WSL。先由管理员按部署说明准备环境；通过DSH使用时，先完成连接与工具发现。以下工具均以服务器工作区为文件基准，客户端文件不会自动上传。尚未启动服务时，先到启动标准MCP服务；工具已列出但调用失败，直接按Windows连接诊断检查，不以工具列表代替在线状态。

先确认所连接服务的版本：将本包VERSION与服务实际运行版本对照，不一致先按部署说明更新/重启正确实例，核对后再计算。方法见运行版本核对。MCP调用openmc_environment读取service.version，它是当前服务启动版本，与/health和握手同源；version_matches只针对OpenMC。缺少service字段表示未取得这项证明，先核对部署版本；Windows也可按部署页直接查询/health，无须一概交管理员。CLI直接调用不代表某个在线MCP服务，不返回service字段。

先调用openmc_environment，确认api_available、executable_available、version_matches为true，并记住workspace。cross_sections_configured和cross_sections_env_set只检查环境变量；false不单独阻断，也不能单独放行。连续能模型先核对nuclear_data.source/index_path/index_exists候选索引，再在2.2核对模型核素/S(a,b)与索引的语义匹配。该静态检查不证明索引引用的HDF5文件存在、可读或内容正确；数据文件完整性由部署者按生效索引另行核对，无法确认就记未验证，不把index_exists=true或complete=true当全库齐备。模型显式索引可覆盖部署候选，合成多群模型则使用其自带数据。详见核数据选择。通过DSH时另按参数定义刷新步骤检查当前会话。本文默认一次一个任务、1线程；目录、材料、几何、源和计分分别决定“在哪算、算什么、统计什么”。

复现状态：已有第三方按本手册完成组件、全堆及同作业内的数据核对，记录见工程复现记录。这不预填你在新机器、新部署上的结果；仍须保存自己的输入、编号和核对记录。1000粒子/12批/2非活跃批是工程练习设置，专业计算需另行确定采样与收敛条件。

查其他官方例题时推荐openmc_list_official_examples传group="api"、limit=10、summary=true；按返回next_offset继续，详情用openmc_get_official_example。count是筛选总数，returned_count是本页条数，不能将分页首屏当成全部例题。

2．用官方17×17组件完成一次计算

已有 OpenMC 经验：create_model → define_tally → preview_input → validate_inputs → submit_job → job_status → read_results → export_report。第一次使用按 2.1–2.4 做。

本例使用 OpenMC 内置的 openmc.examples.pwr_assembly()，几何和材料来自官方组件。输入由工具适配生成，增加规则网格 flux 计分，并覆盖采样设置。这是公开示例，不是甲方组件；输入经过适配，不是未修改的官方完整统计计算。

四个参数：case_dir 是服务器工作区里的新模型目录；particles=1000 是每代粒子数；batches=12 是总批数；inactive=2 是前两批不计入统计。这里只有10个活跃批，用于练习接口；正式计算要另定采样和收敛条件。

2.1 新建输入，追加明确要计算的量

先给本次计算取一个唯一标识，例如日期时间加 4 位随机字符，作为 RUN_TAG。下文出现的 RUN_TAG 都要替换成这个字符串；工具不会自动替换。组件和全堆各用新目录，后续步骤沿用返回的 case_dir。目录重名就换标识，不要删除或复用旧目录。

创建模型 openmc_create_model

{
  "case_dir": "reproduction/assembly-RUN_TAG",
  "template": "assembly-17x17",
  "particles": 1000,
  "batches": 12,
  "inactive": 2
}

目录已存在就停下，保留旧输入，换一个新的后缀。成功后记录返回的 case_dir。模型由包内官方工厂适配生成，不是 DSH 现场编写的物理算法。

定义计分 openmc_define_tally

{
  "case_dir": "reproduction/assembly-RUN_TAG",
  "name": "assembly central slice flux",
  "scores": ["flux"],
  "filters": [
    {
      "type": "mesh",
      "dimension": [17, 17, 1],
      "lower_left": [-10.71, -10.71, -1],
      "upper_right": [10.71, 10.71, 1]
    }
  ]
}

tally是希望OpenMC统计的量，本例统计中间2cm厚区域内的flux；x/y覆盖21.42cm组件宽度，分为17×17格。每格是空间统计箱，不承诺等于一个独立燃料棒或组件功率。记录本次返回的tally_id为T，下文T必须替换成实际整数，不能猜1或17。未定义计分就不会自动出现相应结果。

2.2 看输入，分别核对各层校验

预览输入 openmc_preview_input

{
  "case_dir": "reproduction/assembly-RUN_TAG"
}

先看summary中的采样设置、材料/几何摘要和tally计分，再用files核对文件清单、指纹及可返回的文本正文；确认problems为空、manifest_complete=true。清单包含普通提交会复制的全部算例文件：XML、mc-case.json及相对资源；大文件与H5M/HDF5等只返回大小和SHA256，不展开二进制。既有PNG/StatePoint等输出按普通提交规则排除，部署在算例外的核数据库不在此清单。文本内容可能截断，保留完整input_hashes供提交快照核对；清单完整不表示物理校核通过。

校核输入 openmc_validate_inputs

{
  "case_dir": "reproduction/assembly-RUN_TAG",
  "api_check": true,
  "semantic_check": true
}

继续条件同时满足：structure_valid=true、openmc_api.api_parsed=true、semantic.checked/ok/complete均为true。complete=false不算已全部校验，通过skipped_reason查未执行的原因；报错则停止，不跳过错误提交。此处API读回/静态校验不做真实几何抽样，也不替代专业判断。

2.3 命名提交，按返回编号查到终态

提交计算 openmc_submit_job

{
  "case_dir": "reproduction/assembly-RUN_TAG",
  "name": "组件公开模型试用-001",
  "threads": 1
}

将返回的job_id记录为J，通常是32位字符串。下面JSON中的"J"只表示这次真实编号，执行前替换；T也是实际整数。不要复制示例占位符直接执行。

查询状态 openmc_job_status

{
  "job_id": "J"
}

queued/running时隔几秒再查原编号；completed后才能读结果。failed/cancelled/interrupted进入失败处理，不假装完成。将终态input_hashes与预览input_hashes作完整字典比较（文件名集合与每项SHA256都相等，也可从files提取指纹）；有新增、遗漏或不同就停止把结果归属于先前确认输入。查看几何不应改变原输入；仍逐项核对所有输入哈希，不排除plots.xml。若使用过旧版查看工具且已出现差异，先保留现场并对照原提交快照，不能用新文档把旧差异视为正常。

2.4 读取真实结果，再按实际tally生成产物

读取结果 openmc_read_results

{
  "job_id": "J",
  "max_values": 10000
}

在tallies数组找id=T且score含flux的计分，确认nuclides为total、values_truncated=false、mean和std_dev各289个数。查看keff及其std_dev；有null或warnings要保留并说明。不能为得到图而静默选择另一个tally。

空间热图 openmc_plot_mesh

{
  "job_id": "J",
  "tally_id": "T（替换为整数）",
  "score": "flux",
  "format": "png"
}

返回PNG路径及values_json/values_csv。横轴x/cm、纵轴y/cm，颜色是该网格的原始flux计分；本例只有一层，不需要level。不是实际功率，也没有追加体积或外部源强归一化。

网格热图支持在同一tally的多个score中选择：显式给score:"flux"或实际可用项。省略score时，仅单一score会自动选择；多个score会提示选择，不要求为此重算。核素优先取total，无total且只有一个核素时取该项；其他组合不隐式合并。带能量过滤须指定energy_bin，三维网格须指定level；输出JSON标明实际score/nuclide和网格坐标。

完整所选曲线 openmc_plot_results

{
  "job_id": "J",
  "tally_id": "T（替换为整数）",
  "score": "flux",
  "nuclide": "total",
  "filter_selection": [],
  "format": "png"
}

此曲线横轴是明确标注的展平网格分箱索引，用于逐点核对，不是能量轴或空间长度。空间关系看前一张热图。

所选结果报告 openmc_export_report

{
  "job_id": "J",
  "tally_id": "T（替换为整数）",
  "score": "flux",
  "nuclide": "total",
  "filter_selection": [],
  "format": "markdown"
}

保留selection_mode、selection、points、chart、series_json和series_csv；应为selected、同一T/flux/total/空筛选、289点。报告引用的是完整所选曲线，不会自动嵌入前一张网格热图；热图作为独立产物一起交付。Markdown无需Office；PDF等需另配转换环境。

列产物 openmc_list_artifacts

{
  "kind": "job",
  "identifier": "J"
}

记录directory和每个artifact.server_path，下一节按这些真实文件核对。不要用DSH当前目录猜测.mc-jobs的位置。matches_recorded_output为true表示当前SHA256与作业保存的输出指纹一致；false表示有记录且不一致，应保留现场、停止据此沿用原结果；null表示没有保存的基线可对照，不等于失败。派生图、报告和results.json通常为null，仍应保留当前sha256并按第5节核对数据及来源。指纹一致不代表物理正确。

4．换成自己的输入

模型来源有两种：已有 XML 就导入；没有 XML 就用 model-spec 写 JSON。已有模型只改密度、温度、面系数或源强时，用参数发现和副本，见4.5。下面给出路线、JSON 格式和 3×2 组件的完整流程。

4.1 选路线

已有 OpenMC XML，用 openmc_import_model 导入。没有 XML，用 openmc_build_model 写 model-spec。已有模型只改密度、温度、面系数或源强，用 openmc_list_parameters 发现可改项，再用 openmc_prepare_case 建副本。固定模板和 CAD 各有单独入口。

4.2 model-spec 的写法

model-spec 是一个 JSON，描述材料、面、栅元、运行设置和计分。工具检查字段并导出 XML。长度用 cm，能量用 eV，温度用 K。下面是一个可运行的球模型：半径 8 cm，300 粒子、20 批、5 个非活跃批，统计通量。

{
  "name": "u235-sphere",
  "materials": [
    {"id": 1, "name": "HEU", "density": 18.7, "density_unit": "g/cm3",
     "percent_type": "ao", "nuclides": [{"name": "U235", "fraction": 1}]}
  ],
  "surfaces": [
    {"id": 1, "type": "sphere", "boundary": "vacuum", "parameters": {"r": 8}}
  ],
  "cells": [
    {"id": 1, "universe": 0,
     "region": {"op": "halfspace", "surface": 1, "side": "negative"},
     "fill": {"type": "material", "id": 1}}
  ],
  "root_universe": 0,
  "settings": {"run_mode": "eigenvalue", "particles": 300, "batches": 20,
               "inactive": 5, "source": {"type": "point", "point": [0, 0, 0]}},
  "tallies": [{"id": 1, "scores": ["flux"]}]
}

字段含义：

  • materials：材料编号、密度、核素和份额。UO₂ 的氧份额和 U235 富集度要自己写，工具不推断。
  • surfaces：面。支持 x/y/z 平面、x/y/z 圆柱和球；region 是类型化布尔树：{"op":"halfspace","surface":1,"side":"negative"} 表示 1 号面内部；并、交、补分别用 union、intersection、complement。
  • cells：用面围出区域，fill 指定材料、宇宙、格架或真空。
  • settings：粒子数、批数、非活跃批数和源。本征值模式至少两个活跃批。
  • tallies：统计量。不写 tallies 就没有结果。

编号由调用方指定，引用必须存在。未知字段会被拒绝。只被根宇宙直接栅元使用一次的外边界面必须显式设 vacuum/reflective/white，不能留空或设 transmission；专家确需透射边界时，在 validation.overrides 写带 reason 和 scope 的 outer_boundary_transmission 覆盖，报告会保留该 tag。没有 OpenMC 时，可在算例目录运行 python3 build_model.py --validate，只校验 model-spec.json，不生成 XML；默认 --backend auto 优先 Pydantic，缺失时自动使用标准库 fallback。能力发现的 validation_backend 是 MCP 服务端输入校验后端；构建结果另报 builder_validation_backend，表示 OpenMC 运行时实际使用的后端，两者可能不同，按字段分别追溯，不混为一个。

5．读取结果与交付文件

OpenMC产生数值，工具提取和组织数值。先读结果清单，再明确 tally_id（哪项统计）、score（通量/反应率等量）、nuclide（总量或核素）和 filter_selection（哪些分箱）。多个候选时应显式选择，避免默认首项与你的问题不同。固定源计算通常没有keff，不能把空值当故障或零。

结果层次拿来做什么完整性与限制
接口预览快速看keff、计分、形状及部分均值/标准差。受max_values等限制，返回截断标记；默认作业汇总CSV也可能来自预览，不能一概当全量。
完整所选数据明确选择后得到配套CSV/JSON，继续用Python、表格或专业程序分析。通用所选曲线、数据和所选报告同源；正文最多预览20点，所选数据文件保留全部所选点。绘图点数超限须缩小选择，不静默截断。
原始StatePoint保留更深入分析所需的求解输出，用官方API重新读取。不等同于轻量预览或一张图；大计分仍需评估读取内存。

横轴决定图能说明什么。单能量过滤图用eV区间的算术中点，保留上下界；计分仍是bin积分量，没有自动除以能宽。多过滤器通用图使用展平分箱序号，不是空间距离。空间关系应看规则网格热图；多层三维网格选层、带能量过滤选箱，不能不说明条件就投影。

空间图的实际字段：openmc_plot_mesh返回的image是图片文件名，以server_path定位服务端图片；values_json/values_csv指向配套数值文件。热图JSON的x_edges/y_edges是所选切片的网格边界（cm），格心由相邻边界的平均值得到；values[j][i]对应CSV的(i,j)，仍按本节和下方核对步骤解释。文件路径不是下载URL，甲方自有服务器上的文件按现有交付方式取回。

统计误差和归一化须一起看。std_dev是OpenMC对均值统计不确定度的估计（标准误），不是空间各格分布的离散程度，也不自动等于95%置信区间；非有限值保留为空并提示，不补零。图表没有自动追加功率、实际源强或体积归一化。k逐批图可辅助观察统计过程，不能单凭曲线平缓宣布收敛。进度中的entropy_latest=null只表示未取得可用的该项观测，不能据此判失败或已收敛。这两条低统计练习只核对工程流程；专业计算的源收敛、有效统计量及误差要求须由使用者明确，本手册不把某个粒子数或批次数作为通用充分条件。

低统计下，网格的均值可能恰为0。热图对这些格子加×并返回zero_bins和提示；它们仍保留0，非有限缺失值仍为空。单凭0不能断言物理量严格为0，也不能确认没有径迹贡献；需结合计分定义、区域和采样判断。x标记不改变归一化或置信度。

statepoint.N.h5keff、tally均值/标准差、维度与过滤条件。通用结果读取的主要依据，使用官方StatePoint API；入口是本包成功作业，不是任意HDF5文件。
summary.h5 / source.h5等几何材料辅助快照、源分布；源库也可能是模型输入。若产生则可保留/列清单；可核对声明依赖，但没有独立通用Summary/源库分析工具。
tallies.out人可读的计分文本。若产生则保留供查看；通用结果提取选用StatePoint，不以ASCII文本解析为主。
solver.log / worker.log运行过程、进度与错误。用于状态和有限诊断；日志尾部不是最终统计结果，截断会标注。
几何PNG / PPM等检查输入模型外形或切片。绘图作业与切片入口；不是通量分布，也不证明无重叠或物理正确。切片与自动边界推断有适用范围。
depletion_results.h5时间序列的燃耗计算结果。读取时间、keff及U235/U238/Pu239/Pu241等当前支持项；不是通用解析全部HDF5结构。

用于分析和交接的整理产物

格式适合什么用途打开或继续使用时注意
PNG / SVG看结果曲线、误差或空间热图；SVG便于矢量排版。留意坐标、计分选择和归一化说明。几何图与计算结果图要区分。
CSV / JSON二次数值分析与自动处理。显式选择后的完整数据包含所选值、误差与坐标/来源；默认汇总可能截断。
Markdown / DOCX / PDF / DOC阅读、编辑、交流报告。所选报告沿用通用曲线的同一数据，网格热图是独立产物；MD图片用同目录相对链接，DOCX嵌图，PDF/DOC需Office转换。正文预览不替代完整数据。
job.json / runtime.json / mc-case.json回查名称、状态、输入、配置和来源。这是工具包管理记录，不能当物理结果；同一job_id把它们与求解文件关联。

文件存于服务端，默认记录目录为 workspace/.mc-jobs/<job_id>/，其中 work/保存提交副本和原始输出。以工具返回的 server_path为准；MCP返回数据或路径不等于已下载到客户端。部分PNG可随调用预览，网格热图主要返回文件位置，能否内联显示还取决于宿主。异机文件取回目前需另行安排；同机Windows可经WSL共享路径打开，见文件取回方式。

新增计分后，filters用简短说明及parameters列出实际网格编号、维度、边界或能量/粒子分箱；长能量列表仅预览前20个边界并标记截断，完整定义以输入文件为准。

核对输入、原生数据、图表与报告是否一致

离线输入指纹：预览返回的input_hashes、作业目录job.json中的input_files、状态返回的input_hashes都是“相对文件名 → SHA256”的映射，字段名不同；状态返回的input_files才只是文件名列表。保留提交前预览，将其完整映射与job.json的input_files双向比较，不能只检查XML或拿状态文件名列表当摘要。job.json不保存预览本身；未保留预览就不能补证提交前后相同。work/保存副本，后续绘图/几何检查/燃耗可能按模式调整文件，提交时指纹以job.json记录为准。

  1. 归属：记录J/T、输入SHA256、版本、采样与种子；所有结果必须来自同一J。read_results的keff与statepoint一致，缺不确定度不能补0。
  2. 图与数：热图配套JSON的dimension应为[17,17,1]或[8,8,1]，values/errors分别为17×17或8×8；CSV中(i,j)对应JSON的values[j][i]与errors[j][i]。x/y中心由边界等距计算：组件首格中心(-10.08,-10.08)cm、全堆(-175,-175)cm。
  3. 原生计分：本例单一mesh、flux、total，原生展平索引为i+nx*j；将StatePoint该tally均值/标准差与热图每格核对。完整曲线JSON的mean/std_dev应按该顺序一致；通用曲线plot-*.csv由浮点值直接写出，保留Python浮点序列化精度；热图mesh-*.csv的value/std_dev及所选报告计分预览表使用9位有效数字，其他字段（如Markdown全局keff）按实际格式输出。比较热图CSV或计分预览表时按相同显示精度对照，完整数值以配套JSON/StatePoint为准；不要求浮点文本格式完全相同，不把显示舍入当物理准确率容差。
  4. 报告：打开report.md，检查版本、采样、选择说明与正文引用的plot-*.png/json/csv；报告预览最多20点，完整CSV仍289/64行。正文只与其实际展示的前20点核对；第1、最后1个点及中间点的完整数值，应打开该报告引用的series_csv/series_json核对，再与同一作业/tally/score/nuclide/过滤选择的原生结果比较。不要在20点正文中找第288点，也不能拿另一个tally替代。报告附带的曲线与此前显式生成的曲线文件名可能不同，数据选择和值应一致。
  5. 历史复现对照：完成本作业内的数据核对后，可按工程复现记录比较历史观测及运行条件。同seed不足以保证跨机器、引擎构建、核数据或线程配置逐位相同；条件不齐就标为不可直接比较。出现差异先定位条件与输入，不套用固定k值区间或自造精度容差。
  6. 科学结论：这轮只说明公开模型经过工具处理得到相互一致的计分和产物。图的空间差异是样例原始计分分布，不足以断言工程功率、收敛或专业精度。需更高统计、参考值、归一化和专家判据后才能作进一步结论。

推荐先打开网格PNG理解空间分布，再打开report.md看计算信息和所选曲线，最后用配套CSV/JSON核数。图表文件名是随机唯一名，以工具返回为准。

批量计算：从一份模型生成多组参数

先对组件目录调用openmc_list_parameters，再使用发现的 settings.particles，在原输入上建立 1000 和 2000 两组计算：

./mc.sh call openmc_submit_scan '{"case_dir":"reproduction/assembly-RUN_TAG","axes":{"settings.particles":[1000,2000]},"threads":1}'

它返回 scan_id，用 openmc_scan_status 查询；多轴取笛卡尔积，当前串行执行。图和报告保存到 .mc-scans/<scan_id>；失败项保留，曲线不以 0 替代缺失值。横轴、固定维度与报告参数见扫描绘图和扫描报告。

燃耗：先给材料体积，再配置时间步

燃耗比普通计算多两步：openmc_configure_depletion 写入功率（W）与时间步长，再用 openmc_submit_job 以 mode=deplete 提交。引擎要求可燃耗材料显式给出体积，否则提交时报 Volume not specified for depletable material；同一材料也不能混用原子分数与质量分数（报 Cannot mix atom and weight percents）。

./mc.sh call openmc_create_model '{"case_dir":"cases/burnup","template":"pincell-depletion"}'
./mc.sh call openmc_configure_depletion '{"case_dir":"cases/burnup","power_watts":100000.0,"timesteps":[0.05,0.05],"timestep_unit":"d"}'
./mc.sh call openmc_submit_job '{"case_dir":"cases/burnup","mode":"deplete","threads":4}'

完成后用 openmc_read_depletion 读取逐时间步的 k-eff、关键核素质量与初始重金属质量。燃耗值按"功率×时间/初始重金属质量"估算（MWd/kgHM），不是裂变能积分得来的实测值；核素只报少数关键项。

链文件（chain_casl_thermal.xml，约 1MB）不在 OpenMC 安装里，也不在核数据安装脚本范围内：由部署配置 depletion_chain 指定，未配置时在核数据目录下找同名文件。缺文件时提交会在链解析阶段失败，报错会给出期望路径。

诊断与确认修复：先看差异，再决定

openmc_diagnose_job 读取指定计算的日志，提供有证据的提示；受支持问题可在新副本生成修复计划。只有用户看过差异并明确确认后才应用，再校核或关联重算。

现成练习用 mcp/.venv/bin/python examples/repair_demo.py。它故意制造运行模式拼写错误，并保留第一次失败。当前自动修复仅限普通 run 中唯一的 run_mode 近似拼写；不自动修物理参数。CLI 需要交互终端确认，MCP 需要可信宿主逐次取得批准。

该修复练习使用合成单群截面，成功重算可出现k均值约1.66667、合并标准差为NaN的情况；这不是拼写修复失败的判据，也不代表专业物理结论。结合completed、原始日志和计分判断接口流程；无法安全解析的统计量保留为空并提示，不填0。不能仅凭这条日志确定NaN的物理原因。

看几何：切片图只画输入，不等于几何检查通过

openmc_view_geometry 按已有算例输入出 2D 切片图（xy/xz/yz），可给 origin/width（cm）与像素数，PNG 写在算例的 views/ 下。它只渲染输入几何，不做重叠判定；几何是否合法仍要用 openmc_validate_inputs 的 geometry_check 或几何调试作业确认。判读方法见几何重叠检查。

省略width时取所选切片平面的有限几何包围盒；省略origin时取平面包围盒中心，垂直于切片的坐标为0。例如组件xy视野约为21.42×21.42cm。显式width表示用户指定视野，一项为正方形、两项对应basis的两轴；响应返回实际origin/width及各自来源。无法自动确定有限范围时，请同时给出origin和width。

查看与输入隔离：工具在临时目录导出仅用于绘图的模型并调用OpenMC绘图模式，完成后删除临时文件；原算例的XML、内嵌plot定义和已有图片均不改写。仅新增views/中的PNG。查看失败也不应改动原输入。

某些六角棱柱或无界模型的包围盒无法由引擎自动确定；请按实际模型给出origin/width。切片图只表示该平面和视野内的输入几何，不能据图推断整个模型已通过几何检查。

几何重叠检查：怎样执行、继续或停止

仅需要此检查时，调用openmc_validate_inputs并给实际case_dir与geometry_check:true；它会在临时副本运行OpenMC几何调试、消耗计算资源，不是查看图片。本次检查按现有实现最多2批、inactive归零、单线程；实际设置差异见geometry.settings_adjusted，不改变原输入，也不能当作按原采样设置完成的正式计算。先完成结构校核，避免以其他输入错误代替几何判断。

看返回的geometry分支：checked=true、completed=true、ok=true、returncode=0且overlapping_cells=[]表示本次抽样完成、未发现重叠。它不能证明所有几何均无重叠，也不能替代专业判定。

checked=false看skipped_reason；completed=false或ok=null表示没有完成，不记通过；ok=false或非零退出看reason/log_tail，先定位再继续。overlap_check_summary.low_check有值时，cells是低于该摘要中min_checks阈值的栅元数量，属于抽样覆盖提示；为null表示未解析到该提示，不能直接当作0个低覆盖栅元。summary可能为空、cells明细最多200条，不能据部分明细声称全模型覆盖充分。

7．异常、继续与记录

需要主动练习失败分支时，直接进入诊断—预览差异—用户确认—关联重算练习，使用随包repair_demo.py。它在新目录制造一次预期失败，保留原失败；只有用户确认后才应用修复并重算。拒绝确认或未取得批准就停下，不在原业务算例上练习。

情况怎样处理怎样继续
连接/发现失败按Windows连接诊断（check-mcp.ps1）核对端点、隧道、profile和插件事件；服务未启动时转到启动入口。写请求结果未知时不重复提交。先使环境工具只读调用成功，再进入建模。

写操作响应未知：先核对当前状态，再决定是否继续

fetch failed、断网或客户端超时，只说明没拿到可靠响应。服务无日志、某文件不存在或一次前后哈希相同，都不能证明调用从未执行，也不能排除服务端稍后继续写入。先保存工具名、请求参数、时间段、错误、原case_dir/任务名/job_id以及调用前预览；无法确认结果时不要自动重试写操作。

  1. 先恢复查询：按部署说明检查服务、连接和只读环境调用；不要用Shell重新做一遍业务计算来绕过MCP错误。
  2. 建模/追加计分：重新preview同一case_dir，对照调用前的文件名集合与所有输入指纹。新增或改变的文件须看实际内容，校核结构/API/语义；清单完整不等于文件写入完整。有限预览不足以核对时请管理员查看完整服务端文件，不把截断文本当全量。
  3. 以define_tally为例：若新tally已落盘且内容与原请求一致，沿实际tally_id继续，不再次追加。若当前清单与调用前一致、未见新计分，只能记“当前未见变更”；先由管理员排除原请求仍在执行，再重新预览/校核并决定是否重试。发现部分写入或无法确认仍在执行时，保留现场并停止，不自行删除或覆盖。
  4. 提交计算：用openmc_list_jobs按原name查，再核对case_dir与提交时间；找到唯一对应记录后继续原job_id。多个匹配、不可读记录、没有明确匹配或无法排除提交仍在进行时，交给管理员确认，不直接重投。
  5. 图表/报告：保留原StatePoint，先查原作业是否已完成；生成产物失败不需要重新求解。再次读结果会刷新results.json，同格式重导可能覆盖原报告，复测前先归档需要保留的派生文件。

当前工具包没有通用写请求状态查询/幂等重放接口，不能仅靠缺日志或一次快照补出这一保证。证据不足时记“结果未知、待确认”，不是记“失败且肯定未执行”。

每轮填写：提交SHA、环境/核数据、J/T、采样、选择、是否截断/警告、产物目录、数据核对、DSH自动完成或人工补操作、首次失败和复测。分别记工程通过、未覆盖、发现问题、待专业判定，不预填结果。

结束后先用openmc_storage_report查看占用，按清理说明预览本次J的删除计划。只在维护窗口、资料归档后执行；原输入、核数据库、运行时和必要证据保留，不用一键全删腾空间。

清理本次练习产物

在计算服务器与相同PID命名空间执行。先将组件流程中返回的真实job_id赋给shell变量，再在包根目录预览。若服务使用自定义MC_WORKSPACE，另传--workspace并填环境工具返回的绝对路径，先核对预览打印的工作区：

mc_job_id='J（替换为本次真实job_id）'
./cleanup.sh --job-id "$mc_job_id"

需要删除时，先归档结果并确认计算结束；停止 MCP 和其它 CLI 写入，进入维护窗口，再对同一选择加 --apply：

./cleanup.sh --job-id "$mc_job_id" --apply
Windows PowerShell：调用同机WSL中的清理入口

只有服务运行在本机WSL时使用；先用wsl --list --quiet核对发行版名。下列变量分别填实际包根目录、环境工具返回的workspace和本次真实job_id；目录均为Linux绝对路径，不是Windows共享路径。

$mcDistro = 'Ubuntu'
$mcPackageLinux = '/实际的Linux工具包根目录'
$mcWorkspaceLinux = '/环境工具返回的workspace'
$mcJobId = '本次真实job_id'
wsl -d $mcDistro --cd $mcPackageLinux -- bash ./cleanup.sh --workspace $mcWorkspaceLinux --job-id $mcJobId

这是预览，不删除。只有归档、停写与维护窗口条件均满足后，对同一选择加--apply；检查退出码和返回的选择，不因失败自动重试。

wsl -d $mcDistro --cd $mcPackageLinux -- bash ./cleanup.sh --workspace $mcWorkspaceLinux --job-id $mcJobId --apply

远程Linux服务器应通过已有SSH登录后执行上面的Linux命令，不能用本机WSL清理远程服务器。两种方式都先确认预览显示的工作区和job_id正确。

它删除选定终态记录及其快照、日志、图和报告；原 cases/ / demos/ 输入保留。删除后不能再按编号查询。扫描按整批用 --scan-id；运行中、未确认中断、关联冲突等会拒绝。./cleanup.sh --help 可查保留时间和修复引用选项；默认不删，失败非 0，不应无条件重试。

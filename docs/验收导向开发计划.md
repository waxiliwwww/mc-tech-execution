# 验收导向开发计划

本项目开发独立的蒙卡接口工具包：依据公开接口封装需要的操作，提供直接调用、标准MCP服务、可运行示例、部署包和使用文档，供下游接入与甲方联调。专业计算复用OpenMC等已有程序；Harness是可选调用客户端。

本计划按2026-10-27确认的定位更新，替代此前仅围绕四项助手与等待业务脚本的安排。覆盖技术规格书表4-1的15项功能，但“覆盖计划”不表示当前全部实现。工程自测由开发方完成；指定业务和专业结果按甲方确认的测试计划验证，不把所有测试转给甲方，也不把专业模型设计默认为接口开发人员个人责任。

## 1. 开发依据与版本

- [OpenMC官方最新正式发布0.16.0](https://github.com/openmc-dev/openmc/releases/tag/v0.16.0)，查阅日期2026-10-27。本轮固定0.16.0；后续升级先查变更并重验相关接口，不在运行时自动追随latest。
- [Python API](https://docs.openmc.org/en/stable/pythonapi/index.html)、[基本能力索引](https://docs.openmc.org/en/stable/pythonapi/base.html)、[命令行](https://docs.openmc.org/en/stable/usersguide/commands.html)、[结果处理](https://docs.openmc.org/en/stable/usersguide/processing.html)。stable页面会随发行更新，部署与测试记录仍须保存实际版本。
- [官方示例](https://github.com/openmc-dev/openmc/wiki/Example-Jupyter-Notebooks)、[PWR pin-cell](https://docs.openmc.org/en/stable/pythonapi/generated/openmc.examples.pwr_pin_cell.html)、[XSdata](https://docs.openmc.org/en/stable/pythonapi/generated/openmc.XSdata.html)、[MGXSLibrary](https://docs.openmc.org/en/stable/pythonapi/generated/openmc.MGXSLibrary.html)。可自行取得公开开发样例，不以私有业务脚本到位作为全部开发的前提。
- 甲方提供的技术规格书及《OpenMC_MCP_表4-1技术落点对照与开发指引》是项目功能与验收依据。原始合同资料保留在本机references，默认不提交Git、不混入源码分发包；公开接口文档不能替代原规格要求。
- OpenMC 0.16.0的Python API要求Python≥3.12；MCP协议层的运行要求按其依赖清单。求解器、API、核数据分别探测，安装Python包不表示已有计算可执行程序。

## 3. 本轮先交什么

首批接口：openmc_environment、openmc_create_model、openmc_validate_inputs、openmc_submit_job、openmc_job_status、openmc_cancel_job、openmc_read_results、openmc_export_report。直接CLI和MCP使用同一实现；保留原7项辅助接口，保持MCP与Harness独立。

完整使用顺序：配置运行时→生成示例或放入已有算例→检查输入→提交返回作业编号→查询到终态→读取真实产物→导出报告。提交与完成分开，失败、取消及缺失产物有可见说明。长计算不套用当前30秒、stdout必须JSON的通用程序适配器。

合成截面可通过XSdata/MGXSLibrary生成，供真实求解器测试接口流程；其作业、结果和报告均标synthetic_mgxs。模拟可执行程序只用于进程/异常测试，标mock_process_fixture。两者均不代表真实核数据计算或专业验收。没有依赖时明确失败，不自动退到模拟结果。

## 5. 原验收边界

调用成功率≥95%、调用结果准确率≥95%、规定17×17=289场景下物理结果准确率≥90%分别验证。样本、分母、重试、专业公式、容差、模型/核数据版本和故障判据按确认计划固定。至少两个独立MCP宿主、原多模型和本地模型要求、主备切换与72小时稳定性均保留；不以本机CLI+Harness算两个宿主。

模拟数据、自测通过或安装成功不替代原指标。功能符合率100%、性能指标达标率100%、文档完整性100%及原交付保障不变，不新增响应时间、并发或任意模型/任意恢复承诺。

## 6. 需甲方配合的最小清单

1. 指定业务场景、模型/参数范围和适配对象；可先提供一个有正确输入输出的代表算例。
2. 正式目标计算/测试环境、核数据库版本及访问方式，涉及HPC时提供集群接口和权限。
3. 指定基准、参考结果、专业容差和审定人员，明确资料使用权限。
4. 确认正式测试计划、宿主/模型组合与验收口径，参与联调和见证测试。

专业模板、微调模型及训练条件等未在原规格明确归属的成果需项目内落实提供者，不能一律转给甲方。能用公开资料和模拟条件完成的工程开发继续推进。

## 8. 扫描、图表与报告迭代

本次目标是无甲方私有材料也能执行的工具工程功能：参数发现→新输入/组合→真实本地计算→汇总→图表→报告。复用本地作业，不新增通用调度平台。工具包首次环境配置后独立运行，CLI/MCP使用同一实现；各宿主按标准协议连接，模型及账号由宿主自己配置。

本轮按确认决定仅保存服务端产物、返回清单和位置，不提供远程下载。Quick Start准备求解器/API、图表及文档依赖；源码包不嵌入环境和真实核数据库。参数范围按当前模型发现的适配列表，不能宣称任意OpenMC模型/参数已适配。产物包含来源和失败/缺失项；合成数据不能替代专业验收。

本轮记录：artifacts/runs/20261027-scan-report；真实用例覆盖独立输入/单位、组合预检、取消、失败与中断、不重复提交、计分选择、报告实际格式/内容和MCP图像。原型首次失败（模型重导出丢宏观截面、Office启动/转换）与修复记录保留。最终数量及提交以当次测试日志和Git为准。

后续依然需要：CAD转换公开链、HPC实际接口、原微调模型生成、专业输入/诊断规则、资料与CLEAR-S接入；指定业务/核数据/参考判据到位后逐项联调，最后按原合同计划做兼容性、多模型及72小时等正式验证。本轮工程完成不代表全15项或原指标已验收。

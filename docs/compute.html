主操作流程

用同一个算例，完成一次计算

本页用随包公开例题走到可打开的图和报告。你会看到输入文件、修改后的副本和计算记录各在哪里；之后换成自己的输入，操作顺序相同。

环境准备输入发现与修改校核与计算读取与产物清理

以下命令在同一个 Bash 终端、工具包根目录依次执行。工具调用格式是 ./mc.sh call 工具名 'JSON参数'；返回 JSON 方便脚本继续使用。无需启动服务或配置大模型。

01 / 环境
安装在哪台机器，就在哪里运行工具

计算服务器使用 Linux/WSL。先具备 Python 3.10+ 与 venv、Bash、curl、tar/bzip2 和包源网络；默认 Office 准备还需 apt-get/dpkg-deb。Windows 可在 WSL 运行，或连接另一台服务器的 MCP。

./quickstart.sh

脚本准备 mcp/.venv（调用层）、.runtime/openmc（OpenMC 0.16.0 / Python 3.12）和图表/报告依赖，写入本机配置 config/openmc.local.json；不修改 shell 配置或安装系统包。首次需下载，部署包不包含正式核数据。

已有 OpenMC、只需部分报告、或者想改数据位置 
./quickstart.sh --openmc-prefix /opt/openmc-env --skip-office

将路径换成已安装且有 bin/python、bin/openmc 的环境。--skip-office 跳过 PDF/DOC 转换准备；本页 Markdown 和 PNG 不需要它。

配置选择与生效
工作区CLI --workspace > MC_WORKSPACE > 包根目录 workspace/。本页不改根目录；如已设置环境变量，以探测结果为准。
OpenMC 运行配置CLI --config > MC_OPENMC_CONFIG > config/openmc.local.json > config/openmc.json。其中命令数组、超时等由部署者设置。计算记录保存当次配置。
MCP 监听和鉴权见部署配置，修改后重启服务；直接 CLI 不需要这一层。

若更换工作区，请在新 Bash 会话开始时导出绝对路径 MC_WORKSPACE，后续每一步用同一配置。不要把客户端本地目录当成远程服务端路径。

./mc.sh call openmc_environment

继续前看四项：api_available、executable_available、version_matches 应为 true；记住 workspace 的绝对路径。本例自带多群数据，cross_sections_configured=false 本身不妨碍它运行；自己的连续能模型需要适用核数据。

02 / 输入
先看得到输入，再谈修改

本例 openmc-pincell-mg 来自随包的 OpenMC 官方多群燃料棒代码，内含公开 C5G7 数据。下面先建立 cases/tutorial，明确使用 200 / 10 / 2 的练习设置。生成输入还没有开始计算。

./mc.sh call openmc_prepare_example '{
  "case_id":"openmc-pincell-mg", "case_dir":"cases/tutorial",
  "particles":200, "batches":10, "inactive":2
}'
mc_workspace=$(./mc.sh call openmc_environment | python3 -c 'import json,sys; print(json.load(sys.stdin)["workspace"])')
ls "$mc_workspace/cases/tutorial"

你会看到 geometry.xml（几何）、materials.xml（材料与截面引用）、settings.xml（运行设置）、tallies.xml（统计什么量）、mgxs.h5（本例多群截面数据），以及绘图和来源文件。用文本编辑器打开 XML；本例的 settings.xml 应含以下设置：

<particles>200</particles>
<batches>10</batches>
<inactive>2</inactive>

case_dir 相对刚才查到的 workspace，与终端当前目录无关。本例的真实输入位置就是 $mc_workspace/cases/tutorial。目标已存在时换一个新目录名，并在后续命令同步替换；工具不会覆盖。

03 / 修改
知道能改什么，再创建新副本

./mc.sh call openmc_list_parameters '{"case_dir":"cases/tutorial"}'

返回的 parameters 是当前输入中已适配为可修改的字段。每项有 name、current、类型、单位和范围。例如：

{"name":"settings.particles", "type":"integer", "minimum":1,
 "current":200, "unit":"particles/generation"}

这次为何改成 400？练习只改一个统计设置，并确认原输入保留、新输入生效。particles 是每代模拟粒子数；400 让“200 → 400”的变化容易核对，不是业务推荐值。相同代数下采样量增加；耗时、keff 和标准差是否变化，需要实际观察，不能预先保证精度改善。

./mc.sh call openmc_prepare_case '{
  "case_dir":"cases/tutorial", "target_dir":"cases/tutorial-400",
  "parameters":{"settings.particles":400}
}'
python3 - "$mc_workspace" <<'PY'
from pathlib import Path
import sys, xml.etree.ElementTree as ET
for name in ("tutorial", "tutorial-400"):
    file = Path(sys.argv[1]) / "cases" / name / "settings.xml"
    print(str(file), "particles=" + ET.parse(file).findtext("particles"))
PY

预期：返回 changes 中的 before=200、after=400；上面的文件检查显示原目录仍为 200，副本为 400。几何、材料和计分定义沿用原输入。这是本步骤应能验证的变化。

别的字段同样先取 name 和单位，不能照搬另一模型的材料/表面 ID。当前自动修改支持哪些字段、未支持的怎么处理，见输入与参数范围。

04 / 执行
校核通过后，提交这份副本

./mc.sh call openmc_validate_inputs '{"case_dir":"cases/tutorial-400","api_check":true}'

先检查结果：structure_valid=true、problems=[]，且 openmc_api.api_parsed=true。否则先处理错误，不要执行下一条提交命令。这里只检查结构和官方 API 能否解析，不保证几何无重叠或物理正确。

mc_job_id=$(./mc.sh call openmc_submit_job '{"case_dir":"cases/tutorial-400","threads":1}' | python3 -c 'import json,sys; print(json.load(sys.stdin)["job_id"])')
printf '本次计算编号：%s\n' "$mc_job_id"
./mc.sh call openmc_job_status "{\"job_id\":\"$mc_job_id\"}"

openmc_api 仅在请求 API 校核且结构通过时出现，API 解析失败会返回工具错误。

提交会复制当次输入并返回唯一 job_id，不等于计算结束。上面用 Bash 变量自动保存编号；以后查询、读结果都用这个编号。

./mc.sh call openmc_job_status "{\"job_id\":\"$mc_job_id\"}"

如果还是 queued / running，隔一会重复查询，等到 completed 再继续。不要重复提交，否则会创建另一份计算。

失败、取消和终端关闭后怎么办？

failed：查看状态错误和记录目录的 solver.log/worker.log；保留原记录。interrupted：终态未确认，可能仍有求解器，先由部署者核对进程。completed 也仍需看统计提示和实际产物。

./mc.sh call openmc_cancel_job "{\"job_id\":\"$mc_job_id\"}"

取消后继续查终态，不能只看取消请求成功。关闭终端/停止 MCP 不自动停止独立 worker；在同一工作区可继续按编号查询。丢失 Bash 变量时，从先前输出或 .mc-jobs 目录找回编号，不用重新计算。

05 / 结果
读哪些量、画什么图，由输入决定

./mc.sh call openmc_read_results "{\"job_id\":\"$mc_job_id\",\"max_values\":10}"

keff 是有效增殖因数；mean 是估计均值，std_dev 是统计标准差。tallies 列出输入中定义的计分（Tally），含名称、ID、score、核素和筛选维度。max_values=10 只限制返回预览，不截断原始结果文件。

本例的输入定义了名为 Flux spectrum 的通量能谱计分。下面从结果中取它的真实 ID，再画 flux。自己的模型要改用自己的计分，工具不会自动替你决定业务上应看哪个量。

mc_tally_id=$(./mc.sh call openmc_read_results "{\"job_id\":\"$mc_job_id\",\"max_values\":10}" | python3 -c 'import json,sys; print(next(t["id"] for t in json.load(sys.stdin)["tallies"] if t["name"]=="Flux spectrum"))')
./mc.sh call openmc_plot_results "{\"job_id\":\"$mc_job_id\",\"tally_id\":$mc_tally_id,\"score\":\"flux\",\"nuclide\":\"total\"}"
./mc.sh call openmc_export_report "{\"job_id\":\"$mc_job_id\",\"tally_id\":$mc_tally_id,\"score\":\"flux\",\"nuclide\":\"total\",\"format\":\"markdown\"}"
./mc.sh call openmc_list_artifacts "{\"kind\":\"job\",\"identifier\":\"$mc_job_id\"}"

现在应该拿到：一张 PNG、图表对应的 JSON/CSV、一份 Markdown 报告，以及原始 StatePoint 和日志的清单。图/报告响应的 server_path 是可以在服务器上打开的绝对文件路径；清单的 directory 是记录根目录。

核对是不是同一份结果：这里的绘图和报告都明确传入同一个 tally_id、score=flux、nuclide=total；不能只对绘图选参、报告却省略。报告返回 selection_mode=selected 和实际 selection，并给出对应图与完整数据的 chart、series_json、series_csv。打开报告，核对选择名称、图标题和数表中的计分项一致，而不只是看文件存在。

图的横轴是什么意思？报告为什么只放少量数据？

本例只有一个能量过滤器的通量计分，横轴用能量区间的算术中点，单位 eV；数据 CSV/JSON 同时保存 x_lower 和 x_upper 上下界。所有下界为正时使用对数横轴，有零下界时使用线性轴。均值仍是该区间的原始统计值，未除以能宽，不能当作每 eV 的谱密度；也未换算实际源强或功率。多种过滤器组合的结果仍用明确标注的展平分箱序号，不能把序号解释成距离或能量。

所选结果报告以图和摘要为主，正文最多预览前 20 点（受配置 max_report_rows 的更小上限约束），数表显示 9 位有效数字。完整所选均值、标准差、坐标和来源保存在配套 CSV/JSON 中；CSV 格式报告导出全部所选点，不受正文预览限制。原 StatePoint 保留。超出 max_plot_points 时须缩小 filter_selection，不会静默截断。

自己选择其它结果时，给绘图与报告传入相同的四项选择：tally_id、score、nuclide、filter_selection。其中任一项出现就进入所选模式，空数组表示所有分箱。四项全部省略才使用兼容旧调用的全作业摘要；它保留预览/截断提示，Word/PDF 默认附图取首个统计项目，不表示自动理解用户之前画过哪张图。

工作区：                 $mc_workspace
原输入（200）：           cases/tutorial/settings.xml
修改副本（400）：         cases/tutorial-400/settings.xml
本次计算：               .mc-jobs/<本次job_id>/
  job.json               编号、状态、输入与配置记录
  work/                  输入快照、StatePoint等OpenMC产物
  solver.log、worker.log  求解器/监控日志
  results.json           提取后的结构化结果
  plot-….png / json / csv 图与绘图数据
  report.md              导出的Markdown报告
ls -la "$mc_workspace/.mc-jobs/$mc_job_id"
目录名前有点号，所以默认隐藏。path、series_json 等相对服务端工作区；优先使用返回的 server_path，不要仅拿 image 文件名拼路径。异机调用只获得位置，当前没有自动下载接口，可由部署方通过已有 SSH/SFTP 等方式交付文件。

图保留 OpenMC 原始归一化，不自动转换为业务单位。std_dev=null 不是零误差，warnings 不能忽略。报告还支持 CSV/DOCX/PDF/DOC；同一编号重复导出同一格式会覆盖该报告，需要多版时先另行归档。

后续操作，按需要做

批量计算：从一份模型生成多组参数

继续用已发现的 settings.particles，在原输入上建立 200 和 400 两组计算：

./mc.sh call openmc_submit_scan '{"case_dir":"cases/tutorial","axes":{"settings.particles":[200,400]},"threads":1}'

它返回 scan_id，用 openmc_scan_status 查询；多轴取笛卡尔积，当前串行执行。图和报告保存到 .mc-scans/<scan_id>；失败项保留，曲线不以 0 替代缺失值。横轴、固定维度与报告参数见扫描绘图和扫描报告。

诊断与确认修复：先看差异，再决定

openmc_diagnose_job 读取指定计算的日志，提供有证据的提示；受支持问题可在新副本生成修复计划。只有用户看过差异并明确确认后才应用，再校核或关联重算。

现成练习用 mcp/.venv/bin/python examples/repair_demo.py。它故意制造运行模式拼写错误，并保留第一次失败。当前自动修复仅限普通 run 中唯一的 run_mode 近似拼写；不自动修物理参数。CLI 需要交互终端确认，MCP 需要可信宿主逐次取得批准。

产物清理：预览，确认，再删除

在计算服务器与相同 PID 命名空间执行。先预览本次记录：

./cleanup.sh --job-id "$mc_job_id"

需要删除时，先归档结果并确认计算结束；停止 MCP 和其它 CLI 写入，进入维护窗口，再对同一选择加 --apply：

./cleanup.sh --job-id "$mc_job_id" --apply

它删除选定终态记录及其快照、日志、图和报告；原 cases/ / demos/ 输入保留。删除后不能再按编号查询。扫描按整批用 --scan-id；运行中、未确认中断、关联冲突等会拒绝。./cleanup.sh --help 可查保留时间和修复引用选项；默认不删，失败非 0，不应无条件重试。

已经知道怎么跑：换成自己的模型，了解参数与扩展入口；需要远程调用：把现有工具作为 MCP 服务。

实现依据：例题准备、参数适配、输入快照/计算、官方 API 与结果读取。接口完整约束见参数参考。

# 从收到工具包到拿到结果

本文按实际使用顺序说明。先完成一次公开例题，再带自己的输入；需要给平台或智能体使用时才部署MCP。仅想封装已有程序，直接看[已有程序接入](已有程序接入.md)，无需安装OpenMC。

## 支持哪些工作

本包复用OpenMC计算能力，增加统一调用、检查和记录管理：

| 工作 | 当前可用内容 |
| --- | --- |
| 接入输入 | 注册公开例题或已有OpenMC XML；结构/基础参数校核，可选官方API解析 |
| 调整与执行 | 发现已适配参数、保留原输入创建新副本；本地计算/几何绘图/几何调试，提交/查询/取消 |
| 扫描 | 多参数笛卡尔组合，串行执行、逐项状态及取消；组合数按部署配置检查 |
| 结果 | 官方StatePoint读取keff与tally，PNG/SVG及对应数据，Markdown/CSV/DOCX/PDF/真实DOC报告 |
| 管理 | 每次计算输入快照、独立编号、日志、来源与产物清单；维护窗口预览清理 |
| 资料和修复 | 固定官方原文/出处、公开例题；受限日志诊断→新副本差异→用户确认→校核/关联重算 |

专业参数与模型设计仍按业务依据决定。当前参数修改仅覆盖发现接口列出的运行设置、部分CSG表面、材料密度/温度和源强，不能称所有OpenMC字段均可扫描。未适配的模型设置可以在准备输入时按OpenMC方式设置，再由本包校核、提交；超出当前输入或运行支持时会报错。

CAD、HPC、微调生成、专业规则和指定基准等仍有未完成项，见[开发计划](验收导向开发计划.md)。接口自测与公开工程例题不等于原合同专业验收。

## 初始化

解压后进入mc-tech-execution根目录。服务端用Linux/WSL，建议Debian/Ubuntu。需Bash、Python3.10+及venv、curl、tar/bzip2与包源网络；自动准备Office需apt-get/dpkg-deb。其他机器可以只做MCP客户端。

```bash
./quickstart.sh
```

它准备接口环境mcp/.venv、OpenMC0.16.0环境.runtime/openmc及图表/文档依赖；OpenMC API环境为Python3.12。已有系统LibreOffice时复用，否则提取转换组件/字体到.runtime/office。脚本不修改系统包或shell配置。首次下载完成后，日常运行不依赖其他项目目录。

已有运行环境可复用，把示例路径替换为实际prefix：

```bash
./quickstart.sh --openmc-prefix /opt/openmc-env
```

只需Markdown/CSV/DOCX可加--skip-office；之后要PDF/DOC再配置转换组件。源码包不包含已安装环境、密钥或正式核数据库，不是完全离线系统镜像。

检查有效环境：

```bash
./mc.sh call openmc_environment
```

分别看api_available、executable_available、version_matches、核数据条件及workspace。API可导入不表示求解器已安装；探测成功也不表示输入或物理结果正确。

## 先跑一次，再改一个设置

```bash
mcp/.venv/bin/python examples/public_case_demo.py
mcp/.venv/bin/python examples/public_case_demo.py --particles 400
```

两次分别生成独立例题和计算。第二条只改变每代粒子数，演示如何传参，不据此声称收敛或精度改善。--batches和--inactive也可传入，但须满足工具的组合约束。

例题使用随包公开C5G7多群数据。默认摘要含实际计算编号、状态、统计提示、图/报告的服务端绝对位置；进度写stderr。按打印路径在服务器打开文件，先确认自己能找到产物。

程序需要全部结果时：

```bash
mcp/.venv/bin/python examples/public_case_demo.py --json > public-result.json
```

--json让stdout成为一个完整JSON对象。原有openmc_demo.py、scan_report_demo.py和repair_demo.py采用同样规则，直接CLI/MCP始终结构化。旧版本读取演示stdout JSON的脚本需显式加--json。

## 换成自己的输入

熟悉OpenMC的使用者可以从这里开始。先调用openmc_environment查看实际workspace；默认在包根目录/workspace。

将已有输入复制到该工作区的独立目录。默认工作区示例：

```bash
mkdir -p workspace/cases/my-case
cp -a /实际输入目录/. workspace/cases/my-case/
./mc.sh call openmc_validate_inputs '{"case_dir":"cases/my-case","api_check":true}'
```

替换实际输入路径；若设置了MC_WORKSPACE，复制目标也须改到该数据根。工具参数case_dir相对**服务器工作区**，不能传客户端本地路径。工具拒绝越界和符号链接输入。

通常为materials.xml、geometry.xml、settings.xml及需要的tallies.xml，也支持模型入口model.xml。源项由相应设置描述，不虚构必须有source.xml。模型引用文件和核数据库须在运行服务器上可访问；正式连续能核数据按OpenMC方式配置。生成Python建模脚本本身不代替已导出的模型输入。

没有自己的输入时，下面的教学流程可以先创建一个固定目录。每个目标须尚不存在；重复练习请改新目录名，工具不会覆盖：

```bash
./mc.sh call openmc_prepare_example '{"case_id":"openmc-pincell-mg","case_dir":"cases/tutorial"}'
```

后文使用cases/tutorial；接自己的输入时将其换成自己的case_dir。

## 发现参数，再生成新副本

```bash
./mc.sh call openmc_list_parameters '{"case_dir":"cases/tutorial"}'
./mc.sh call openmc_prepare_case '{"case_dir":"cases/tutorial","target_dir":"cases/tutorial-400","parameters":{"settings.particles":400}}'
./mc.sh call openmc_validate_inputs '{"case_dir":"cases/tutorial-400","api_check":true}'
```

第一步返回每项name、type、current、unit和范围；第二步只接受已发现的参数并生成副本，原输入保留。例如材料参数含对象ID和密度单位，不能照抄别的模型的编号，也不能把macro截面倍率当质量密度。

生成或校核通过仍要计算才能得到结果。structure_valid/problems描述XML/基础参数检查；仅请求api_check且结构通过时才有openmc_api，未请求或结构失败时字段缺席，API解析失败则返回工具错误。几何重叠、核数据适用性和专业正确性还需相应检查/计算与业务判据。

## 提交与查询

以下是Bash示例，自动取出返回的job_id，避免手抄编号：

```bash
mc_job_id=$(./mc.sh call openmc_submit_job '{"case_dir":"cases/tutorial-400","threads":1}' | python3 -c 'import json,sys; print(json.load(sys.stdin)["job_id"])')
./mc.sh call openmc_job_status "{\"job_id\":\"$mc_job_id\"}"
```

queued/running时重复查询同一个编号，不要重复提交。completed表示计算正常结束，仍需核对统计和实际产物。failed保留错误/日志；cancelled为取消终态；interrupted表示监控丢失、终态未确认，可能仍有求解器，不能当成功或盲目重提。

需要取消：

```bash
./mc.sh call openmc_cancel_job "{\"job_id\":\"$mc_job_id\"}"
```

取消请求后继续查询终态。停止MCP服务不会自动停止独立worker；相同工作区在重启后仍可查询已有记录。

## 读取、画图、报告

等查询到completed再执行：

```bash
./mc.sh call openmc_read_results "{\"job_id\":\"$mc_job_id\",\"max_values\":10}"
./mc.sh call openmc_export_report "{\"job_id\":\"$mc_job_id\",\"format\":\"markdown\"}"
./mc.sh call openmc_list_artifacts "{\"kind\":\"job\",\"identifier\":\"$mc_job_id\"}"
```

| 返回内容 | 下一步怎样用 |
| --- | --- |
| job_id / scan_id | 分别用于计算/批次查询；不是目录，不能混用 |
| keff、tallies | 核对均值、标准差、计分定义/维度；null不是零误差，保留warnings |
| path、series_json、series_csv | 相对服务端workspace的产物路径 |
| server_path、directory | 服务端绝对文件/记录位置，远程客户端不会自动下载 |
| provenance | 数据、模型和执行来源，不能因工具成功就忽略其工程示例标记 |

本教学例题选择实际结果中的Flux spectrum计分，再用返回的ID画图：

```bash
mc_tally_id=$(./mc.sh call openmc_read_results "{\"job_id\":\"$mc_job_id\",\"max_values\":10}" | python3 -c 'import json,sys; print(next(t["id"] for t in json.load(sys.stdin)["tallies"] if t["name"]=="Flux spectrum"))')
./mc.sh call openmc_plot_results "{\"job_id\":\"$mc_job_id\",\"tally_id\":$mc_tally_id,\"score\":\"flux\"}"
```

自有模型不保证有这个名字或score，须从实际tallies选择ID与计分后填写，不能照抄别的模型的ID。

max_values仅控制返回的预览长度，截断会标记；绘图从完整StatePoint读取所选计分。先从结果的tallies核对tally_id、score、nuclide与filters，再调用openmc_plot_results；省略会选默认项，不表示自动选中业务上正确的量。嵌套filter_selection填法见[参数参考](工具接口参考.md#openmc_plot_results)。图可选PNG/SVG，并另存对应数据JSON/CSV；保留原OpenMC归一化。

报告可选markdown、csv、docx、pdf、doc；DOCX无需Office，PDF/DOC需要转换组件。真实DOC不是改后缀的文本。同一个job_id或scan_id重复导出同格式会覆盖报告文件，需要多版时先另行归档。导出成功与统计可靠、专业结果正确分别判断。

### 产物在哪里

```text
workspace/                         默认MC_WORKSPACE
  cases/、demos/                   原输入/演示输入
  .mc-jobs/<job_id>/               记录、图、报告、results.json
    work/                         本次输入快照与StatePoint等原始产物
    solver.log、worker.log        求解器/监控日志
  .mc-scans/<scan_id>/             扫描基线、组合副本、汇总和图/报告
  .mc-plans/、.mc-backups/          修复计划及备份
```

点号开头是隐藏目录，用ls -la或文件管理器“显示隐藏文件”。以工具返回位置和清单为准，不相对终端cwd、examples或mcp目录。case.files相对case_dir，计算files在记录work/中，image往往只是文件名；不要仅拼文件名。知识source标识另以包内knowledge为根。

openmc_list_artifacts列出产物位置、大小和SHA256。当前仅保存服务端文件；有SSH权限可用现有SCP/SFTP取回，没有访问方式则由部署方交付。没有自动下载接口，服务器路径不代表客户端已有文件。

## 扫描与确认修复

批量扫描复用同一参数发现过程：axes是参数名到候选数组的映射，多维作笛卡尔积，默认串行。submit_scan返回scan_id，用scan_status查询、cancel_scan取消；失败组、partial和缺失结果保留。曲线用x_parameter选横轴，fixed固定其它多值维度，不能把失败点填0。各参数与例子见[接口参考](工具接口参考.md#openmc_submit_scan)。

现成工程演练：

```bash
mcp/.venv/bin/python examples/scan_report_demo.py
# 未配置Office时：
mcp/.venv/bin/python examples/scan_report_demo.py --formats markdown csv docx
```

它使用合成单群macro倍率，验证扫描/五格式报告链路；keff可能近似不变、统计量可能不可用，不能用来评价真实密度敏感性。

确认修复练习：

```bash
mcp/.venv/bin/python examples/repair_demo.py
```

它真实保留首次失败，在新副本展示差异，等待用户确认，再校核/关联重算。当前自动修复限普通run的run_mode唯一近似拼写；其它问题提供证据与排查方向。拒绝不应用、不重算，原失败和输入保持。直接CLI须TTY确认，管道y不能代替用户；MCP须可信宿主逐次展示并取得批准，模型不能自行确认或永久自动批准apply_repair。更详细来源与规则见[专题说明](公开资料与例题修复.md)。

## 清理产物

在实际计算服务器、相同PID命名空间运行；不能从另一台机器的共享挂载推断远端进程状态。

```bash
./cleanup.sh
./cleanup.sh --older-than-days 7
./cleanup.sh --job-id 实际计算编号
./cleanup.sh --scan-id 实际扫描编号
```

默认仅列记录/预览，不删除。年龄按finished_at而非文件mtime；可以重复编号选多项。扫描按整批连子计算清理，被保留扫描引用的单独子计算不能删。

核对、归档，查询/取消计算并确认结束，**停止MCP及其它CLI写入**进入维护窗口后，对相同选择加--apply：

```bash
./cleanup.sh --scan-id 实际扫描编号 --apply
```

只删除经检查的内部终态记录及其输入快照、数据副本、日志和全部产物；原cases/demos、配置、知识库、外部核数据、计划和备份保留。记录删除后不能继续按编号查询，不自动重算。

运行/排队、interrupted、无有效完成时间/进程身份、坏关联、符号链接和使用中的记录锁均拒绝。interrupted可能留有求解器，应由部署方先核对。停止服务本身不停止worker；脚本互斥与执行前复查也不替代维护窗口，不承诺在线并发清理。

修复计划引用所选作业时默认拒绝，列出plan_id；确已归档且接受失去相关查询/重验能力，可显式加--allow-repair-references。计划/备份保留不等于关联计算历史仍在。

失败返回非0；部分删除时分别列出已删、未删或可能部分删除，不回滚、不无条件重试。日志/输出不自动轮转，部署方按容量管理。

## 部署MCP与交给调用方

直接CLI跑通后再启动：

```bash
./mcp/start.sh
```

默认Streamable HTTP，http://127.0.0.1:8770/mcp。一个服务提供多个工具，服务不依赖Harness或模型。可先用标准SDK客户端验证，不需要模型账号：

```bash
mcp/.venv/bin/python examples/mcp_client.py --url http://127.0.0.1:8770/mcp
mcp/.venv/bin/python examples/mcp_client.py --url http://127.0.0.1:8770/mcp --tool openmc_environment
```

第一条初始化并tools/list，拿到名称、用途、参数含义/类型/范围/默认及关键返回说明；第二条tools/call。不能拿裸HTTP JSON POST代替完整MCP初始化。图表调用可同时返回标准图像内容和结构化结果；脚本的stdout为JSON，失败非0。

交给调用方的是以下信息，不是手抄所有函数参数：

| 信息 | 例子/说明 |
| --- | --- |
| 传输方式 | streamable-http；是否支持由实际客户端确认 |
| 实际MCP URL | 同机可用http://127.0.0.1:8770/mcp；异机须部署方实际可达URL |
| 鉴权 | 启用时配置Authorization: Bearer 令牌；秘密另行提供，不写进源码/说明 |
| 连接名称 | 客户端用于区分服务的别名，服务启动会给出示例 |
| 工具定义 | 连接后通过tools/list发现，不需要人工抄函数名与参数表 |

启动后mcp/connection.json保存连接信息，/info提供同份Schema等扩展信息；它们的配置格式不是所有平台通用格式，按调用方字段填写。${MCP_AUTH_TOKEN}是环境占位符，仅支持该替换的客户端才会展开；其它平台显式配置认证头。/health只探活，不证明认证、OpenMC或业务可用。连接文件停止后仍保留，不能据此判断在线。

远程部署示例，实际路径/域名/令牌需替换：

```bash
export MC_WORKSPACE=/srv/mc-data
export MCP_HOST=0.0.0.0
export MCP_PORT=8770
export MCP_PUBLIC_URL=https://mc.example.org/mcp
export MCP_AUTH_TOKEN='部署方生成的令牌'
./mcp/start.sh
```

非回环监听须实际publicUrl和Bearer；公网使用部署方HTTPS入口。0.0.0.0只用于监听，不能交给客户端。防火墙、DNS、TLS和反向代理由部署条件落实，代理保留Host/Authorization；当前按服务端客户端使用，浏览器来源/CORS需另行配置核对。/info和MCP同样受Bearer保护。

四个演示也可加--mcp-url 实际URL走同一服务。协议客户端成功与自然语言工具选择分别验证，不能据此声称全部模型/平台通过。[Codex/DSH等](MCP平台接入.md)仅为扩展说明，原合同兼容性仍按计划验证。

## 配置速查

| 设置 | 优先级与生效 |
| --- | --- |
| 工作区 | CLI --workspace > MC_WORKSPACE > 包根目录/workspace；服务启动后固定 |
| OpenMC配置 | CLI --config > MC_OPENMC_CONFIG > config/openmc.local.json > config/openmc.json；计算记录保存当次快照 |
| 服务配置 | MCP_CONFIG_FILE选择JSON，MCP_HOST/PORT/PATH/PUBLIC_URL等覆盖；鉴权来自MCP_AUTH_TOKEN，改变后重启 |

MC_WORKSPACE建议用绝对路径，CLI/MCP共享数据时设置一致；CLI的相对--workspace/--config按调用cwd解析，MC_OPENMC_CONFIG相对路径按包根目录解析。重新配置不会迁移旧数据；迁移包后重新初配，不照搬旧个人路径。本机local配置、密钥不提交Git或分发。

OpenMC配置常用项：python_command/openmc_command为管理员控制的argv数组；expected_version为适配基线；api_timeout_seconds/job_timeout_seconds为执行时限；max_scan_cases/max_plot_points/max_report_rows限制组合/完整绘图/报告；max_log_bytes控制日志保留；office_command/report_timeout_seconds/font_path配置转换与字体。相对Office命令路径按包根定位，通用命令名从服务PATH查找，不拼任意shell文本。正式核数据用OPENMC_CROSS_SECTIONS或模型相应引用配置。

## 出问题时从哪里继续

- **找不到文件**：先查environment.workspace，再按产物清单server_path找；用ls -la看隐藏目录，远程路径不是本机文件。
- **API有、程序没有／版本不符**：检查实际配置的两个命令和版本，不能只pip安装Python包。
- **输入能生成但算不了**：看输入、核数据引用及solver.log；工具不会退到模拟结果。
- **标准差null、图一点、keff近似不变**：检查统计条件与计分维度，合成macro例题有其用途边界；不填0、不凭图判断精度。
- **PDF/DOC失败**：核对Office命令、字体、权限和转换日志；可先导出Markdown/CSV/DOCX，不生成假PDF。
- **MCP连接失败**：核对实际URL、监听、公网入口、Bearer及Host；先标准初始化/发现/调用，不能只看health。
- **模型选错工具或参数**：核对客户端是否收到完整Schema、实际模型/版本和授权策略；记录真实调用，先验证标准接口再排查自然语言层。
- **清理拒绝/部分失败**：读清原因与剩余目录，先核对实际worker和关联，不能盲目重试。

# 从算例到产物的完整使用流程

先完成[配置与部署](配置与部署.md)。所有以下命令从工具包根目录执行；除了演示，底层CLI和MCP均返回结构化数据，便于下游编程。工具参数完整定义见[接口参考](工具接口参考.md)。

## 1. 先用可运行例题确认环境

```bash
mcp/.venv/bin/python examples/public_case_demo.py
```

默认打印简明结果、计算编号、统计提示和服务端绝对位置，不把原始日志和大数组铺满终端。演示会创建新算例和产物；进度写stderr。

程序需要完整结果时：

```bash
mcp/.venv/bin/python examples/public_case_demo.py --json > public-result.json
```

--json使stdout成为一个完整JSON对象，进度/提示仍在stderr。其他三个演示openmc_demo.py、scan_report_demo.py、repair_demo.py采用相同规则。已有依赖旧演示stdout的脚本应加--json；./mc.sh和标准MCP的结构化输出方式保持。

| 例题 | 用途与条件 |
| --- | --- |
| openmc-pincell-mg | 官方多群燃料棒，随包C5G7数据；不代表指定业务验收 |
| synthetic-mgxs | 合成单群工程练习，验证接口/进程/产物链路 |
| openmc-pwr-pin-cell | 可生成连续能输入；实际计算需要对应核数据库 |
| run-mode-typo | 故意失败的确认修复练习 |
| CLEAR-S / 17x17 | 原指定材料/参考判据仍待提供，目录条目不表示已可计算 |

## 2. 放入自己的OpenMC算例

先查实际工作区：

```bash
./mc.sh call openmc_environment
```

返回workspace是服务端绝对数据根。默认情况下，可在项目根目录这样复制一个已有算例；用自己的实际目录替换/实际输入目录：

```bash
mkdir -p workspace/cases/my-case
cp -a /实际输入目录/. workspace/cases/my-case/
./mc.sh call openmc_validate_inputs '{"case_dir":"cases/my-case","api_check":true}'
```

自定义MC_WORKSPACE时，将复制目的地改为该工作区中的cases/my-case。case_dir始终相对服务端工作区；不能把客户端绝对路径直接传给MCP工具。当前工具拒绝越界和符号链接输入。

通常输入为materials.xml、geometry.xml、settings.xml和按需要提供的tallies.xml，也支持模型入口model.xml。源项由相应设置描述，不要求额外虚构一个source.xml。所需核数据、模型引用的文件及Python/OpenMC版本必须在服务端具备。

结构和API解析检查不等于专业正确：几何重叠、材料适用性、单位/归一化等还要相应规则或实际计算核对。

## 3. 提交、等待、查询

```bash
./mc.sh call openmc_submit_job '{"case_dir":"cases/my-case","threads":1}'
```

把真实返回的job_id复制到下一条的“实际计算编号”：

```bash
./mc.sh call openmc_job_status '{"job_id":"实际计算编号"}'
```

queued/running还未完成；completed表示求解器正常结束，仍须核对文件和统计；failed保留错误与日志；cancelled表示取消终态；interrupted表示监控结束但结果未确认，不能当成功。不要反复提交来代替查询。

需要取消时调用openmc_cancel_job，随后查询到终态；请求受理不等于子进程已退出。

## 4. 读取结果、选图、导出

```bash
./mc.sh call openmc_read_results '{"job_id":"实际计算编号","max_values":20}'
./mc.sh call openmc_export_report '{"job_id":"实际计算编号","format":"markdown"}'
./mc.sh call openmc_list_artifacts '{"kind":"job","identifier":"实际计算编号"}'
```

read_results返回keff与tally定义/均值/标准差，并刷新派生results.json；max_values只控制预览长度。图表读取完整所选StatePoint数据，不能把预览当完整统计。多个tally/score/nuclide或维度时，按返回定义选择tally_id、score、nuclide、filter_selection，不能猜第一个结果就是想要的量。

例如只有确认所选tally确实含flux后，才这样画图：

```bash
./mc.sh call openmc_plot_results '{"job_id":"实际计算编号","tally_id":2,"score":"flux","format":"png"}'
```

这里2只是参数示例，不保证每个模型都有同一tally。支持PNG/SVG；报告支持markdown、csv、docx、pdf、doc。DOCX无需转换组件，PDF/DOC需要Office。返回path是工作区相对路径，server_path是服务端绝对路径；远程客户端不能把它当本地已下载文件。

## 5. 批量参数扫描

```bash
mcp/.venv/bin/python examples/scan_report_demo.py
```

这是三组macro截面倍率的合成练习，默认生成五种报告。没有配置Office时可用--formats markdown csv docx。macro不是质量密度；该例不是材料密度敏感性验证，keff可能近似相同。标准差不可用会显示“不可用”和原统计警告，不会填0。

自己的模型先用openmc_list_parameters发现已适配参数，再把返回的name用于openmc_submit_scan。工具只接受当前适配列表；多维axes按笛卡尔组合串行执行。提交返回scan_id；用openmc_scan_status查询、openmc_cancel_scan请求取消。partial/failed/interrupted等状态及逐组结果都会保留。

扫描图通过x_parameter选横轴，其他多值维度用fixed固定。metric可取keff或已确认的tally；结果保留原归一化，失败/缺失点不填0。扫描报告和清单使用openmc_export_scan_report、openmc_list_artifacts(kind=scan)。

## 6. 诊断、确认修复和重算

运行repair_demo.py可演练真实失败→日志证据→新副本差异→逐次确认→校核/关联重算。当前自动修改只覆盖普通计算中run_mode的唯一近似拼写。

直接CLI要求TTY确认，管道输入y不能代替用户；标准MCP由可信调用方逐次展示预览并取得确认。拒绝不修改、不重算。旧失败记录与原输入保留；校核或修改成功也不代表重算成功。详见[专门说明](公开资料与例题修复.md)。

## 7. 换成标准MCP调用

服务端先启动./mcp/start.sh；调用方通过标准ClientSession发现工具，用相同参数调用。可把以上演示加--mcp-url http://127.0.0.1:8770/mcp走协议；异机使用实际可达地址。模型与具体宿主不属于完成这条协议链路的前置要求，见[MCP服务与接口](MCP服务与接口.md)。

完成后按[产物与清理](产物与清理.md)管理文件。原始业务输入和专业数据应独立归档，不依赖演示目录长期保存。

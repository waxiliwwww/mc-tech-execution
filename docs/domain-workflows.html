先准备环境：接口、引擎和核数据分别就绪

在工具包根目录执行 ./quickstart.sh，具体下载、版本和核数据准备见环境说明；已有环境先检查 ./mc.sh call openmc_environment '{}'。不能只安装接口层Python包。以下组合模型用真实连续能核数据，不会自动退到合成数据或假计算。

完整源码交付建议直接运行或 pip install -e .。独立wheel仅含接口代码；使用基础建模/计算时要显式给出 MC_OPENMC_CONFIG、MC_WORKSPACE 和实际核数据路径，官方资产仍随完整源码包准备。

所有 case_dir/source_dir/target_dir 是服务端 MC_WORKSPACE 内的相对目录，默认工具包的 workspace/。客户端本机路径不会自动上传。返回的 server_path 是服务端绝对位置，配置和依赖探测仍以实际服务器为准。

入口一：带入已有模型

已有Python建模程序：先在安装OpenMC的环境运行它，导出 model.xml 或几何、材料、设置、计分分文件。导出步骤由你或部署管理员执行；MCP导入工具不执行随输入提供的Python或本地动态库。

把XML及本地依赖放入服务端工作区的一个专用目录，例如 inbox/my-model/，再调用：

./mc.sh call openmc_import_model '{"source_dir":"inbox/my-model","target_dir":"cases/my-model"}'
./mc.sh call openmc_list_parameters '{"case_dir":"cases/my-model"}'
./mc.sh call openmc_preview_input '{"case_dir":"cases/my-model"}'

导入会复制原始输入、检查文件与依赖并通过官方API读回，然后发布新副本；原输入不变，也不会按生成器Schema重建陌生模型。api_check=false 只关闭API解析，不表示模型可计算。

输入情况处理与需要你注意的事
原生合法模型 / 更复杂几何可导入范围比新建模型Schema宽；是否能运行还取决于引擎编译、核数据和模型本身，可自动改参范围另由发现接口给出。
相对路径依赖文件须整理进源目录，随目录复制；../、符号链接和特殊文件拒绝。不要把旧计算记录混入输入目录。
绝对路径与核数据索引绝对文件要求在服务器存在，返回依赖清单并标为不可直接搬移；复制了截面索引也不等于已核验/复制它引用的全部核数据。
编译源 / 自定义输出目录当前导入拒绝compiled source及非默认output.path，分别需要管理员审查、原生产物路径适配；不会静默删除或改写这些设置。
原工具包私有marker导入会重置未审定来源，不继承“已验证”声明；燃耗配置需用专用配置接口重新配置。

入口二：组合生成新模型

先调用能力发现（openmc_model_capabilities），取得与实际执行同源的 spec_schema。长度是cm、能量是eV、温度是K；核素份额的 ao/wo 由调用者明确指定，工具不推断富集度、材料成分或专业设计。

./mc.sh call openmc_model_capabilities '{}'
能配置什么用途与边界
材料核素相对份额、原子/质量口径、密度、温度、热散射、可燃耗标记与显式体积。份额按所选口径归一化，化学计量与专业适用性由输入依据确认。
几何与布局平面、轴向圆柱、球；使用面编号的布尔区域；材料/真空/宇宙填充；二维矩形格架。格架数组按y从上到下、每行x从左到右。Schema不支持的CAD、六角格架等可沿原生模型入口接入。
源与运行点源/盒源、可选单能源、本征值/固定源、粒子、批次、非活跃批次和种子。低统计设置仅供调试，不保证收敛。
计分实际scores/核素及能量、材料、规则网格过滤；未定义的量不能在结果阶段凭空提取。组合大小受工具工程保护，不代表物理限制。

随包 rectangular-assembly.json 是显式组成的3×2异构格架输入，四个燃料棒位置和两个水位置，六个通量网格箱；它用于解释布局与接口，不是甲方组件或已核验的堆设计。fixed-source-water.json 展示另一种固定源水球输入。可以换材料、数量、区域、格架排列、源与计分，不需要增加例题ID。

先只生成并检查输入，以下代码把JSON文件作为数据传给工具，不把它当代码执行：

mcp/.venv/bin/python - <<'PY'
import json, subprocess, sys
from pathlib import Path
spec = json.loads(Path('examples/model-specs/rectangular-assembly.json').read_text())
subprocess.run([sys.executable, 'mcp/cli.py', 'call', 'openmc_build_model',
    json.dumps({'case_dir':'cases/my-assembly', 'spec':spec})], check=True)
PY
./mc.sh call openmc_preview_input '{"case_dir":"cases/my-assembly"}'
./mc.sh call openmc_validate_inputs '{"case_dir":"cases/my-assembly","api_check":true,"semantic_check":true,"geometry_check":true}'

得到XML、model-spec.json 和 build_model.py。后者是可信构建器源码，放到另一个空目录、连同模型描述，用装有OpenMC的Python运行即可重建；不需要原仓库路径。API读回成功与抽样几何检查均不代表专业计算正确。

先知道参数，再改参数重算

组合示例的材料编号2在JSON中明确是水，初始密度0.7 g/cm³。因此将 materials.2.density 设为0.8，是改变冷却剂密度；它不是随便改某个数字，也不是对真实工况的推荐。

./mc.sh call openmc_list_parameters '{"case_dir":"cases/my-assembly"}'
./mc.sh call openmc_prepare_case '{"case_dir":"cases/my-assembly","target_dir":"cases/my-assembly-denser","parameters":{"materials.2.density":0.8}}'
./mc.sh call openmc_preview_input '{"case_dir":"cases/my-assembly-denser"}'
./mc.sh call openmc_submit_job '{"case_dir":"cases/my-assembly-denser","name":"组件冷却剂密度0.8","threads":1}'
./mc.sh call openmc_list_jobs '{"name":"组件冷却剂密度0.8"}'

任务名只是标签，可重名；从返回列表取得实际 job_id 再查状态、取消或读取结果。状态中的 input_hashes 可与预览SHA256核对，确认结果归属于看到的输入；查询不会替你重算。

本工具生成且指纹未漂移的模型，改参会同步模型描述并经Python API重建，保留可重跑性。手工改了XML、描述文件，或用其他接口改变了生成输入后，应重新导入为原生模型，或修改描述后构建新目录；工具会拒绝用旧描述覆盖已改变的输入。原生模型继续保留局部改参能力，不强制进入受限Schema。

完整调用示例：用你的模型走同一流程

mcp/.venv/bin/python examples/model_workflow.py \
  --spec examples/model-specs/rectangular-assembly.json \
  --name '组件密度研究' --set materials.2.density=0.8 \
  --receipt artifacts/my-model-workflow.json

这次命令会明确执行两次计算：原模型与修改副本，然后按同一计分画图、导报告并比较。默认中文摘要包含服务端绝对位置，--json 输出完整结构。低统计比较只显示观察值及不确定度，不预先保证变化趋势或显著性。

选项含义
--spec FILE / --source-dir DIR二选一：客户端JSON模型描述，或已放在服务端工作区的原生输入目录。后者仍会导入新副本，不自动上传文件。
--set NAME=VALUE可重复，参数名/单位先从发现接口取得；不传只算原模型，传入时额外创建修改副本并对比。完整模型结构修改使用spec，不能猜通用改参键。
--case-dir / --name新目录省略则唯一生成；任务名省略为model-workflow。已有目标拒绝覆盖。
--mcp-url URL通过标准MCP调用相同接口；不传走直接CLI。模型JSON可在客户端，原生模型目录和核数据必须先在服务器就绪。
--threads / --timeout每次求解线程数默认1，等待终态默认300秒；超时请求取消并保留编号。
--tally-id / --report-format省略时选实际首个含flux计分（否则首个计分）、Markdown；可选其他实际计分与报告格式。没有计分时只导作业摘要。
--receipt FILE完整调用记录保存到客户端指定位置；计算、图和报告仍在服务端。任何阶段失败会保存已完成部分、失败阶段和job_id，不自动重试计算。清理产物用既有维护入口，默认仅预览。

换成自然语言，智能体怎样调用

按标准MCP接入说明交付URL、传输方式及必要鉴权。工具包不要求Helix或内置模型。先发现能力，再提供有依据的参数；没有材料组成、几何尺寸等必要信息时，宿主应向用户询问，而不是替用户编造。

“按我给的材料组成和尺寸，建立两种宇宙组成的矩形组件，加入空间通量计分。先展示生成输入供我检查，确认后命名提交计算；输出keff、通量图和报告，并给出服务器产物位置。”

对应调用：能力发现 openmc_model_capabilities → 组合新建 openmc_build_model → 预览/校核 → 用户确认 → 命名提交/状态 → 结果/图/报告。已有模型则从 openmc_import_model 开始。确认由宿主向用户展示并取得，服务不声称能自行证明真人同意。模型描述是一份数据契约，宿主无需拼接Python或手写XML。

本轮按用户决定只做真实MCP接口验证，不调用模型；自然语言宿主编排后续另行安排。合同RF004微调模型生成另行落实。不能以“模型能看到工具”宣称生成质量或正式验收已通过。

产物怎么看，结论怎样得出

默认输入在 workspace/cases/…；每次实际求解快照、日志和StatePoint在 workspace/.mc-jobs/<job_id>/。优先使用返回的绝对路径，别从客户端当前目录拼路径。图旁的CSV/JSON是完整所选数据，报告正文可能只预览前若干点。

先核对任务名/ID、实际输入、计分定义和坐标；再看均值与标准差、有效批次及警告，最后比较变更前后结果。原始flux计分未自动转成功率或物理工况通量，须按源强、体积或功率等专业依据归一化。缺少依据时只呈现原始统计结果。

空间不足时，提交在复制输入、创建作业记录前拒绝，并给出清理预览命令。min_free_disk_bytes 默认保留1GiB，是可调工程配置，不是验收指标；不保证求解期间新增HDF5、并发及其他写入不会耗尽空间。清理与容量查看见DSH交接说明。

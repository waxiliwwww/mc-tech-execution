MC工具包说明

本包把OpenMC的建模、计算和结果处理接成一套可检查、可追踪的操作。用户可以直接用CLI，也可以让DSH等宿主通过MCP调用；OpenMC是现有的蒙特卡罗粒子输运引擎，负责求解；模型理解与对话由宿主完成。

已有模型 / 结构化新模型→预览与校核→命名作业与输入快照→OpenMC→数据、图和报告

用户视角：一次任务怎样完成

  1. 准备环境。拿到完整源码包，按环境说明配置接口、OpenMC和核数据。直接运行./mc.sh，或启动MCP服务后在DSH中连接；DSH模型配置不属于本包。
  2. 选输入来源。已有Python程序先导出XML，再把输入及依赖放入服务端工作区，用导入模型（openmc_import_model）创建副本。没有现成模型时，先发现建模能力（openmc_model_capabilities），再把有依据的材料、几何、源与计分交给组合建模（openmc_build_model）。自然语言由宿主组织成这些参数。组合模型的长度用cm、能量用eV、温度用K，材料份额明确原子或质量口径。
  3. 看清再算。预览输入（openmc_preview_input）、分层校核（openmc_validate_inputs）。改参先发现可调项，再建新副本，原输入保留；并非所有OpenMC属性都能自动修改。
  4. 命名提交。提交作业（openmc_submit_job）取得job_id，查询同一编号到终态，也可取消。任务名便于查找，重名仍靠ID区分；提交成功不等于计算完成。
  5. 读结果和产物。读取结果（openmc_read_results）后，按实际计分选择图与报告。输入、日志、StatePoint、CSV/JSON和报告留在服务端，返回绝对路径；远程调用不会自动上传输入或下载输出。

完整操作与改参示例说明每一步的参数和命令；DSH接入说明说明Windows连接方式。

同一个例子：简化全堆空间通量

输入来自随包适配的公开全堆模型，复用OpenMC的pwr_core()；空间统计由用户明确加入8×8×1网格flux计分。创建模型、定义计分、预览校核、提交查询后，工具从真实StatePoint提取keff和64格均值/标准差，再生成热图、完整数据和报告。

这条链的价值是把输入、作业和结果对应起来。实际输入有快照与指纹，图表沿用所选统计数据，失败有编号和日志。已有工程记录核对了原生数值、图和报告的一致性；小统计运行不证明收敛。keff无量纲；本包保留flux原始计分，不追加体积、源强或功率归一化，不能直接称为实际功率或工况通量。

开发者视角：这些能力怎样实现

职责实现与扩展入口保留的行为
公共接口tools.py注册函数和Schema；cli.py、server.py共用适配层。CLI与MCP调用同一业务实现，嵌套参数带含义、单位和约束。
模型与改参openmc_model_spec.py经官方Python API生成XML；openmc_import.py保留原生输入；参数适配在openmc_parameters.py。组合建模受Schema约束，不执行任意用户代码；声明式改参同步描述、Python源码与XML，发现漂移就拒绝覆盖。
作业与扫描openmc_jobs.py的submit()/run_worker()管理作业进程和持久状态；openmc_scan.py复用作业执行参数组合。快照、日志、失败及取消可追踪；接口进程与计算进程分开，提交后用后续调用查询长计算。
结果与报告openmc_worker.py的execute()在OpenMC环境读原生结果；图表和文档由openmc_visuals.py、openmc_reports.py处理。保留计分维度、来源和不确定度；所选图、完整数据与报告同源。
其他适配官方例题工作流、燃耗、CAD转换、几何查看、资料检索及有限诊断/确认修复，见接口参考。各有适用范围；固定例题不是唯一输入入口，通用计算管理可接非目录模型。
资源与维护openmc_storage.py检查提交空间；cleanup_artifacts.py提供离线维护清理。低空间拒绝新提交，清理先预览并保护关联记录；不自动删除核数据或旧证据，不承诺运行期硬配额。

扩展一个操作时，在业务模块实现，再注册Schema、补参数说明和真实边界测试，最后重生成接口参考。修改建模能力还须同步发现、预检、执行与源码重建；只加工具名称不算完成。

当前边界：可运行、可自动改参、可组合生成是三个不同范围。DSH注册与自然语言任务按实际回执判断，不能从标准MCP测试推定通过。HPC、微调模型生成、指定CLEAR-S及专业验收未完成；宿主编排不替代这些合同要求。

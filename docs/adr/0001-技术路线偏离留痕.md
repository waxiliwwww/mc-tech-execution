# ADR-0001 技术路线偏离留痕（对《表4-1技术落点对照表》）

日期：2026-11-03　状态：记录并生效　依据：交付文档 09 号《表4-1技术落点落地审计》§3；AGENTS.md"偏离必须留痕"。

本记录覆盖实现与表 4-1"技术落点"列设计建议不一致的全部已知位置。每条给出：设计原文要点、实际路线、为什么可辩护（后果对比）、代价与回头条件。此后新增偏离，先补记录再实现。

## 1. 参数 schema：Pydantic v2 → 手写类型检查

- 设计（1.1）：参数 schema 建议 Pydantic v2，参考 promptmc 的 typed CSG schema 墙；LLM 只在 schema 内填值。
- 实际：create_model/prepare_case 内逐参数 isinstance/范围检查；参数语义经 tool_metadata 进入 MCP inputSchema。
- 为什么可辩护：当前无 LLM 直接填参路径（微调模型未接入），手写检查够用且零依赖；MCP inputSchema 已承担对外约束面。
- 代价与回头条件：**RF004 微调模型接入时必须回头**——没有 schema 墙就没有"LLM 只在 schema 内填值"的约束面。pydantic 已在 mcp/requirements.txt，组件模板（需求 A1）启动时一并上。

## 2. 模板渲染：Jinja2 → OpenMC 对象模型直出

- 设计（1.1/4.3）：运行期"选模板→填参→Jinja2 渲染→schema 校验→openmc CLI"；报告 Jinja2→Markdown。
- 实际：worker 在计算环境内用 openmc 对象模型（Cell/Geometry/Materials/Settings/Model）建模后 export_to_xml；报告为自研渲染。
- 为什么可辩护：对象模型经 openmc 解析器保证结构正确，渲染错误面小于文本模板；分层策略的核心意图（接口层不装 openmc）已由双环境达成——mcp/.venv（Python 3.14）无 openmc，计算经 api() 子进程 JSON 桥进入 .runtime/openmc（Python 3.12 + OpenMC 0.16.0），实测确认。
- 代价：模板不能脱离 Python 环境编辑；报告模板生态不通用。可维持。

## 3. 任务表：SQLite → JSON 文件（原子写 + flock）

- 设计（3.1）：SQLite 任务表。
- 实际：每作业一目录，job.json 原子写 + record.lock（fcntl.flock），状态机字段齐全，重启后可查询。
- 为什么可辩护：单用户本地场景等价、零依赖、产物即记录（可直接查看/归档/校验指纹）；测试覆盖重启查询。
- 代价与回头条件：作业量上千或需要跨作业 SQL 查询时会吃亏；HPC（RF007）引入远端作业后如需统一台账再评估迁移。

## 4. 结果提取：tallies.out ASCII 优先 → StatePoint(HDF5) 为准

- 设计（4.1）：tally 提取可完全不碰 HDF5，仅精确 keff/细分时用 h5py；大 tally 自动切换。
- 实际：read_results 统一走 openmc.StatePoint（mean/std_dev），"不将 HDF5 累计和误当均值"写入 RF009 验证法。
- 为什么可辩护：StatePoint 结构化、精确、带不确定度，单一读取路径减少分支错误；设计坑条款（大 tally 切换）在此路线下天然不存在。
- 代价：大 tally 时内存占用高于 ASCII 路线。出现性能问题再引入 tallies.out 快路径。

## 5. 知识库检索：向量库+关键词混合 → 固定 8 份官方 RST 的文本检索

- 设计（5.3）：离线文档→切分→FAISS/Chroma/Milvus 向量库+关键词混合检索。
- 实际：openmc_knowledge 对随包 8 份固定版本官方 RST 做文本检索，带版本/行号/出处；未展开引用、不声称全手册解析（RF014 原话）。
- 为什么可辩护：范围诚实、出处可溯、零算力依赖；表 4-1 自己把"向量库算力"列为前置依赖。
- 代价与回头条件：**六条里唯一可能影响验收指标的**——5.3 验收"20 个参数解释问题回答正确且给出出处"，纯文本检索对同义改写不鲁棒。行动：先做 20 问自测拿基线；不达标或算力到位即上向量/混合检索。

## 6. 扫描采样：拉丁超立方 → 笛卡尔积（组合上限已实现）

- 设计（3.3）：参数空间定义支持笛卡尔积/列表/拉丁超立方；Slurm 侧 --array；组合爆炸设上限并把预估返回用户确认。
- 实际：itertools.product 笛卡尔积；顺序执行（RF008 留痕："顺序执行可满足原路线"）；**上限已实现**：max_scan_cases（默认 100，配置可调，超限拒绝并提示缩小范围）；"预估用时返回"未做。
- 为什么可辩护：验收判据（≥20 组自动跑完+汇总+失败清单）当前路线可达；上限保护住了爆炸风险。
- 代价与回头条件：高维空间采样效率低（LHS 需求在 P2）；预估用时需基线作业时长模型，列入 P2；HPC 到位后 --array 按 RF007/RF008 联调。

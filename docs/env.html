02 / 能力来源
conda 构建串就是一张能力清单

openmc-0.16.0-dagmc_nompi_py312h63f0379_103
             └┬──┘ └┬──┘ └┬─┘
              │     │     └── 绑定的 Python 版本（3.12）
              │     └──────── mpi / nompi：是否支持分布式并行
              └────────────── dagmc / nodagmc：是否支持 CAD 几何

三条判断，直接影响能不能做某类功能：

  • nompi 不影响 Slurm 单节点提交（可用 OpenMP 线程 + srun），只影响多节点与并行 I/O。
  • dagmc 构建包含 CAD 几何能力（openmc.DAGMCUniverse）。2026-11-04复核：本包已有STEP转换和DAGMC模型组装接口；cad_to_dagmc转换环境仍需单独准备，quickstart尚未自动安装。调用关系与验证边界见CAD输入流程。
  • 构建串只是声明。CAD 能力是否可用，必须用最小算例验证，见下节。

OpenMC 的功能是编译期开关组合出来的：OPENMC_USE_OPENMP 默认开、OPENMC_USE_MPI 默认关、OPENMC_USE_DAGMC 默认关、OPENMC_USE_LIBMESH 默认关。装了一个 OpenMC 不等于能力齐全。

03 / 核数据
核数据不在安装范围内

安装 OpenMC 不带核数据。核数据是独立下载的 HDF5 库，用 OPENMC_CROSS_SECTIONS 指向 cross_sections.xml 索引。未设置时的表现是：能启动、能读几何，然后在材料读取阶段失败。

因此探测要分三步记录：求解器可执行文件、Python API、核数据索引。本工具包由 config/openmc.local.json 声明库名并在运行期注入，不依赖登录 shell；openmc_environment 会分别报告这三项。

燃耗另需链文件（chain_casl_thermal.xml，约 981KB）：由部署配置 depletion_chain 指定，未配置时在核数据目录下按同名查找；核数据安装脚本不含链文件，换机或离线部署要一并带上，否则燃耗在链解析阶段失败。本机实测文件 SHA256 9c71578f366b40ca0aa566b56ac99c22fc1c37d183ad8641eba253d5a6f370f7。

04 / 踩过的坑
四个会浪费半天以上的问题

症状原因处理
CMake 找不到 HDF5只找 PATH 上的 h5cc / h5pcc设 HDF5_ROOT 指向安装根目录
编译通过，运行时段错误或符号缺失HDF5 与 OpenMC 不是同一编译器工具链全流程固定一个工具链
import openmc 正常，import openmc.lib 失败共享库必须在 openmc/lib/ 包目录内，源码用 importlib.resources 定位，不搜 LD_LIBRARY_PATH由包管理器放置，不手工搬运 .so
开 MPI 后并行 I/O 失败用了串行 HDF5链接并行 HDF5，并设 HDF5_PREFER_PARALLEL=on

另有一条：使用 openmc.lib（燃耗、CMFD）时，h5py / mpi4py 建议与 OpenMC 用同一编译器与 HDF5 版本重装，否则问题只在燃耗阶段暴露。

05 / 换机
先探测，再跑例题

openmc --version
python -c "import openmc; print(openmc.__version__)"
python -c "import openmc.lib; print('ok')"

三步都有结果，才算装好。CAD应分层检查：STEP转换 → H5M几何读入 → 补齐材料与计算设置 → 用同一输入实际求解并检查日志和结果。现有转换产物与官方现成H5M输运来自不同模型，不能合称同一STEP的端到端通过；运行条件和专业判据按实际模型确定，不把示例粒子数当新增验收指标。

Windows 不在官方支持范围。 OpenMC 安装文档中“在 Windows 上编译”一节只有一句：使用 WSL，再按 Linux 流程编译。甲方若提供 Windows 桌面机，只能在 WSL 或容器中运行，前置条件需写入部署说明。

06 / 可复现
两件改变结果、但与统计无关的事

  • 线程数。OMP_NUM_THREADS 不同，随机数分配路径不同，同一 seed 也会得到不同结果。任何“同输入同结果”的承诺都要连同线程数一起写。
  • 编译选项。RelWithDebInfo（-O2）与 Release（-O3）之间、以及是否开启 OPENMC_ENABLE_STRICT_FP，会产生比特级差异。跨环境比对要么统一编译选项，要么明确按统计判据比较，不比比特。

当前 runtime.json 已记录配置快照；建议补充线程数与 OpenMC commit hash，使复查不必推断。

07 / 选择
安装路径怎么定

路径结论说明
conda / micromamba采用唯一环境来源，由 config/openmc-linux-64.lock 锁定
源码编译不采用除非需要自定义开关组合，维护成本高
Spack仅 HPC 备用默认 MPI off、OpenMP on、RelWithDebInfo，与本地组合不同，混用会产生结果差异
Docker可选交付包装镜像应由同一 lock 文件构建，保证与本地环境一致

离线部署需准备本地 channel 或等价离线包，避免目标机无外网导致安装中断。切换 MPI 版本会连带更换 HDF5 与 h5py 的构建，不要为了 HPC 随手改锁文件。

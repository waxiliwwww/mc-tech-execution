# 故障排查

先定位发生在哪一层：环境准备→输入/参数→提交→计算终态→结果/图→报告→文件位置→MCP连接。保留第一条错误和编号，不以再次提交替代查询。

## 找不到.mc-jobs、.mc-scans或输出图片

它们是服务端工作区下的隐藏目录。运行./mc.sh call openmc_environment查看workspace；再用openmc_list_artifacts查询实际目录和server_path。默认在项目workspace，不在examples/或终端cwd。用ls -la查看；远端路径不会自动成为本机文件。[路径与维护说明](产物与清理.md)

## API可用但求解器不可用，或版本不匹配

两者分别检查。核对当前生效的MC_OPENMC_CONFIG/本机配置，确认python_command与openmc_command在服务端存在，实际版本是适配基线。Quick Start或configure_openmc.py可重新指定已有prefix；不要仅安装Python包就认为已有计算程序。

## 输入生成成功，却算不了

生成、XML/API解析和实际运行是不同阶段。核对核数据路径、模型文件、源/材料/计分配置及日志。公开多群例题自带数据，连续能模型仍需适配核数据库；正式物理规则需要业务判据。工具不会自动退到假结果。

## keff几乎不变、std_dev为null或图只有一个点

合成单群示例用于工程流程，macro是截面倍率；不能当真实质量密度敏感性实验。null表示统计量不可用，不表示0误差，原warnings必须保留。示例只有一个空间计分点时单次结果图可能只有一点；扫描图是多个组合的对应值。正式模型的统计设置、归一化和专业判断须另核对，不能靠图形外观判定准确率。

## 作业failed、cancelled或interrupted

用job_id/scan_id查询终态、错误和逐项状态；到服务端记录目录查看solver.log、worker.log。取消请求之后仍须查询。interrupted可能留有实际求解器，不声称自动恢复；先按记录核对实际进程并保留证据，勿盲目重提。

## PDF/DOC未生成，或转换超时

DOCX、Markdown、CSV无需Office转换；PDF/DOC需要。检查office_command、字体、运行权限、日志和依赖；缺组件明确报失败，不登记假的PDF。可先使用--skip-office及演示--formats markdown csv docx检验其他链路，补组件后再验证所需格式。

## 标准MCP连不上

核对服务实际监听、publicUrl、网络可达性与Bearer环境。客户端不能连接0.0.0.0，异机也不能把127.0.0.1当远端地址。先用examples/mcp_client.py完成initialize/list/call；/health可用只证明进程，不能证明认证、工具或OpenMC通过。

## 接口能调用但智能体选错工具/参数

先核对工具Schema、宿主版本、模型与授权策略，记录实际工具选择及参数。标准客户端成功与自然语言成功分别留证；不把特定宿主表现归为求解器故障。参考可选[宿主说明](MCP平台接入.md)。

## 清理被拒或部分失败

确认是维护窗口、目标终态、worker已退出；中断记录和损坏/缺失的关联需要人工核对。修复引用默认拒绝，接受丢失追溯能力须显式选择。部分删除失败返回非0并列剩余目录，不回滚、不自动重算。具体边界见[清理说明](产物与清理.md)。

## 请求协助时带什么

提供代码版本、实际入口、脱敏配置、生效workspace、编号、第一条错误、终态和相关产物清单。不要贴API Key、Bearer、完整私有核数据或未经允许的业务材料。重跑/手工改配置与系统自动恢复分开记录。

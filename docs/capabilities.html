MC工具包能力范围

本包是OpenMC的建模接入与计算管理层，已覆盖常用中子输运工作流。参数化生成器是一个明确受控的子集，尚不是完整OpenMC前端。原生模型能接入的范围通常比它能自动生成和修改的范围更广。

覆盖范围输入校验技术指引与PromptMC依据与验证边界
宿主把用户需求组织为受支持参数→包内Python API生成 / 原生文件接入→校核与作业管理→StatePoint与派生产物

例如：能接入官方三维全堆模型，并不表示自然语言可以任意设计堆芯。自然语言由DSH等宿主解析；本包只接受公开Schema内的结构化描述。未知材料、边界、单位和源条件需要用户补充，不能让模型猜。

1．怎样判断覆盖了多少

分别看“生成、接入、修改、解析、验证”。OpenMC的类、函数和组合没有统一的功能分母，当前不报总覆盖百分比。下面明确到类型的数量仅适用于该行，不相加。

能力本包可生成或提供可接入、可修改及限制
材料显式核素配比、密度与单位、温度；连续能量材料。元素展开、宏观多群材料不在通用spec生成字段内。原生材料输入可保留；改参支持密度/温度，保留原单位。核素配方不在通用改参列表内。
CSG几何7种面：X/Y/Z平面、X/Y/Z圆柱、球；布尔区域、Cell/Universe及填充引用。原生合法几何可接入；改参支持11种面公开系数，另含一般平面及3种圆锥。不是任意拓扑编辑。
重复结构二维RectLattice：节距、左下角、宇宙排布。原生三维RectLattice和HexLattice可保留；官方全堆模板通过上下分区内的二维矩形格架构成三维几何，自测模板可产生HexLattice。通用spec不能据此宣称支持三维RectLattice或HexLattice生成。
源与运行设置point/box中子源、各向同性方向，可选单能；eigenvalue/fixed source、采样设置、种子。改参开放particles/batches/inactive/generations_per_batch/seed及源相对强度；不提供任意空间/角度/能谱分布的通用编辑。
计分tallyspec支持能量、材料、规则网格3种过滤器，score/nuclide列表交OpenMC校核。追加计分接口另支持particle，共4种过滤器；已有原生计分可保留。支持某个score字符串不等于已验证所有score/过滤器组合。
CAD经独立cad_to_dagmc环境将STEP转H5M，按材料名称映射组装DAGMC模型。DAGMC版OpenMC实际加载H5M；密度/核素/单位和边界仍需用户明确。任意复杂装配体的修复、网格质量与业务物理正确性未作通用保证。
计算与扫描本地命名作业、快照、状态、取消；发现的参数可做笛卡尔串行扫描。服务器本地执行；没有Slurm提交、HPC账户认证、MPI调度、LHS或自动失败重试。
燃耗配置功率/时间步/链文件及mode=deplete；要求可燃耗材料与显式体积。可读逐步keff及部分核素质量，燃耗量是功率×时间/初始重金属质量估算。通用spec/改参不覆盖整套燃耗API。
结果与图表管理作业的StatePoint：keff、tally均值/标准差/维度；曲线、能谱、规则网格切片、k收敛图。完整所选CSV/JSON与报告同源；热图独立交付。summary.h5/source.h5/tracks不提供通用解析器，任意外部StatePoint不直接当受管作业读取。
报告与知识Markdown/CSV/DOCX/PDF/DOC；固定官方资料关键词检索、原文行号。PDF/DOC需Office转换；不自动进行物理评价。检索返回原文，宿主模型另组织回答；不是向量知识库或微调模型。

适合的任务：已有模型接入与校核，受支持几何组合，公开组件/简化全堆计算，有限改参/扫描，以及可追溯结果整理。要做新的专业设计，先对照字段与输入格式；超出范围可接入原生模型或扩展适配器，不能只换一段提示词就获得缺失功能。

完整OpenMC还包括更丰富的源、过滤器、网格/几何、权窗、CMFD、MGXS、重启及多物理等功能；本包没有逐项开放全部创建/编辑接口。本机编译选项、核数据和外部文件会进一步限制可运行范围。

2．入参校验已经有，分四层看

层次现在做什么如何使用及边界
接口SchemaMCP/CLI共用工具定义，校验类型、必填、范围及部分组合；参数含说明。合法JSON不表示模型物理有效。参数化spec另查编号引用、区域、循环填充和单位等约束。
XML结构缺文件、根元素、解析、DTD/实体拒绝、少量运行参数及文件大小。默认validate_inputs和提交入口的基础检查；structure_valid只回答这一层。
API与静态语义公开API读回模型；密度/温度有限且为正、核素/S(a,b)索引可用性、计分过滤器与引用规则。调用api_check=true、semantic_check=true；核对openmc_api.api_parsed及semantic.checked/ok/complete。索引存在不保证其HDF5文件完整或温度范围适用。
几何与专业检查geometry_check=true在临时副本低批次运行openmc -g；报告重叠/未完成及抽样限制。会消耗计算资源，按需单独执行。通过不证明无重叠；专业判据、收敛、核数据适用性仍需专家。
重要使用规则：提交工具目前不会强制执行API/语义/几何全部检查。宿主或调用脚本必须安排校核并读取各层结果；不要只看structure_valid=true就提交。新复现脚本对API和静态语义设置停止条件，未改变所有调用方的默认提交行为。

此次补齐：单文件model.xml内计分过滤器的层级识别；inf密度/温度拒绝；语义核素检查优先采用模型声明的cross_sections；particle过滤器Schema接受合法粒子名称。产物清单也补列网格与收敛图及数据。相关定向用例用于代码回归，不能替代真实模型试用。

4．依据与验证边界

覆盖矩阵按当前源码核对。历史已有例题记录与本次改动检查分别保存；本轮按用户安排不执行OpenMC、DSH模型或目标服务器部署。复现手册是待执行步骤，尚无本轮两个模型运行成功结论。

源码、公开依据与范围核查方法
  • 生成字段：openmc_model_spec.py；修改白名单：openmc_parameters.py；模板与读取：openmc_worker.py。
  • 校验：MCP Schema、validate_inputs；结果/格式：openmc_visuals.py、产物清单。
  • OpenMC 0.16官方API目录用于核对功能面；官方模型工厂源码用于核对组件和全堆来源。
  • PromptMC固定审阅提交（MIT）：schema.py、provenance.py、commands/run.py和openmc_integration.py。参考原则，未将其代码或服务打包为本包依赖。

核查顺序为：对照OpenMC公开模块 → 区分各输入路线 → 看Schema和实际worker分支 → 核对可发现改参字段及结果选择 → 单列实际执行证据。工具数量与API类数量均不作为合同完成率。

当前实现说明；运行、模型联调与专业验收分别记录。合同进展另见执行对照。

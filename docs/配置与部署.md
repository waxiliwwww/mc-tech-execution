# 配置与部署

## 1. 收到包后准备什么

服务端当前支持Linux/WSL，建议Debian/Ubuntu。准备Bash、Python3.10+及venv、curl、tar/bzip2；自动准备Office需apt-get和dpkg-deb。首次需要访问软件源并预留安装空间。其他机器可以作为标准MCP客户端，无需在那里安装OpenMC。

先解压收到的版本包，进入解压后的mc-tech-execution根目录。包里有源码、依赖清单、配置、示例、文档与测试；已安装的运行时、密钥、本机配置、用户数据和计算产物不随包分发。源码包不是完全离线的系统镜像。

```bash
./quickstart.sh
./mc.sh call openmc_environment
mcp/.venv/bin/python examples/public_case_demo.py
```

Quick Start准备两个环境：mcp/.venv运行接口层；.runtime/openmc运行OpenMC0.16.0及图表/报告Python依赖。没有系统LibreOffice时，转换组件和字体提取到项目.runtime/office，不修改系统安装或shell配置。

环境检查分别报告API、求解器、版本、核数据配置和服务端workspace。三个程序命令成功不等于正式物理验收。公开多群例题自带C5G7数据；正式连续能模型仍需匹配的核数据库。

已有OpenMC可复用：

```bash
./quickstart.sh --openmc-prefix /opt/openmc-env
```

把示例prefix换成真实环境。初配工具写入的本机配置包含该环境实际路径。迁移后重新配置，不复制旧的个人绝对路径。只需Markdown/CSV/DOCX时可用`--skip-office`；PDF/DOC需要后续配置转换组件。

## 2. 三组配置分别负责什么

| 对象 | 入口与优先级 | 何时使用 |
| --- | --- | --- |
| 工作区 | CLI的--workspace > MC_WORKSPACE > 工具包根目录/workspace | 保存算例、记录、计划和产物；服务进程启动后固定 |
| OpenMC运行配置 | CLI的--config > MC_OPENMC_CONFIG > config/openmc.local.json > config/openmc.json | 工具执行/创建记录时读取；作业保存当次配置快照 |
| MCP监听/鉴权 | MCP_CONFIG_FILE指向服务JSON；MCP_HOST/PORT/PATH/PUBLIC_URL等覆盖其中相应值；MCP_AUTH_TOKEN来自环境 | 服务启动时读取；改变后需重启服务 |

工作区和运行配置是不同设置。改端口不会移动数据；重新配置运行时也不会自动迁移已有作业。MC_WORKSPACE建议使用绝对路径，避免服务从mcp/启动与客户端从其他目录执行时，相对环境变量指向不同位置。CLI的--workspace/--config相对路径按调用时工作目录解析；MC_OPENMC_CONFIG相对路径按工具包根目录解析。

例如在已有、具备写权限的服务目录准备独立数据区，然后在每次启动前设置：

```bash
export MC_WORKSPACE=/srv/mc-data
export MC_OPENMC_CONFIG=/srv/mc-tech-execution/config/openmc.local.json
./mc.sh call openmc_environment
```

示例路径需按实际部署替换；不需要更改用户shell配置。CLI与MCP要共享同一批记录时，使用同一个绝对MC_WORKSPACE。生产服务的环境变量应由部署方式固定传入。

## 3. OpenMC配置字段

config/openmc.json是可提交的默认配置；Quick Start生成config/openmc.local.json。不要把密钥或个人本机配置提交到Git或部署包。

| 字段 | 用途 |
| --- | --- |
| runtime / expected_version | 当前native适配和固定OpenMC版本；升级需重验相关接口 |
| python_command / openmc_command | 管理员控制的非空argv数组；前者运行官方API工作进程，后者执行求解器 |
| data_kind | 区分未审定用户数据与测试模拟进程；示例另保留自己的来源标记 |
| api_timeout_seconds / job_timeout_seconds | API和计算执行时限；取消请求之后仍须查询终态 |
| max_log_bytes | 求解器日志保留上限，截断会明确标记 |
| max_scan_cases | 扫描组合上限；在提交前校核 |
| max_plot_points / max_report_rows | 图点和报告行数限制；不能用截断预览冒充完整图数据 |
| office_command / report_timeout_seconds / font_path | DOC/PDF转换命令、时限与中文字体位置 |

命令使用argv数组，不拼接任意shell文本。Office相对命令路径由包根目录定位；通用命令名通过服务进程PATH查找。正式核数据库按OpenMC方式配置，例如服务进程的OPENMC_CROSS_SECTIONS或输入模型中的相应引用。数据文件路径必须能在执行计算的服务器上访问。

## 4. 启动标准MCP服务

```bash
./mcp/start.sh
```

默认只监听127.0.0.1:8770/mcp。服务与计算worker的生命周期不同：停MCP不会自动停止独立计算；已提交记录可在相同工作区重新查询。

远程部署在mcp/service.config.json中设置实际监听地址、端口、路径和publicUrl，也可用环境变量覆盖：

```bash
export MC_WORKSPACE=/srv/mc-data
export MCP_HOST=0.0.0.0
export MCP_PORT=8770
export MCP_PUBLIC_URL=https://mc.example.org/mcp
export MCP_AUTH_TOKEN='替换为部署方生成的令牌'
./mcp/start.sh
```

这是配置示例，地址和令牌需要替换。非回环监听必须有公开访问URL和Bearer；使用部署方已有的HTTPS入口。0.0.0.0是监听通配地址，不能交给客户端连接。客户端与服务端各自在进程环境提供相应令牌，不把真实令牌写入源码或文档。日志/connection.json保留的是连接信息与令牌变量占位符。

/health用于进程探活，不证明OpenMC或业务可用；/info是服务扩展信息入口，启用鉴权后与MCP同样需要Bearer。标准MCP接入使用协议发现/调用，不依赖/info，见[MCP服务与接口](MCP服务与接口.md)。

## 5. 交给另一台机器

打包后同时交付压缩包、MANIFEST.json和SHA256SUMS。接收方核对文件，解压到自己的目录，执行Quick Start或配置已有运行时，再检查workspace并运行公开例题。核数据库、业务输入和认证信息按实际部署分别准备。

先验证CLI/标准MCP和产物可查，再接具体智能体。代码可迁移不表示任意系统、私有集群或全部宿主已经实测通过。

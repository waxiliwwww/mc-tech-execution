# 实现结构与扩展入口

本文帮助接手者修改工具；运行步骤见[使用指南](使用指南.md)，参数表见[工具接口参考](工具接口参考.md)。

## 一次请求怎样走完

```text
直接CLI mc.sh → mcp/cli.py ┐
                         ├→ tools.py注册表 → adapters.py校验/调度 → 业务函数
标准MCP → mcp/server.py ──┘                                      │
                       OpenMC runtime/API/本地worker ←───────────┘
                                  │
                       服务端workspace的记录、日志与产物
```

两条入口调用同一业务实现。examples只是调用这些接口的参考流程与终端摘要，不承担求解器逻辑。Harness是可选宿主，不被工具服务反向依赖。

长计算异步执行：提交时校核与复制输入快照，生成持久编号；独立worker启动OpenMC并记录状态。服务退出后可用同一工作区继续查询。失去监控时标interrupted，不擅自把它算成成功或自动重提。

| 文件 | 主要职责与修改场景 |
| --- | --- |
| mcp/tools.py | 工具名称、说明、输入输出Schema、函数绑定；新增接口先登记这里 |
| mcp/adapters.py | 公共校验及函数/程序/HTTP适配；直接CLI与MCP共用 |
| mcp/cli.py、server.py | 终端JSON入口、标准协议/鉴权/服务信息；CLI的apply_repair另执行TTY确认 |
| mcp/openmc_runtime.py、openmc_worker.py | 配置/工作区边界；在配置的OpenMC Python环境执行官方API动作 |
| mcp/openmc_tools.py | 环境、输入生成/校核、提交、StatePoint读取和基础导出 |
| mcp/openmc_jobs.py、openmc_scan.py | 输入快照、独立作业、取消、串行扫描及持久记录 |
| mcp/openmc_parameters.py | 参数发现、允许修改项和组合校核；不是任意XML字段编辑器 |
| mcp/openmc_plots.py、openmc_visuals.py | 选择完整计分数据、图与JSON/CSV数据的一致性 |
| mcp/openmc_reports.py | 文档模型、五格式导出、受控Office转换 |
| mcp/openmc_artifacts.py | 服务端产物目录、路径、大小、哈希清单 |
| mcp/openmc_knowledge.py、openmc_examples.py | 固定官方资料/导航/出处与例题准备状态 |
| mcp/openmc_diagnostics.py、business.py | 有限规则诊断、差异计划、确认后修改、校核/关联重算 |
| examples/demo_output.py | 人读摘要与--json；不改变业务结果和统计值 |
| scripts/cleanup_artifacts.py | 维护窗口预览/清理内部记录；不删除原输入或通过MCP开放删除 |

## 加一个普通函数工具

先在独立模块实现输入输出明确的函数，例如：

```python
# mcp/custom_tools.py
def add_numbers(a: int, b: int) -> dict:
    return {"sum": a + b}
```

然后在tools.py导入该函数，并按现有格式加入TOOLS：

```python
from custom_tools import add_numbers

TOOLS.append({
    "name": "add_numbers",
    "description": "返回两个整数之和。",
    "inputSchema": schema({"a": {"type": "integer"}, "b": {"type": "integer"}}, ["a", "b"]),
    "outputSchema": {"type": "object"},
    "function": add_numbers,
})
```

这是扩展示例，默认包未注册该工具。复用统一校验，不为CLI和MCP各写一套分支。参数与返回值应可JSON序列化；未知或不合法输入返回明确错误。

外部程序使用固定argv、工作目录、超时与输出Schema，不能把用户文字直接拼进shell。通用程序适配器适合有界的JSON任务；长计算复用提交/状态/取消模式，不占同步工具无限等待。具体适配键与边界参考adapters.py已有实现，勿靠猜测另造协议。

## 扩展OpenMC能力

1. 输入模板在openmc_worker.py的生成动作和相应参数模块衔接。保留单位、材料类型和未修改字段，模型重新导出可能改变不相关内容，需要对照。
2. 允许扫描的新参数要明确名称、类型、范围、单位、适用模型，并在提交前检查所有组合；原输入保持，组合使用独立副本。
3. 新结果/图表用官方StatePoint/Tally选择接口，明确score、nuclide、filter和归一化。原始均值/标准差、截断提示与数据来源保留，不用截断预览画完整图。
4. 新例题在config/cases.json登记来源、依赖与准备入口。ready_to_prepare不等于已计算；指定基准没有材料时保持缺料状态。
5. 资料扩展保留许可、版本、原文和哈希，更新manifest与中文导航；未展开引用不冒充完整手册。修改规则、专业参数和自动修复范围需有业务依据。

## 改完怎样验证并交付

先用相关tests验证正常、失败和必要边界；新增关键检查用实际反例确认能失败。涉及求解器/图/格式时启用真实OpenMC套件，不能用模拟进程代替物理结果。修复确认必须保留拒绝、预览后变化、确认后重验和原失败。

运行mcp/.venv/bin/python scripts/generate_tool_reference.py同步接口文档，用./mc.sh list或标准tools/list核对名称与参数。最后按[测试说明](测试与验收说明.md)做受影响组合检查，./package.sh生成源码包，检查MANIFEST/SHA与解压后的入口。

本轮不新增CAD/HPC/微调算法；工程实现与原合同功能的状态沿[开发计划](验收导向开发计划.md)。模型由宿主接入的现有路径，不自动替代工具内部统一LLM层及微调等原要求。

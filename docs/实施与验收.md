# 实施与验收边界

当前工作是独立蒙卡接口工具包的开发、MCP封装、调用说明和工程验证，覆盖表4-1全15项的实现计划。专业计算复用OpenMC等已有程序；公开接口和示例可直接作为工程开发依据，不要求技术执行者先承担专业模型设计。

本文件更新于2026-10-27，替代此前“四项助手主责”的旧工程描述，不修改原合同义务。工具/API/测法/甲方协作项统一见[开发计划](验收导向开发计划.md)，操作见[工具手册](OpenMC工具使用说明.md)。

## 各方配合

开发方负责清晰可执行的接口、参数/结果组织、错误回执、样例、部署说明、自测与经确认的测试计划执行。甲方按规格提供详细计算需求和使用场景、必要测试算例和基准模型、计算环境及验证条件，参与评审验收。

专业模型、参数边界、核数据选择、参考答案和专业判据需要相关专业人员提供或审定。微调成果和未明确归属的专业脚本需落实提供者，不能自动全部转给甲方，也不由个人无条件兜底。

## 证据层次

1. 模拟进程验证进程/异常控制；明确标mock_process_fixture。
2. 真实OpenMC加合成MGXS验证实际输入、运行和产物解析；明确标synthetic_mgxs。
3. 指定真实数据与基准验证业务处理及专业结果；需要固定版本、相同计算设置和参考判据。
4. 正式合同验收需覆盖全部原功能、指标、兼容性、稳定性和交付要求；按甲方确认的计划执行。

原调用成功率≥95%、结果准确率≥95%、规定17×17=289场景物理准确率≥90%分别验证。两个宿主、多模型及本地模型、自动主备、72小时、原100%功能/性能达标/文档完整性要求保留，不因当前工程示例而降低。
